# 操作系统 强化-I/O 管理

> **大题位置**：选择题为主（30-32 题），大题偶尔涉及
> **数据口径**：2016-2025 近 10 年统计

> **本板块串联**：I/O 管理是进程与硬件的桥梁——进程管理板块的"阻塞"状态多因等待 I/O 而来，文件系统板块的数据最终经此落盘，与计组的总线与 I/O 板块（硬件实现视角）互为表里。

## 🧭 知识主线

I/O 管理的主线是**"CPU 的解放程度递进"**：程序查询（CPU 全程盯着设备，纯串行）→ 程序中断（设备就绪才打断 CPU，一次传一个字）→ DMA（CPU 只管开头下命令和结尾收通知，整块数据自己搬）。三种方式的对比本质是"CPU 干预粒度"的对比，SPOOLing 用磁盘把独占设备虚拟成共享设备是这条主线的巅峰应用。缓冲区（单/双/循环）则是在内存里为速度失配做的"蓄水池"。

## 二、I/O 控制方式

### 2.1 程序查询

- CPU 不断轮询设备状态
- CPU 与设备串行工作，效率最低
- 适用于简单低速设备

### 2.2 程序中断

```
I/O请求 → CPU启动设备 → CPU做其他工作
→ 设备就绪 → 发中断请求 → CPU响应中断
→ 中断处理 → 数据传输 → 返回
```

- CPU 与设备并行工作
- 每次传输一个字/一个字节
- 中断处理需要保护/恢复现场

**中断处理流程：**
1. 中断隐指令：关中断 → 保存 PC → 取中断程序入口地址
2. 中断服务程序：保护现场 → 处理中断 → 恢复现场 → 开中断 → 中断返回

### 2.3 DMA

```
I/O请求 → CPU向DMA控制器发命令 → CPU做其他工作
→ DMA控制设备与内存直接传输（不需要CPU干预）
→ 传输完成 → DMA发中断 → CPU处理
```

- CPU 与设备高度并行
- 每次传输一个数据块
- DMA 与 CPU 共享内存总线（周期窃取）

### 2.4 对比

| 方式 | CPU 干预 | 传输单位 | 数据路径 |
|------|---------|---------|---------|
| 程序查询 | 每次都 | 1 字 | 设备→CPU→内存 |
| 程序中断 | 中断时 | 1 字 | 设备→CPU→内存 |
| DMA | 传输完成后 | 数据块 | 设备→内存（直接） |

## 三、SPOOLing（假脱机）

### 3.1 原理

- 用软件模拟脱机技术
- 利用高速磁盘模拟独占设备→共享设备
- 输入井 + 输出井 + 输入缓冲区 + 输出缓冲区

### 3.2 应用

- 打印机共享：多进程同时"打印"→先写入输出井→排队输出
- 网卡收发

## 四、设备分配

### 4.1 设备类型

| 类型 | 特点 | 分配方式 |
|------|------|---------|
| 独占设备 | 一次只给一个进程 | 静态分配 |
| 共享设备 | 多进程同时使用 | 动态分配 |
| 虚拟设备 | SPOOLing 模拟 | 假脱机 |

### 4.2 设备分配算法

- 先请求先服务
- 优先级高者优先

## 五、缓冲区

| 类型 | 说明 |
|------|------|
| 单缓冲 | 一个缓冲区，CPU与设备交替 |
| 双缓冲 | 两个缓冲区，一边收一边处理 |
| 循环缓冲 | 多个缓冲区环形使用 |
| 缓冲池 | 多缓冲区共享管理 |

**处理时间计算（单缓冲）：**
- 若 T(设备) > C(CPU处理)：总时间 ≈ n × T
- 若 C > T：总时间 ≈ n × C
- 最后一块还需加上 C

## 六、易错点清单

- [ ] DMA 不需要 CPU 干预数据传输（但需要 CPU 启动和善后）
- [ ] 中断响应优先级 vs 中断处理优先级（响应优先级固定，处理优先级可屏蔽）
- [ ] DMA 与 CPU 争用总线（周期窃取）
- [ ] SPOOLing 将独占设备变共享设备
- [ ] 单缓冲 vs 双缓冲的处理时间公式不同
- [ ] 中断隐指令由硬件完成，中断服务程序由软件完成

## 🧠 思考模式

**遇到 I/O 题，第一反应应该是：**

1. **定方式**：先判断题目场景是查询 / 中断 / DMA——看"谁搬数据"：查询和中断是 CPU 搬，DMA 是控制器搬
2. **比并行度**：中断比查询强在"设备准备数据时 CPU 不等"，DMA 比中断强在"传输过程也不打断 CPU"——选择题常考这个差别的量化（CPU 干预频率、传输单位）
3. **辨两级优先级**：中断响应优先级（硬件排队，不可变）vs 处理优先级（屏蔽字调整，可变）——出现"高优先级被推迟处理"就是考处理优先级

**知识串联提示：**
- 中断的"进程被唤醒" ↔ 进程管理板块的阻塞→就绪：I/O 完成中断的服务程序里就有 V 操作
- SPOOLing 的"输出井" ↔ 文件系统板块的磁盘管理：假脱机技术本质是把并发打印请求变成磁盘文件排队
- 容易混淆对比：DMA 与 CPU 争用内存总线是"周期窃取"，不经过 CPU 也不占用 CPU 时间；中断处理需要保护/恢复现场，DMA 只在首尾需要 CPU
