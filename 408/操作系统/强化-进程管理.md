# 操作系统 强化-进程管理

> **大题位置**：45 题，10 分（OS 大题核心）
> **核心能力**：PV 信号量设计 + 进程同步模型分析
> **数据口径**：2016-2025 近 10 年大题统计

> **本板块串联**：进程管理是 OS 的心脏——从概述板块的"并发"特征落地为进程实体，向下衔接内存管理（进程的地址空间），向上衔接 I/O 管理（进程等待设备即阻塞）。

## 🧭 知识主线

进程管理的主线是**"一个程序如何变成被调度的实体"**：程序加载→创建 PCB（进程实体）→进入就绪队列→被调度运行→运行中申请资源（可能阻塞/同步）→完成退出。其中"申请资源时的等待与唤醒"正是 PV 操作的位置——信号量是资源的抽象，P 是"等资源"，V 是"还资源"。所有同步模型（生产者-消费者、读者-写者、哲学家）都是"多个角色 + 有限资源 + 制约关系"的排列组合，五大经典模型是全部变体的原型。

## 二、进程基础

### 2.1 进程的三种基本状态

```
     就绪 ────调度────→ 运行
      ↑                  │
      │ ←──时间片到───┘
      │                  │
      └────等待事件────────┘
              ↕
             阻塞 ←──等待资源─── 运行
              ↓
            时间片到（部分系统）
```

- **就绪→运行**：调度程序选择
- **运行→就绪**：时间片到/被抢占
- **运行→阻塞**：等待资源（I/O、信号量）
- **阻塞→就绪**：资源可用/事件完成

### 2.2 进程调度算法

| 算法 | 规则 | 特点 |
|------|------|------|
| FCFS | 先来先服务 | 非抢占，公平但对短作业不友好 |
| SJF | 短作业优先 | 平均等待时间最短，可能饥饿 |
| RR | 时间片轮转 | 公平，响应快，但开销大 |
| 优先级 | 按优先级调度 | 静态/动态优先级，可能饥饿 |
| 多级反馈队列 | 多队列+不同时间片 | 综合性能最优 |

## 三、PV 操作解题四步法

**所有 PV 题的通用框架，背熟即可应对 90% 的变体。**

```
// 第一步：确定临界资源和制约关系
// - 哪些是共享资源？（缓冲区、数据、座位）
// - 谁制约谁？（谁等谁，什么条件下等）

// 第二步：定义信号量
semaphore mutex = 1;    // 互斥访问临界区
semaphore empty = n;    // 空位数量（消费者等待）
semaphore full = 0;     // 产品数量（生产者等待）

// 第三步：写进程代码框架
void Producer() {
    while (1) {
        生产一个产品;
        P(empty);       // 申请空位（必须在P(mutex)前！）
        P(mutex);       // 互斥
        放入产品;
        V(mutex);
        V(full);        // 通知消费者有产品
    }
}

void Consumer() {
    while (1) {
        P(full);        // 申请产品
        P(mutex);       // 互斥
        取出产品;
        V(mutex);
        V(empty);       // 通知生产者有空位
    }
}

// 第四步：检查死锁
// - P 操作顺序是否可能导致死锁？（P(empty) 和 P(mutex) 不能反）
// - 是否有信号量遗漏 V 操作？
```

## 四、五大经典模型

### 模型一：单生产者-单消费者（1P1C）

```
semaphore mutex = 1, empty = n, full = 0;
// P(empty) 必须在 P(mutex) 之前，否则可能死锁
```

### 模型二：多生产者-多消费者（mP-kC）

```
// 例：爸爸放苹果，妈妈放橘子，儿子吃苹果，女儿吃橘子
semaphore plate = 1;     // 盘子容量
semaphore apple = 0;     // 苹果数量
semaphore orange = 0;    // 橘子数量
// 爸爸: P(plate) → 放苹果 → V(apple)
// 妈妈: P(plate) → 放橘子 → V(orange)
// 儿子: P(apple) → 取苹果 → V(plate)
// 女儿: P(orange) → 取橘子 → V(plate)
```

### 模型三：读者-写者（读者优先）

```
int readcount = 0;
semaphore mutex = 1;     // readcount 互斥
semaphore rw = 1;        // 读写互斥

void Reader() {
    P(mutex);
    if (++readcount == 1) P(rw);  // 第一个读者锁写
    V(mutex);
    读操作;
    P(mutex);
    if (--readcount == 0) V(rw);  // 最后一个读者解锁
    V(mutex);
}

void Writer() {
    P(rw);
    写操作;
    V(rw);
}
```

### 模型四：写者优先

```
int readcount = 0, writecount = 0;
semaphore rmutex = 1, wmutex = 1;
semaphore rw = 1;
semaphore w = 1;                   // 写优先

void Writer() {
    P(wmutex);
    if (++writecount == 1) P(r);   // 第一个写者阻止新读者
    V(wmutex);
    P(rw);
    写操作;
    V(rw);
    P(wmutex);
    if (--writecount == 0) V(r);
    V(wmutex);
}
```

### 模型五：哲学家进餐

```
// 方案：限制最多 4 人同时拿筷子（避免死锁）
semaphore chopstick[5] = {1,1,1,1,1};
semaphore room = 4;

void Philosopher(int i) {
    P(room);
    P(chopstick[i]);
    P(chopstick[(i+1)%5]);
    吃饭;
    V(chopstick[i]);
    V(chopstick[(i+1)%5]);
    V(room);
}
```

## 五、死锁

### 5.1 死锁四条件

1. 互斥
2. 占有并等待
3. 不可剥夺
4. 循环等待

### 5.2 银行家算法

**安全序列判断步骤：**
1. 计算 Need = Max - Allocation
2. 找 Need ≤ Available 的进程
3. 假设分配，更新 Available += Allocation
4. 标记完成，重复直到所有进程完成

| 年份 | 变体特点 | 应对策略 |
|------|---------|---------|
| 2025 三人植树 | 三个不同角色，流水线协作 | 分析谁等谁，画依赖关系图 |

1. 先确定有几个"角色"（进程）
2. 每个角色需要什么资源？
3. 资源之间的制约关系是什么？
4. 套用经典模型，调整信号量

## 🧠 思考模式

**遇到 PV 大题，第一反应应该是：**

1. **数角色**：题目里有几类进程？各自循环做什么？（三人植树 = 3 个角色）
2. **找资源**：什么是共享资源/制约条件？空位、产品、盘子、筷子——每个资源对应一个或一对信号量
3. **判制约**：谁等谁？画"角色 → 等待的资源"映射表；互斥资源加 mutex（=1），同步资源用计数信号量
4. **套模型**：对照五大原型（生产者-消费者 / 读写者 / 哲学家），90% 的题是原型的角色或资源变体
5. **验死锁**：P(mutex) 是否可能夹在其他 P 之间？每个 P 是否有配对的 V？

**知识串联提示：**
- 进程的阻塞与唤醒 → I/O 管理板块的中断处理：等待设备的进程由中断服务程序唤醒
- 死锁的"资源占有"视角 → 银行家算法本质是"预演 PV 分配序列的安全性"
- 容易混淆对比：互斥信号量（初值 1，保护临界区）vs 同步信号量（初值=资源数，表达制约）；P 操作顺序错 = 死锁，V 操作顺序错 = 只影响效率不死锁
