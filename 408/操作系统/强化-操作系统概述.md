# 操作系统 强化-操作系统概述

> **大题位置**：选择题为主（23 题附近，2-4 分）
> **数据口径**：2016-2025 近 10 年统计

> **本板块串联**：概述是全部 OS 章节的"地图"——并发特征展开成进程管理，共享/虚拟展开成内存管理，异步靠 I/O 管理兜底；用户态/内核态这条线贯穿后面所有章节的系统调用。

## 🧭 知识主线

概述的主线是**"操作系统在用户和硬件之间扮演什么角色"**：向上提供接口（系统调用，唯一合法入口）→ 向下管理资源（处理机/存储器/设备/文件四大管理）→ 用四个特征（并发/共享/虚拟/异步）描述工作方式。系统调用的"用户态→内核态"切换是这条主线的枢纽——进程切换、缺页、I/O 全都要经过它。选择题最爱考的就是"哪些操作会陷入内核"，答案永远是"凡是需要特权指令或共享资源的操作"。

## 二、操作系统概念

### 2.1 功能

1. **处理机管理**：进程创建/撤销/调度/同步/通信
2. **存储器管理**：分配/回收/保护/扩充
3. **设备管理**：分配/驱动/缓冲
4. **文件管理**：存储/检索/共享/保护

### 2.2 特征

1. **并发**（最基本）：宏观同时运行，微观交替执行
2. **共享**：互斥共享 + 同时访问
3. **虚拟**：物理→逻辑映射（虚拟处理机/虚拟存储器）
4. **异步**：进程走走停停

**并发 vs 并行：**
- 并行：多处理器同时执行（物理同时）
- 并发：单处理器交替执行（逻辑同时）

## 三、用户态与内核态

### 3.1 区分

| 状态 | 权限 |
|------|------|
| 用户态 | 不能访问特权指令、不能直接访问硬件 |
| 内核态 | 可执行所有指令、访问所有硬件 |

### 3.2 状态切换

- 用户态→内核态：系统调用、中断、异常
- 内核态→用户态：执行特权指令后返回

### 3.3 系统调用

| 类型 | 社例 |
|------|------|
| 设备管理 | 请求/释放设备 |
| 文件管理 | 打开/关闭/读/写 |
| 进程管理 | 创建/终止/等待 |
| 存储管理 | 分配/回收内存 |
| 通信 | 发送/接收消息 |

## 四、操作系统发展

| 阶段 | 特点 |
|------|------|
| 手工操作 | 无人机交互，效率极低 |
| 批处理 | 单道→多道，提高吞吐量 |
| 分时 | 时间片轮转，交互性好 |
| 实时 | 及时响应，可靠性高 |
| 网络/分布式 | 资源共享 |

## 五、中断与异常

| 类型 | 来源 | 示例 |
|------|------|------|
| 外中断 | 外部设备 | 时钟中断、I/O 中断 |
| 内中断（异常） | CPU 内部 | 除零、缺页、地址越界 |
  - 故障：缺页中断（可恢复）
  - 陷阱：系统调用（有意为之）
  - 终止：不可恢复（如硬件故障）

---

## 六、易错点清单

- [ ] 并发是单处理器的特征，并行需要多处理器
- [ ] 系统调用是用户态→内核态的方式之一
- [ ] 缺页中断是内中断（异常），不是外中断
- [ ] 中断隐指令由硬件完成
- [ ] 系统调用一定在内核态执行

## 🧠 思考模式

**遇到概述题，第一反应应该是：**

1. **判状态切换**：题目给一个操作（读文件/算术运算/printf），先问"要不要动硬件或共享资源"——要就必然经过系统调用进入内核态
2. **辨并发并行**：单核多道 = 并发（交替），多核同时 = 并行（真同时）——看到"单处理器"直接排除并行
3. **辨中断类型**：缺页/除零/越界 = 内中断（异常），时钟/I/O 完成 = 外中断——按"来源在 CPU 内还是外"一刀切

**知识串联提示：**
- 系统调用的陷入机制 ↔ 进程管理（创建进程 fork）、内存管理（mmap）、文件管理（open）——后面每个板块的具体系统调用都从这里出发
- "虚拟"特征 ↔ 内存管理的虚存 + SPOOLing 的虚拟设备：都是"用逻辑抽象扩充物理资源"
- 容易混淆对比：并发（宏观同时微观交替）vs 并行（物理同时）；用户态不能执行特权指令，但可通过系统调用"请内核代劳"
