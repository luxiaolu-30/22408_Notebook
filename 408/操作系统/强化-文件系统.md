# 操作系统 强化-文件系统

> **大题位置**：46 题（与内存管理轮换），5/10 年考
> **核心能力**：多级索引文件大小计算 + FAT 链式存储分析
> **数据口径**：2016-2025 近 10 年大题统计

> **本板块串联**：文件系统是"持久化"的学科——内存管理板块的数据断电即失，这里的数组落到磁盘块上；磁盘调度又与 I/O 管理板块的设备驱动衔接。

## 🧭 知识主线

文件系统的主线是**"一个文件如何映射到磁盘块"**：用户按名存取→目录项找到 inode→inode 里的地址指针（直接/一级/二级/三级索引）指向磁盘块→空闲块由位示图/成组链接管理。所有题型都是这条映射链上的计算：索引题算"指针能指多远"（最大文件大小），FAT 题算"链表怎么走"（显式链接 vs 隐式链接），磁盘调度题算"磁头怎么走最省"。inode 不存文件名、文件名在目录项——这是理解整条链的钥匙。

## 三、文件物理结构（核心考点）

### 3.1 连续分配

- 文件占用连续磁盘块
- 优点：支持随机访问，顺序访问快
- 缺点：外部碎片，文件不能动态增长

### 3.2 链接分配

**隐式链接：**
- 每个盘块存放下一盘块指针
- 优点：无外部碎片，文件可动态增长
- 缺点：只能顺序访问，指针开销

**显式链接（FAT）：**
- 文件分配表 FAT 存放所有盘块的链接指针
- FAT 在内存中，访问速度快
- 优点：支持随机访问（沿FAT链查找）

### 3.3 索引分配（重点！）

**多级索引计算公式：**

给定条件：盘块大小 D，地址占 A 位 → 每个索引块有 D/A 个指针

| 索引级别 | 指针数 | 最大文件大小 |
|---------|--------|------------|
| 直接索引 k 个 | k | k × D |
| 一级索引 1 个 | D/A | (D/A) × D |
| 二级索引 1 个 | (D/A)² | (D/A)² × D |
| 三级索引 1 个 | (D/A)³ | (D/A)³ × D |

**计算示例：**
- 盘块 4KB，地址 4B → 每个索引块 1024 个指针
- 10 个直接 → 10 × 4KB = 40KB
- 1 个一级 → 1024 × 4KB = 4MB
- 1 个二级 → 1024² × 4KB = 4GB
- 1 个三级 → 1024³ × 4KB = 4TB
- 最大文件 = 40KB + 4MB + 4GB + 4TB

## 四、目录结构

| 结构 | 特点 |
|------|------|
| 单级目录 | 所有文件同一目录，不能重名 |
| 两级目录 | 主文件目录 + 用户文件目录 |
| 树形目录 | 多级层次，路径唯一 |
| 无环图目录 | 共享文件/目录，可能有环 |

**路径名：**
- 绝对路径：从根目录开始
- 相对路径：从当前目录开始

## 五、文件系统布局

### 5.1 文件系统结构

```
| 引导块 | 超级块 | 空闲空间管理 | inode区 | 数据区 |
```

### 5.2 inode（索引节点）

- 每个 inode 存储文件元数据 + 数据块指针
- inode 大小固定（通常 128B 或 256B）
- inode 包含：文件类型、权限、大小、时间戳、15 个地址指针

### 5.3 空闲空间管理

| 方法 | 说明 |
|------|------|
| 空闲表 | 连续空闲区列表 |
| 空闲链 | 盘块链/空闲区链 |
| 位示图 | 每位对应一个盘块，0=空闲 |
| 成组链接 | UNIX 使用 |

## 六、磁盘调度

### 6.1 磁盘存取时间

```
存取时间 = 寻道时间 + 旋转延迟 + 传输时间
```

### 6.2 调度算法

| 算法     | 规则            | 特点       |
| ------ | ------------- | -------- |
| FCFS   | 按请求顺序服务       | 公平但寻道长   |
| SSTF   | 最短寻道时间优先      | 可能饥饿     |
| SCAN   | 电梯算法，到端后反向    | 两端请求等待长  |
| C-SCAN | 到端后直接回起点      | 响应均匀     |
| LOOK   | 到最远请求后反向（不到端） | SCAN改进   |
| C-LOOK | 到最远请求后回起点     | C-SCAN改进 |

## 七、易丢分点清单

- [ ] 多级索引最大文件大小公式记错

- [ ] FAT 是显式链接，不是隐式

- [ ] 位示图的位与盘块的对应关系搞反

## 🧠 思考模式

**遇到文件系统大题，第一反应应该是：**

1. **算指针容量**：索引题先算"一个索引块装几个指针"（盘块大小 ÷ 地址大小），再按级别累乘——所有文件大小公式都从这一个数字推出
2. **定位题型**：问最大文件 → 索引公式累加；问第 i 块在哪 → 判断落在哪级索引、访存几次；给 FAT → 沿链走
3. **磁盘调度画数轴**：把请求磁道号标在数轴上，按算法规则（SCAN 到端/LOOK 到最远请求）逐个移动累加距离

**知识串联提示：**
- 索引分配的"分级扩容"思想 ↔ 内存管理的"多级页表"：都是用间接层换取小文件省空间、大文件可扩展
- 文件存放的磁盘块 → I/O 管理板块的设备驱动负责真正读写；文件系统的读请求最终变成磁盘调度问题
- 容易混淆对比：隐式链接（指针在盘块内，只能顺序找）vs 显式链接 FAT（指针集中在内存表，可跳查）；SCAN 到磁道端点，LOOK 只到最远请求
