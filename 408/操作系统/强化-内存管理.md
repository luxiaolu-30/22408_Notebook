# 操作系统 强化-内存管理

> **大题位置**：46 题，8 分（OS 第二道大题高频考点）
> **核心能力**：页面置换过程模拟 + 分页地址转换
> **数据口径**：2016-2025 近 10 年大题统计

> **本板块串联**：内存管理是"地址"的学科——进程管理板块的每个进程在这里拥有自己的地址空间，其虚拟地址机制与计组存储系统板块的 Cache/TLB 是同一件事的软硬件两个视角。

## 🧭 知识主线

内存管理的主线是**"一个虚拟地址的生命周期"**：进程发出虚拟地址→拆成页号+页内偏移→查 TLB（快）或页表（慢）→页不在内存则缺页中断（需要页面置换）→拼出物理地址访存。所有零散知识点都挂在这条路径上：连续/非连续分配是"页从哪来"，页表/TLB 是"怎么查"，置换算法是"满了怎么办"，Belady 异常是"FIFO 算法的坑"。模拟题（置换表）和计算题（EAT、访存次数）都围绕这条路径的某一环展开。

## 二、内存分配方式

### 2.1 连续分配

| 方式 | 特点 | 缺点 |
|------|------|------|
| 单一连续 | 用户区整体分配 | 只能单道 |
| 固定分区 | 静态划分分区 | 内部碎片 |
| 动态分区 | 按需分配 | 外部碎片 |

**动态分区分配算法：**
- 首次适应（First Fit）：从头找第一个够大的
- 最佳适应（Best Fit）：找最小的够大分区
- 最坏适应（Worst Fit）：找最大的分区
- 邻近适应（Next Fit）：从上次位置继续找

### 2.2 非连续分配

| 方式 | 特点 |
|------|------|
| 分页 | 固定大小页面，无外部碎片 |
| 分段 | 按逻辑分段，有外部碎片 |
| 段页式 | 先分段再分页 |

## 三、分页地址转换

### 3.1 单级页表

```
虚拟地址 = 页号 || 页内偏移
  ↓ 查页表
物理地址 = 页框号 || 页内偏移
```

**地址位数计算：**
- 页面大小 4KB → 页内偏移 12 位
- 32 位虚拟地址 → 页号 20 位
- 物理地址 = 物理页框号(20位) + 页内偏移(12位)

### 3.2 二级页表

```
虚拟地址 = 一级页号 || 二级页号 || 页内偏移
→ 查一级页表 → 二级页表基地址
→ 查二级页表 → 物理页框号
→ 物理地址 = 物理页框号 || 页内偏移
```

**访存次数分析：**
- TLB 命中：1 次访存（直接取数据）
- TLB 未命中 + 单级页表 + 页面在内存：2 次访存（查页表 + 取数据）
- TLB 未命中 + 二级页表 + 页面在内存：3 次访存（查一级页表 + 查二级页表 + 取数据）
- 缺页：缺页中断 + 查页表 + 取数据

### 3.3 TLB（快表）

**结构：**
| 有效位 | 标记(虚页号) | 物理页框号 | 保护位 |

**查找方式：**
- 全相联：所有表项同时比较
- 组相联：先定位组，组内全相联

**有效访问时间（EAT）计算：**
```
EAT = TLB命中率 × (TLB查找 + Cache访问)
    + (1 - TLB命中率) × (TLB查找 + 页表查找 + Cache访问)
```

## 四、页面置换算法（核心考点）

### 4.1 FIFO（先进先出）

- 维护一个队列，替换最早进入的页面
- **Belady 异常**：增加物理块数反而缺页率上升

### 4.2 LRU（最近最久未使用）

- 每次访问更新时间戳
- 替换最久没被访问的页面
- 模拟用"栈"思路：刚访问的移到栈顶，淘汰栈底

### 4.3 CLOCK / 二次机会算法

- 每页有一个访问位，初始 0
- 访问时置 1
- 替换时：指针扫描，遇到 1 改 0 跳过，遇到 0 替换

### 4.4 改进型 CLOCK

增加修改位，四级优先级：
- (0,0) 最佳替换 → (0,1) → (1,0) → (1,1) 最差

### 4.5 手动模拟标准答题格式

**示例：页面序列 7,0,1,2,0,3,0,4，物理块数 3，LRU 算法**

| 访问 | 块1 | 块2 | 块3 | 缺页? | 替换 |
|:----:|-----|-----|-----|:-----:|------|
| 7 | 7 | | | 是 | — |
| 0 | 7 | 0 | | 是 | — |
| 1 | 7 | 0 | 1 | 是 | — |
| 2 | 2 | 0 | 1 | 是 | 换7 |
| 0 | 2 | 0 | 1 | 否 | — |
| 3 | 2 | 0 | 3 | 是 | 换1 |
| 0 | 2 | 0 | 3 | 否 | — |
| 4 | 4 | 0 | 3 | 是 | 换2 |

缺页率 = 6/8 = 75%

## 五、页面分配策略

| 策略 | 说明 |
|------|------|
| 固定分配局部置换 | 物理块数固定，缺页时在本进程内替换 |
| 可变分配全局置换 | 物理块数可变，缺页时从全局空闲队列取 |
| 可变分配局部置换 | 物理块数可变，缺页时在本进程内替换 |

## 六、易丢分点清单

- [ ] FIFO 有 Belady 异常，LRU 没有
- [ ] CLOCK 算法指针方向（顺时针）和访问位处理搞混
- [ ] LRU 模拟时更新顺序错（刚访问的移到栈顶）
- [ ] 二级页表访存次数算错（TLB 未命中时 = 3 次访存）
- [ ] 物理块数增加反而缺页增加（FIFO Belady 异常）
- [ ] 缺页中断 vs 一般缺页的概念混淆
- [ ] EAT 计算公式中 TLB 命中/未命中的分支搞反

## 🧠 思考模式

**遇到内存大题，第一反应应该是：**

1. **画地址结构**：先算各字段位数（页内偏移 = log₂(页面大小)），把虚拟地址拆开——地址题 80% 的错误在拆位
2. **走查表路径**：TLB 命中？页表命中？缺页？——每条路径对应不同的访存次数，按路径算 EAT
3. **模拟置换**：换页题直接画表格，每行记录"访问页→三个物理块状态→是否缺页→替换谁"，最后数缺页次数
4. **验证反常**：FIFO 换更大块数后缺页率反而升 → 是 Belady 异常，不是算错

**知识串联提示：**
- OS 的页表 ↔ 计组存储系统的虚存：计组问"地址怎么拆、Cache 怎么查"，OS 问"页面怎么换、表怎么组织"——同一个虚存机制的两半，大题常合在一起考
- LRU 页面置换的"最近未用"思想 ↔ 计组 Cache 替换算法的 LRU：完全同源，一个按页算一个按行算
- 容易混淆对比：缺页中断（内中断，OS 介入换页）vs 一般 I/O 中断（外中断）；页面大小决定偏移位数，物理块数不影响地址结构只影响命中率
