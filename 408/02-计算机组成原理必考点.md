## 一、IEEE 754 单精度浮点数（选择 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

IEEE 754 单精度浮点数用 **32 位**表示一个实数，由三部分组成：

- **符号位 S**（1 位）：0 表示正数，1 表示负数
- **阶码 E**（8 位）：用**移码**表示，偏移量为 **127**（即实际指数 = E - 127）
- **尾数 M**（23 位）：规格化数隐含前导 1，即实际尾数为 **1.M**（二进制）

**真值公式**：

$$X = (-1)^S \times 1.M \times 2^{E-127}$$

**关键理解**：
- 阶码全 0（E=0）和全 1（E=255）被保留用于特殊值，所以规格化数的阶码范围是 **1~254**，对应实际指数 **-126~+127**
- 规格化时尾数最高位总是 1，所以隐含不存，这样相当于免费多了一位精度
- 非规格化数（E=0）时，实际指数固定为 -126，且尾数不隐含前导 1（即 0.M），用于表示非常接近 0 的数

#### 2. 关键公式

| 公式 | 说明 |
|------|------|
| $X = (-1)^S \times 1.M \times 2^{E-127}$ | 规格化数真值 |
| $X = (-1)^S \times 0.M \times 2^{-126}$ | 非规格化数真值 |
| 偏移量 = $2^{n-1} - 1 = 127$ | n=8 位阶码 |
| 最大正数 ≈ $(2-2^{-23}) \times 2^{127} \approx 3.4 \times 10^{38}$ | 上溢边界 |
| 最小规格化正数 = $2^{-126} \approx 1.18 \times 10^{-38}$ | 下溢边界 |
| 最小非规格化正数 = $2^{-149}$ | 最接近 0 的正数 |

**特殊值对照表**：

| 阶码 E | 尾数 M | 含义 |
|--------|--------|------|
| 0 | 0 | ±0 |
| 0 | 非 0 | 非规格化数 |
| 1~254 | 任意 | 规格化数 |
| 255 | 0 | ±∞ |
| 255 | 非 0 | NaN（非数） |

#### 3. 解题步骤

**题型 A：十进制 → IEEE 754 表示**

1. 确定符号位 S（正=0，负=1）
2. 将十进制数转为二进制
3. 移动小数点，使整数部分只有 1 位（规格化），记录移动的位数作为指数
4. 计算阶码 E = 实际指数 + 127，转为 8 位二进制
5. 取规格化后小数部分（去掉前导 1），补齐 23 位作为尾数 M
6. 组合 S+E+M，转为十六进制

**题型 B：IEEE 754 → 十进制真值**

1. 将十六进制转为 32 位二进制
2. 拆分 S（1 位）、E（8 位）、M（23 位）
3. 判断 E 的值：全 0？全 1？规格化？
4. 计算实际指数 = E - 127
5. 代入公式求真值

**题型 C：浮点加减运算**

1. **对阶**：小阶向大阶对齐，尾数右移（可能丢失精度）
2. **尾数运算**：用补码进行加减
3. **规格化**：
   - 尾数最高位与符号位相同 → 左规（尾数左移，阶码减 1）
   - 尾数溢出（符号位和最高位不同） → 右规（尾数右移，阶码加 1）
4. **舍入**：0 舍 1 入法 / 恒置 1 法
5. **溢出判断**：阶码上溢 → 溢出；阶码下溢 → 视为 0

#### 4. 典型例题

> **例题**：将十进制数 -3.75 转换为 IEEE 754 单精度浮点数表示（十六进制）。
>
> **解答**：
> 1. 符号位：负数，S = 1
> 2. 转二进制：3.75 = 11.11B
> 3. 规格化：11.11 = 1.111 × 2¹，指数 = 1
> 4. 阶码 E = 1 + 127 = 128 = 10000000B
> 5. 尾数 M = 111 0000 0000 0000 0000 0000（去掉前导 1，补 0 至 23 位）
> 6. 组合：1 10000000 11100000000000000000000
> 7. 十六进制：**0xC0700000**

#### 5. 易错点/坑点

- **偏移量记错**：单精度偏移 127，双精度偏移 1023，不要混淆
- **尾数忘记加前导 1**：规格化数尾数是 1.M，不是 0.M
- **对阶方向错**：小阶向大阶对齐（尾数右移），不是大阶向小阶对齐
- **左规/右规混淆**：尾数溢出时右规，规格化时左规
- **十六进制转换时位数不对**：单精度一定是 8 位十六进制

#### 6. 记忆口诀/技巧

- **口诀**："一符号、八阶码、二十三尾数，偏移一百二十七"
- **快速判断范围**：记住 ±3.4×10³⁸ 是最大绝对值
- **特殊值记忆**："全零零，全一无穷 NaN 分"

## 二、Cache 映射与命中率计算（选择 + 应用 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

**Cache（高速缓冲存储器）** 是 CPU 和主存之间的小容量高速存储器，用于缓解 CPU 与主存之间的速度差异。其核心问题是：**主存中的数据应该放在 Cache 的哪个位置？**

**三种映射方式**：

- **直接映射**：主存中的每一块只能映射到 Cache 中唯一固定的位置
  - 映射规则：Cache 块号 = 主存块号 mod Cache 块数
  - 优点：硬件简单，查找快
  - 缺点：冲突率高，即使 Cache 有空块也可能被替换

- **全相联映射**：主存中的任意一块可以放在 Cache 的任意位置
  - 优点：冲突率低，空间利用率高
  - 缺点：查找时需要比较所有标记，硬件成本高

- **组相联映射**：主存块映射到 Cache 的特定组，组内可以任意放置
  - 折中方案，n 路组相联表示每组有 n 个块
  - 当 n=1 时退化为直接映射，n=Cache 块数时退化为全相联

#### 2. 关键公式

| 公式 | 符号含义 |
|------|----------|
| Cache 块数 = Cache 容量 / 块大小 | — |
| 主存块号 = 主存地址 / 块大小 | — |
| **直接映射**：Cache 块号 = 主存块号 mod Cache 块数 | — |
| **组相联**：组号 = 主存块号 mod Cache 组数 | — |
| 块内地址位数 = $\log_2(\text{块大小})$ | — |
| 块号位数 = $\log_2(\text{Cache 块数})$ | — |
| 组号位数 = $\log_2(\text{Cache 组数})$ | — |
| 标记位数 = 地址总位数 - 块号位数 - 块内地址位数 | 直接映射 |
| 标记位数 = 地址总位数 - 组号位数 - 块内地址位数 | 组相联 |
| **命中率**：$h = \frac{N_c}{N_c + N_m}$ | Nc=Cache 命中次数，Nm=主存访问次数 |
| **有效访问时间**：$t_e = h \times t_c + (1-h) \times t_m$ | tc=Cache 访问时间，tm=主存访问时间 |
| **加速比**：$S = \frac{t_m}{t_e}$ | — |

**地址结构（直接映射）**：

```
┌─────────┬──────────┬──────────┐
│  标记   │ 块号/组号 │ 块内地址 │
│ (Tag)   │ (Index)  │ (Offset) │
└─────────┴──────────┴──────────┘
```

#### 3. 解题步骤

**题型 A：求地址结构各字段位数**

1. 根据块大小计算块内地址位数：$\log_2(\text{块大小})$
2. 根据 Cache 容量和块大小计算 Cache 块数
3. 根据映射方式计算块号/组号位数
4. 标记位数 = 地址总位数 - 块号位数 - 块内地址位数

**题型 B：模拟 Cache 命中/替换过程**

1. 将访问地址转为二进制
2. 根据映射方式提取块号/组号
3. 比较该位置的标记是否匹配
4. 匹配 → 命中；不匹配 → 缺失，需要调入（直接映射直接替换，组相联可能需要 LRU）

**题型 C：Cache + 虚拟存储综合题（应用题 43）**

1. 理清地址结构：虚拟地址 → 物理地址 → Cache 地址
2. 注意是**物理寻址 Cache**还是**虚拟寻址 Cache**
3. 计算平均访存时间 = 命中时间 + 缺失率 × 缺失代价

#### 4. 典型例题

> **例题**：某计算机主存容量 64MB，Cache 容量 32KB，每块 8KB，采用直接映射。
> (1) 主存地址有多少位？
> (2) 地址结构中标记、块号、块内地址各多少位？
>
> **解答**：
> (1) 64MB = $2^{26}$ B，主存地址 **26 位**
> (2) 块大小 8KB = $2^{13}$ B → 块内地址 **13 位**
> Cache 块数 = 32KB / 8KB = 4 = $2^2$ → 块号 **2 位**
> 标记位数 = 26 - 2 - 13 = **11 位**
>
> 地址结构：标记(11 位) | 块号(2 位) | 块内地址(13 位)

#### 5. 易错点/坑点

- **单位换算错误**：KB 要乘以 $2^{10}$，MB 乘以 $2^{20}$，注意是 2 的幂不是 10 的幂
- **块数 vs 组数混淆**：组相联中，组数 = Cache 块数 / 每组块数（路数）
- **标记位计算错误**：标记位 = 总地址位 - 索引位 - 偏移位，不要漏算
- **LRU 替换策略**：组相联中同一组内使用 LRU，不是整个 Cache
- **命中率公式分子分母搞反**：h = Cache 命中次数 / 总访问次数

#### 6. 记忆口诀/技巧

- **直接映射口诀**："主存块号取模 Cache 块数，一对一不商量"
- **组相联口诀**："组间直接定，组内全相联"
- **地址结构记忆**："标记 + 索引 + 偏移"（Tag + Index + Offset）
- **对比表格**：

| 映射方式 | 冲突率 | 硬件成本 | 查找速度 |
|----------|--------|----------|----------|
| 直接映射 | 高 | 低 | 快 |
| 全相联 | 低 | 高 | 慢 |
| 组相联 | 中 | 中 | 中 |

## 三、寻址方式（选择 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

**寻址方式**是指 CPU 根据指令中的地址码字段来获取操作数实际地址的方式。408 重点考查**七种寻址方式**的特点和有效地址（EA）计算方法。

**七种寻址方式详解**：

| 寻址方式 | 有效地址 EA | 操作数位置 | 特点 |
|----------|-------------|------------|------|
| **立即寻址** | — | 指令中 | 操作数直接在指令中，无需访存 |
| **直接寻址** | EA = A | 内存 | 地址码就是操作数的内存地址 |
| **间接寻址** | EA = (A) | 内存 | 地址码指向的是操作数地址的地址 |
| **寄存器寻址** | — | 寄存器 | 操作数在指定寄存器中 |
| **寄存器间接寻址** | EA = (R) | 内存 | 寄存器中存放的是操作数的内存地址 |
| **变址寻址** | EA = (IX) + A | 内存 | 变址寄存器 + 形式地址，适合数组 |
| **基址寻址** | EA = (BR) + A | 内存 | 基址寄存器 + 形式地址，适合重定位 |

**核心区别**：
- **变址寻址**：变址寄存器内容可变（用于循环遍历），形式地址 A 固定
- **基址寻址**：基址寄存器内容固定（程序起始地址），形式地址 A 可变（偏移量）

#### 2. 关键公式

| 寻址方式 | 有效地址 | 访存次数 |
|----------|----------|----------|
| 立即寻址 | 无 | 0 |
| 直接寻址 | EA = A | 1 |
| 间接寻址 | EA = (A) | 2 |
| 寄存器寻址 | 无 | 0 |
| 寄存器间接寻址 | EA = (R) | 1 |
| 变址寻址 | EA = (IX) + A | 1 |
| 基址寻址 | EA = (BR) + A | 1 |

**扩展操作码设计**：
- 目的：在指令长度不变的前提下，增加指令数量
- 原则：短操作码不能是长操作码的前缀
- 公式：若指令字长 n 位，操作码 p 位，地址码 a 位，则 $n = p + a$

#### 3. 解题步骤

**题型 A：判断寻址方式**

1. 看地址码字段是什么：立即数？寄存器编号？内存地址？
2. 看是否需要计算：需要加变址/基址寄存器？
3. 看访存次数：一次？两次？

**题型 B：计算有效地址**

1. 确定寻址方式
2. 根据公式计算 EA
3. 注意间接寻址需要多次访存

**题型 C：扩展操作码设计**

1. 确定指令字长和地址码位数
2. 操作码位数 = 指令字长 - 地址码位数
3. 按优先级分配：先给高频指令短操作码
4. 验证：短操作码不能是长操作码的前缀

#### 4. 典型例题

> **例题**：某计算机指令字长 16 位，地址码长 6 位，有双地址指令和单地址指令两种格式。
> 若双地址指令有 15 条，问单地址指令最多有多少条？
>
> **解答**：
> 1. 双地址指令操作码位数 = 16 - 6×2 = **4 位**
> 2. 4 位操作码最多表示 $2^4 = 16$ 条双地址指令
> 3. 已用 15 条，剩余 1 个编码用于扩展：1111
> 4. 单地址指令操作码位数 = 16 - 6 = **10 位**
> 5. 前 4 位固定为 1111，后 6 位可扩展：$2^6 = 64$ 种
> 6. 单地址指令最多 **64 条**

#### 5. 易错点/坑点

- **变址 vs 基址混淆**：变址寄存器内容变（循环），基址寄存器内容不变（重定位）
- **间接寻址访存次数**：一次间接访存 2 次，两次间接访存 3 次
- **扩展操作码前缀规则**：短操作码不能是长操作码的前缀，否则无法区分
- **有效地址 vs 操作数**：EA 是操作数的地址，不是操作数本身
- **立即寻址操作数在指令中**：不需要访存，速度最快

#### 6. 记忆口诀/技巧

- **寻址方式口诀**："立即直接间，寄存变基间"
  - 立即、直接、间接、寄存器、寄存器间接、变址、基址
- **变址基址区分口诀**："变址循环跑，基址定位牢"
- **访存次数记忆**："立即寄存器零次，直接寄存器间一次，间接两次往上翻"
- **扩展操作码记忆**："短码不能当长码的前头"

## 四、CPU 数据通路与指令执行（选择 + 应用 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

**CPU 数据通路**是 CPU 内部各功能部件之间传送数据的路径，是理解指令执行过程的基础。

**CPU 核心部件**：
- **PC（程序计数器）**：存放下一条指令地址，自动 +1
- **IR（指令寄存器）**：存放当前正在执行的指令
- **MAR（存储器地址寄存器）**：存放要访问的内存地址
- **MDR（存储器数据寄存器）**：存放从内存读/写的数据
- **ACC（累加器）**：存放运算结果
- **ALU（算术逻辑单元）**：执行算术和逻辑运算
- **CU（控制器）**：产生控制信号

**指令周期**：
1. **取指周期**：从内存取出指令 → PC → MAR → 内存 → MDR → IR
2. **间址周期**：取操作数有效地址（间接寻址时）
3. **执行周期**：执行指令操作
4. **中断周期**：处理中断请求

**控制器对比**：

| 特性 | 硬布线控制器 | 微程序控制器 |
|------|--------------|--------------|
| 核心部件 | 组合逻辑寄存器 | 微指令寄存器 |
| 设计方法 | 时序逻辑设计 | 程序设计思想 |
| 修改难度 | 难（需改电路） | 易（改微程序） |
| 执行速度 | 快 | 较慢 |
| 适合场景 | RISC | CISC |
| 易扩充性 | 差 | 好 |

#### 2. 关键公式

| 公式 | 说明 |
|------|------|
| 指令周期 = 取指 + 间址 + 执行 + 中断 | — |
| CPU 周期数 = 指令周期包含的时钟周期数 | — |
| 指令流水线执行时间 = $(n + k - 1) \times \Delta t$ | n=指令数，k=段数，$\Delta t$=时钟周期 |
| 流水线加速比 = 非流水线时间 / 流水线时间 | — |
| 流水线吞吐率 = 指令数 / 总执行时间 | — |

**流水线冒险**：
- **结构冒险**：多条指令争用同一资源
- **数据冒险**：后续指令需要前面指令的结果（RAW、WAR、WAW）
- **控制冒险**：分支指令导致流水线清空

#### 3. 解题步骤

**题型 A：分析指令执行过程**

1. 确定指令类型（传送、运算、转移等）
2. 按周期分析：取指 → 间址 → 执行
3. 写出每个时钟周期内的数据流向
4. 标注控制信号

**题型 B：流水线计算**

1. 确定流水线段数 k
2. 计算第一条指令完成时间：$k \times \Delta t$
3. 计算剩余指令执行时间：$(n-1) \times \Delta t$
4. 总时间 = $(n + k - 1) \times \Delta t$
5. 加速比 = $n \times k \times \Delta t$ / 总时间

**题型 C：流水线冒险处理**

1. 识别冒险类型
2. 结构冒险：增加资源或插入气泡
3. 数据冒险：转发（旁路）或暂停
4. 控制冒险：分支预测或延迟槽

#### 4. 典型例题

> **例题**：某流水线有 5 段，各段执行时间均为 $\Delta t$。
> (1) 若连续执行 100 条指令，总时间是多少？
> (2) 加速比是多少？
>
> **解答**：
> (1) 总时间 = $(100 + 5 - 1) \times \Delta t = 104\Delta t$
> (2) 非流水线时间 = $100 \times 5 \times \Delta t = 500\Delta t$
> 加速比 = $500 / 104 \approx 4.81$

#### 5. 易错点/坑点

- **PC 自动加 1 的时机**：取指周期结束后 PC 才 +1，不是执行周期
- **间址周期容易被忽略**：间接寻址需要额外的间址周期
- **流水线时间公式**：是 $(n+k-1) \times \Delta t$，不是 $n \times k \times \Delta t$
- **硬布线 vs 微程序混淆**：硬布线速度快但难修改，微程序易修改但速度慢
- **数据通路中 MAR/MDR 作用**：MAR 存地址，MDR 存数据，不要混淆
- **中断周期 PC 入栈**：中断时 PC 内容需要保存到栈中，以便返回

#### 6. 记忆口诀/技巧

- **指令周期口诀**："取间执行中，四步记心中"
- **CPU 部件记忆**："PC 指路，IR 存令，MAR 寻址，MDR 搬数据"
- **流水线公式记忆**："n 加 k 减 1，乘以周期得时间"
- **控制器对比记忆**："硬快慢改，软慢快改"（硬布线快但难改，微程序慢但易改）

## 五、虚拟存储器（选择 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

**虚拟存储器**是一种将主存和辅存（硬盘）结合起来，为用户提供一个比实际主存容量大得多的"虚拟地址空间"的技术。用户编程时使用的是虚拟地址，由操作系统和硬件配合将其转换为物理地址。

**核心思想**：
- 仅将当前运行需要的页面/段调入主存，其余存在磁盘上
- 当访问的页面不在主存时，产生**缺页中断**，由操作系统调入
- 用户程序可以运行在比实际内存更大的地址空间中

**三种实现方式**：
- **页式虚拟存储**：将虚拟空间和物理空间都划分为固定大小的页
- **段式虚拟存储**：按程序逻辑结构划分（代码段、数据段等）
- **段页式虚拟存储**：先分段，每段再分页（结合两者优点）

**关键组件**：
- **页表**：存放在主存中，记录虚拟页号到物理页框号的映射
- **快表 TLB**：页表的高速缓存，用相联存储器实现
- **缺页中断**：访问页面不在主存时触发

#### 2. 关键公式

| 公式 | 说明 |
|------|------|
| 虚拟地址空间大小 = $2^{\text{虚拟地址位数}}$ | — |
| 虚拟页号位数 = 虚拟地址位数 - 页内地址位数 | — |
| 页内地址位数 = $\log_2(\text{页面大小})$ | — |
| 页表项数 = 虚拟页数 = $2^{\text{虚拟页号位数}}$ | — |
| 页表大小 = 页表项数 × 页表项长度 | — |
| **TLB 命中时访存次数**：1 次（直接访问主存） | — |
| **TLB 缺失时访存次数**：2 次（查页表 + 访问主存） | — |
| **缺页时访存次数**：3 次（查页表 + 缺页中断处理 + 访问主存） | — |
| 平均访存时间 = $h_{\text{TLB}} \times (t_{\text{TLB}} + t_m) + (1-h_{\text{TLB}}) \times (t_{\text{TLB}} + 2t_m)$ | 不考虑缺页 |
| 考虑缺页的平均访存时间 = $(1-p) \times t_{\text{正常}} + p \times t_{\text{缺页}}$ | p=缺页率 |

**地址变换过程**：

```
虚拟地址 → [虚拟页号 | 页内偏移]
                ↓
         查 TLB（命中？）
          ↙        ↘
       命中         未命中
        ↓              ↓
    直接得到      查页表（主存）
    物理页框号         ↓
        ↓          得到物理页框号
    物理地址 = 物理页框号 + 页内偏移
```

#### 3. 解题步骤

**题型 A：地址变换**

1. 将虚拟地址转为二进制
2. 根据页面大小分离虚拟页号和页内偏移
3. 查 TLB/页表得到物理页框号
4. 物理地址 = 物理页框号 + 页内偏移（页内偏移不变）

**题型 B：页表大小计算**

1. 计算虚拟页数 = 虚拟地址空间 / 页面大小
2. 计算页表项长度 = 物理页框号位数 + 控制位（有效位、修改位、访问位等）
3. 页表大小 = 虚拟页数 × 页表项长度

**题型 C：缺页率与平均访存时间**

1. 确定 TLB 命中率或缺页率
2. 分情况计算：TLB 命中、TLB 缺失但页表命中、缺页
3. 加权平均得到平均访存时间

**题型 D：页面置换算法（FIFO/LRU/OPT）**

1. 模拟访问过程，维护页面队列
2. FIFO：替换最先进入的页面
3. LRU：替换最长时间未使用的页面
4. OPT：替换将来最长时间不被访问的页面（理论最优）

#### 4. 典型例题

> **例题**：某系统虚拟地址 32 位，页面大小 4KB，TLB 命中率 90%，访问 TLB 时间 10ns，访问主存时间 100ns，缺页率 1%，缺页处理时间 10ms。
> 求平均访存时间。
>
> **解答**：
> 情况 1：TLB 命中（90%）→ 访问 TLB + 访问主存 = 10 + 100 = 110ns
> 情况 2：TLB 缺失（10%）→ 访问 TLB + 查页表 + 访问主存 = 10 + 100 + 100 = 210ns
> 不考虑缺页的平均时间 = $0.9 \times 110 + 0.1 \times 210 = 99 + 21 = 120$ns
>
> 考虑缺页：
> 平均访存时间 = $(1 - 0.01) \times 120 + 0.01 \times 10 \times 10^6$
> $= 0.99 \times 120 + 100000$
> $= 118.8 + 100000 = 100118.8$ns ≈ **100.1μs**

#### 5. 易错点/坑点

- **页内偏移不变**：虚拟地址到物理地址变换时，页内偏移位数和数值都不变
- **TLB 是页表的缓存**：TLB 中只存放部分页表项，不是全部
- **缺页中断处理时间极长**：10ms 级别，远大于正常访存（ns 级别）
- **页面置换算法计算缺页次数**：注意初始时主存为空，第一次访问必然缺页
- **多级页表空间计算**：不要忘记页目录表本身也占空间
- **Cache 与虚拟存储对比**：Cache 失效由硬件处理，缺页由操作系统处理

#### 6. 记忆口诀/技巧

- **地址变换口诀**："虚拟页号查映射，页内偏移跟着走"
- **访存次数记忆**："TLB 命中一次完，缺失两次缺页三"
- **页面置换算法口诀**：
  - FIFO："先进先出排队走"
  - LRU："最近最少被替换"
  - OPT："将来不用我最优"
- **对比表格**：

| 特性 | Cache | 虚拟存储器 |
|------|-------|------------|
| 管理方式 | 硬件 | 操作系统 + 硬件 |
| 失效处理 | 硬件自动 | 缺页中断（软件） |
| 失效代价 | 小（ns~μs） | 大（ms） |
| 映射对象 | 主存块 → Cache 块 | 虚拟页 → 物理页框 |
| 快表 | — | TLB（页表的 Cache） |
