# 计算机组成原理 强化 · 计算机系统概述

> **数据口径**：2016-2025 近 10 年大题统计。计组大题为 43-44 题（22 分）。
> 本章仅出现选择题，分值占比约 2-4 分，属低频但必考基础章节。

> **本板块串联**：本章是全计组的总纲——确立"存储程序"的机器观与"性能"这个唯一目标函数，后面各章（数据运算、存储、指令、CPU、总线）都是它的展开与实现。

## 🧭 知识主线

本章零散的概念背后只有一条主线：**性能是计组的唯一目标函数，层次结构是手段，CPI/MIPS/主频是度量**。冯·诺依曼架构（存储程序、五大部件）确立了机器的基本形态；层次结构（微程序级→机器级→OS 级→汇编级→高级语言级）解释了软硬件如何分层协作、上层如何逐级抽象；而真正每年必考的是性能度量链——主频 $f$ 给出节拍，CPI 把"指令"折算成"周期"，CPU 执行时间 $=\dfrac{\text{指令数} \times \text{CPI}}{f}$ 把三者统一成最终答案，MIPS 与 FLOPS 是同一性能在不同量纲下的读数。更关键的是，这个公式就是全书的目录：指令系统优化**指令数**（RISC 精简指令），CPU 流水线压低 **CPI**（消除冒险停顿），存储与总线减少访存等待、提升部件利用率——后面每一章都在回答"如何让机器更快"这个问题。

## 二、计算机发展历程

### 四代计算机

| 代 | 时间 | 器件 | 特点 |
|----|------|------|------|
| 第一代 | 1946-1957 | 电子管 | ENIAC，冯·诺依曼架构提出 |
| 第二代 | 1958-1964 | 晶体管 | 出现高级语言、操作系统雏形 |
| 第三代 | 1965-1971 | 中小规模集成电路 | 多道程序、分时系统 |
| 第四代 | 1972-至今 | 大规模/超大规模集成电路 | 微型化、并行化、网络化 |

### 摩尔定律

- 集成电路芯片上所集成的晶体管数目每隔 **18 个月**翻一番
- 性能也同步提升，但近年来受物理极限制约趋缓

### 冯·诺依曼架构要点

1. 计算机由五大部件组成：**运算器、控制器、存储器、输入设备、输出设备**
2. **存储程序**：指令和数据以同等地位存于存储器中
3. 指令由操作码和地址码组成，按顺序执行
4. 以**运算器**为中心（现代计算机以存储器为中心）

> 易错：冯·诺依曼架构以运算器为中心，现代计算机以**存储器**为中心。

## 三、计算机层次结构

从下到上共 5 级（虚拟机器）：

```
┌──────────────────┐
│  高级语言级       │  ← 第5级：C/Java/Python 等高级语言
├──────────────────┤
│  汇编语言级       │  ← 第4级：汇编语言，需汇编程序翻译
├──────────────────┤
│  操作系统级       │  ← 第3级：操作系统提供的机器级接口
├──────────────────┤
│  一般机器级       │  ← 第2级：机器语言（指令系统），用硬件实现
├──────────────────┤
│  微程序设计级     │  ← 第1级：微指令编程，由固件（微程序）实现
└──────────────────┘
```

| 层级 | 实现方式 | 说明 |
|------|---------|------|
| 微程序设计级 | 微程序（固件） | 最底层，每条机器指令对应一段微程序 |
| 一般机器级 | 硬件/传统机器级 | 机器语言指令系统 |
| 操作系统级 | 操作系统软件 | 系统调用接口 |
| 汇编语言级 | 汇编程序 | 助记符与机器指令一一对应 |
| 高级语言级 | 编译程序 | 面向用户 |

> **翻译方式**：高级语言 → 编译/解释 → 汇编语言 → 汇编 → 机器语言
> **层次关系**：下层是上层的实现基础，上层是下层的抽象

## 四、性能指标（核心考点）

### 4.1 基本概念

| 指标 | 定义 | 公式 |
|------|------|------|
| **主频** $f$ | CPU 时钟频率（Hz） | 每秒时钟周期数 |
| **时钟周期** $T$ | 一个时钟信号的时间 | $T = 1/f$ |
| **CPI** | 执行一条指令所需的平均时钟周期数 | $\text{CPI} = \frac{\text{总时钟周期数}}{\text{指令数}}$ |
| **MIPS** | 每秒执行百万条指令 | $\text{MIPS} = \frac{f}{\text{CPI} \times 10^6}$ |
| **FLOPS** | 每秒浮点运算次数 | 与主频和浮点运算能力有关 |
| **CPU执行时间** | 执行某程序所需时间 | $t = \frac{\text{指令数} \times \text{CPI}}{f}$ |

### 4.2 CPI 计算详解

$$\text{CPI} = \sum_{i=1}^{n} \left( \text{CPI}_i \times \frac{C_i}{\text{总指令数}} \right)$$

其中 $C_i$ 为第 $i$ 类指令的数量，$\text{CPI}_i$ 为第 $i$ 类指令的时钟周期数。

**典型计算模板**：

```
已知三类指令：
  A 类：占 50%，CPI = 2
  B 类：占 30%，CPI = 3
  C 类：占 20%，CPI = 4

则 CPI = 0.5×2 + 0.3×3 + 0.2×4 = 1.0 + 0.9 + 0.8 = 2.7

若主频 = 600MHz：
  MIPS = 600×10^6 / (2.7 × 10^6) ≈ 222.2
  CPU执行时间 = 指令数 × 2.7 / (600×10^6)
```

### 4.3 MIPS 与 CPI 的关系

$$\boxed{\text{MIPS} = \frac{f}{\text{CPI} \times 10^6} = \frac{1}{\text{CPI} \times T \times 10^6}}$$

- MIPS 越大，执行速度越快（在同一指令集下）
- **不能跨体系结构比较 MIPS**：不同 ISA 的"一条指令"复杂度不同

### 4.4 FLOPS

| 单位 | 值 |
|------|-----|
| FLOPS | $10^0$ |
| MFLOPS | $10^6$ |
| GFLOPS | $10^9$ |
| TFLOPS | $10^{12}$ |
| PFLOPS | $10^{15}$ |

### 4.5 CPU 执行时间公式推导

$$\text{CPU执行时间} = \frac{\text{指令数} \times \text{CPI}}{\text{主频}} = \text{指令数} \times \text{CPI} \times \text{时钟周期}$$

**三种优化途径**：
1. 减少指令数（编译器优化、RISC）
2. 降低 CPI（流水线、超标量）
3. 提高主频（工艺提升）

> 易错：**时钟周期和主频成反比**，时钟周期变短 = 主频提高 = 速度变快。但主频高不等于性能高（还需考虑 CPI 和指令数）。

## 五、基准测试程序

| 基准程序 | 适用场景 | 特点 |
|---------|---------|------|
| **SPEC CPU** | CPU 性能 | 综合评价整数/浮点性能 |
| **TPC-C** | 数据库 | 在线事务处理 |
| **Linpack** | 科学计算 | 线性代数，TOP500 排名依据 |
| **Coremark** | 嵌入式 | EEMBC 标准 |

**基准程序的局限性**：
1. 基准程序是**典型程序**，不代表实际应用场景
2. 硬件厂商可能针对基准程序进行"特殊优化"
3. 不同基准程序衡量维度不同，不可直接比较
4. 基准程序无法覆盖所有应用领域

> **高频考点**：基准测试程序的**局限性**常以选择题形式考查。

## 六、易错点清单

| # | 易错点 | 正确理解 |
|---|--------|---------|
| 1 | CPI 和 MIPS 无关 | $\text{MIPS} = f / (\text{CPI} \times 10^6)$，CPI 越小 MIPS 越大 |
| 2 | 主频越高性能越好 | 错！还需看 CPI 和指令数。主频高但 CPI 也高时性能未必提升 |
| 3 | MIPS 可跨平台比较 | 错！不同 ISA 的"指令"粒度不同，MIPS 只能在同 ISA 下比较 |
| 4 | FLOPS = 指令执行速度 | 错！FLOPS 衡量浮点运算次数，MIPS 衡量指令条数，量纲不同 |
| 5 | 时钟周期 = 指令周期 | 错！时钟周期是 CPU 基准节拍，指令周期 = CPI × 时钟周期 |
| 6 | 基准程序代表真实性能 | 错！基准程序是典型程序，存在局限性 |
| 7 | 冯·诺依曼架构以存储器为中心 | 错！冯·诺依曼以**运算器**为中心，现代计算机才以存储器为中心 |
| 8 | 存储程序 = 程序存储 | 存储程序指指令和数据**同等地位**存于存储器，且可自动执行 |
| 9 | 微程序设计级 = 最上层 | 错！微程序设计级是**最底层**（第1级），高级语言级是第5级 |
| 10 | CPI 是固定值 | 错！CPI 是**平均值**，取决于程序中各类指令的比例 |

## 🧠 思考模式

**遇到这类题，第一反应应该是：**

1. 性能计算题：先找齐三要素——指令条数、各类指令 CPI（或加权平均 CPI）、主频，缺什么先由已知条件推什么
2. 套公式 $\text{CPU执行时间} = \dfrac{\text{指令数} \times \text{CPI}}{\text{主频}}$（或 $\text{MIPS} = \dfrac{f}{\text{CPI} \times 10^6}$），统一单位（MHz/GHz、微秒/毫秒）后再算
3. 对比类题目（A 机 vs B 机）用比值法：性能之比 = 执行时间之比的倒数，不要直接比较 MIPS 或主频

**知识串联提示：**
- 与其他板块的关联：CPU 执行时间公式是全书的"总公式"——指令系统（RISC 减少指令数）、CPU 流水线（降低 CPI）、总线与存储（减少访存等待）分别在优化公式的三个因子；CPU 板块每年必考的流水线 CPI 计算题，本质就是本章加权 CPI 公式的应用
- 容易混淆的概念对比：MIPS vs FLOPS（指令条数 vs 浮点运算次数，量纲不同不可互比）；主频 vs 性能（主频只是三因子之一）；时钟周期 vs 指令周期（指令周期 = CPI × 时钟周期）；冯·诺依曼以运算器为中心 vs 现代计算机以存储器为中心
