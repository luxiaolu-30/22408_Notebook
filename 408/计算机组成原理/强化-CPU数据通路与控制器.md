# 计算机组成原理 强化 · CPU 数据通路与控制器

> **数据口径**：2016-2025 近 10 年大题统计。计组大题为 43-44 题（22 分）。
> **44 题大题约 4/10 年考**，常与指令系统结合，考查数据通路流动与控制信号确定。

> **本板块串联**：CPU 是指令系统的执行者——指令板块定义"契约"，本章回答"契约如何被硬件履行"；流水线冒险与 CPI 计算是选择题 10/10 双必考，数据通路分析是 44 题大题常客。

## 🧭 知识主线

本章全部内容围绕**一条指令的执行之旅**展开：取指→译码→执行→访存→写回。**数据通路是路**——PC→MAR→主存→MDR→IR 完成取指，IR 拆出操作码和地址码完成译码，ALU 完成运算，数据存储器完成访存，结果写回寄存器堆；**控制信号是灯**——控制器在路口指挥数据流向，硬布线用组合逻辑直接产生信号（快、难改，适合 RISC），微程序把微命令编成微指令存入控制存储器（慢、规整、易扩展，适合 CISC）；**流水线是让五辆车同时上路**——五条指令的五个阶段在时间上重叠。旅行方式决定性能：单周期让所有指令陪最慢的 lw 走完全程（CPI=1 但时钟慢），多周期把旅程分段（时钟快但 CPI 可变），流水线两头兼得（理想 CPI=1 且时钟快）。并行的代价是三种"交通事故"：结构冒险（抢道，分立 IM/DM 解决）、数据冒险（后车要用前车尚未到站的货，转发解决，Load-Use 必须停顿 1 周期）、控制冒险（不知道往哪拐，分支预测解决）。每年必考的 CPI 计算就是把所有停顿折进"每条指令平均周期数"，最终回扣概述章的总公式：CPU 执行时间 = 指令数 × CPI / 主频——本章所做的一切都是在压 CPI。

## 二、CPU 基本结构

### 2.1 CPU 四大组成部分

```
┌─────────────────────────────────────┐
│                 CPU                  │
│  ┌──────────┐  ┌──────────────────┐  │
│  │  运算器   │  │    控制器(CU)    │  │
│  │ (ALU+    │  │  (硬布线/微程序)  │  │
│  │  寄存器) │  │                  │  │
│  └──────────┘  └──────────────────┘  │
│  ┌──────────────────────────────────┐│
│  │          中断系统                ││
│  └──────────────────────────────────┘│
└─────────────────────────────────────┘
```

| 部件 | 组成 | 功能 |
|------|------|------|
| 运算器 | ALU + 通用寄存器 + 状态寄存器(PSW) | 执行算术逻辑运算 |
| 控制器(CU) | 指令寄存器(IR) + 程序计数器(PC) + 操作控制器 | 产生控制信号 |
| 中断系统 | 中断逻辑 | 处理中断请求 |

### 2.2 关键寄存器

| 寄存器 | 缩写 | 功能 |
|--------|------|------|
| 程序计数器 | PC | 存放下一条指令地址 |
| 指令寄存器 | IR | 存放当前执行的指令 |
| 存储器数据寄存器 | MDR | 暂存从主存读出/写入的数据 |
| 存储器地址寄存器 | MAR | 存放要访问的主存地址 |
| 累加器 | ACC | 暂存 ALU 运算中间结果 |
| 程序状态字 | PSW | 存放标志位（OF/CF/SF/ZF） |

> **操作元件 vs 状态元件**：
> - **操作元件**（组合逻辑）：数据通路中的多路选择器、ALU 等，无状态，输出随输入变化
> - **状态元件**（时序逻辑）：寄存器、PC、IR 等，有状态，在时钟边沿更新

## 三、数据通路

### 3.1 指令执行过程

```
取指 → 译码 → 执行 → 访存 → 写回
```

| 阶段 | 操作 | 关键控制 |
|------|------|---------|
| 取指 | PC → MAR → 主存 → MDR → IR | MemRead, IRWrite |
| 译码 | IR 操作码 → 控制信号 | OpCtrl |
| 执行 | ALU 运算（不同指令不同操作） | ALUCtrl |
| 访存 | lw: 主存→MDR→寄存器；sw: 寄存器→MDR→主存 | MemRead/MemWrite |
| 写回 | ALU 结果 → 寄存器（R型、lw） | RegWrite |
| PC 更新 | PC = PC + 4 或跳转目标 | PCSource |

### 3.2 数据通路示例（MIPS 五级流水线）

```
取指(IF)    译码(ID)     执行(EX)    访存(MEM)   写回(WB)
PC → IM     RF → 读      ALU 运算    DM → 访存   RF → 写
PC+4 → PC   Ext → 扩展   分支判断    数据返回    写回寄存器
            控制译码
```

**关键数据通路元件**：
- **指令存储器(IM)**：取指阶段读取指令
- **寄存器堆(RF)**：译码阶段读源操作数，写回阶段写结果
- **ALU**：执行算术逻辑运算
- **数据存储器(DM)**：访存阶段读写数据
- **扩展器(Ext)**：将立即数扩展为 32 位

## 四、控制器

### 4.1 硬布线控制器（组合逻辑）

**原理**：用组合逻辑电路直接产生控制信号

```
        ┌─────────────┐
IR ────→│             │
       │  组合逻辑    │──→ 控制信号
时钟 ─→│  电路        │
       │             │
状态 ─→│             │
        └─────────────┘
```

**特点**：
- 速度快（纯硬件，无访存）
- 设计复杂，修改困难
- RISC 常用
- 指令系统固定后难以扩展

### 4.2 微程序控制器（存储逻辑）

**原理**：每条机器指令对应一段微程序，微程序由微指令组成

```
机器指令 → 微程序地址 → 取微指令 → 产生微命令 → 执行
```

| 概念 | 说明 |
|------|------|
| 微命令 | 控制信号的最小单位（如 MemRead） |
| 微操作 | 由微命令控制的操作 |
| 微指令 | 若干微命令的集合，存于控制存储器(CM) |
| 微程序 | 若干微指令的序列，对应一条机器指令 |
| 微地址 | 微指令在控制存储器中的地址 |

**微指令格式**：

```
┌────────────────────┬──────────────┐
│  操作控制字段       │  下址字段    │
│ （产生微命令）      │ （下条微指令地址）│
└────────────────────┴──────────────┘
```

**微指令编码方式**：

| 方式 | 说明 | 优缺点 |
|------|------|--------|
| 直接编码 | 每位对应一个微命令 | 简单，但微指令字过长 |
| 字段直接编码 | 分组，每组互斥性微命令 | 缩短字长，需译码 |
| 字段间接编码 | 一个字段的编码需另一字段解释 | 进一步缩短 |

### 4.3 硬布线 vs 微程序

| 特性 | 硬布线 | 微程序 |
|------|--------|--------|
| 实现方式 | 组合逻辑电路 | 控制存储器(CM) |
| 速度 | 快 | 慢（需访CM） |
| 规整性 | 差 | 好 |
| 修改/扩展 | 困难 | 容易 |
| 适用 | RISC | CISC |

## 五、单周期与多周期 CPU

### 5.1 单周期 CPU

- **所有指令在一个时钟周期内完成**
- CPI = 1
- 时钟周期 = 最长指令的执行时间（通常是 lw）
- 效率低：短指令也要等满一个周期

$$T_{\text{单周期}} = \max(T_{\text{lw}}, T_{\text{sw}}, T_{\text{R型}}, \ldots)$$

### 5.2 多周期 CPU

- 每条指令分多个周期完成
- CPI 因指令而异
- 时钟周期 = 最长阶段的时间
- 效率较高：每条指令用恰好够的周期数

$$\text{CPI}_{\text{多周期}} = \sum_{i} \left( \text{CPI}_i \times \frac{C_i}{\text{总指令数}} \right)$$

### 5.3 比较

| 特性 | 单周期 | 多周期 |
|------|--------|--------|
| CPI | 固定 = 1 | 因指令而异 |
| 时钟周期 | 最长指令时间 | 最长阶段时间 |
| 硬件复用 | 否（每个阶段独立部件） | 是（可复用部件） |
| 效率 | 低 | 较高 |

## 六、流水线技术

### 6.1 五级流水线

```
IF → ID → EX → MEM → WB

指令1:  IF | ID | EX | MEM | WB
指令2:      IF | ID | EX  | MEM | WB
指令3:          IF | ID  | EX  | MEM | WB
```

理想情况下，每周期完成 1 条指令，CPI = 1。

### 6.2 三种冒险

#### 结构冒险（资源冲突）

**原因**：多条指令同时使用同一硬件资源
**解决**：
- 指令存储器和数据存储器分离（Harvard 结构）
- 寄存器堆读口和写口分离

#### 数据冒险（数据相关）

**原因**：后续指令需要前面指令的运算结果，但前面指令尚未写回

| 类型 | 说明 | 例子 |
|------|------|------|
| RAW（写后读） | 最常见，B 需要 A 的写结果 | add → sub（使用 add 结果） |
| WAW（写后写） | 两条指令写同一寄存器 | 较少见 |
| WAR（读后写） | B 先读再被 A 写 | 较少见 |

**解决方案**：

1. **转发（前推/旁路）**：将 EX 阶段的结果直接转发给后续指令，不等写回
   - EX/MEM → EX 输入（上一条指令的结果）
   - MEM/WB → EX 输入（两条前的指令结果）

2. **停顿（气泡）**：插入空周期等待数据就绪
   - Load-Use 冒险：lw 后紧跟使用该数据的指令，**必须停顿 1 个周期**（无法完全用转发解决）

```
add $1, $2, $3    IF ID EX  MEM WB
sub $4, $1, $5       IF ID  →  EX  MEM WB
                          停顿
（转发解决：EX/MEM 寄存器 → ALU 输入）

lw  $1, 0($2)
add $3, $1, $4    IF ID -- EX MEM WB
                      停顿（Load-Use 冒险，必须停 1 周期）
```

#### 控制冒险（分支冒险）

**原因**：分支指令改变 PC 值，但结果在 EX/MEM 阶段才确定

**解决方案**：

1. **分支预测**：
   - 静态预测：总是预测不跳转（或总是跳转）
   - 动态预测：根据历史记录预测（2-bit 预测器）

2. **延迟转移**：分支指令后的一条指令总是执行（延迟槽）

3. **提前判断**：将分支判断提前到 ID 阶段（减少停顿周期）

### 6.3 CPI 计算

$$\boxed{\text{CPI}_{\text{流水线}} = \text{理想CPI} + \text{结构冒险停顿} + \text{数据冒险停顿} + \text{控制冒险停顿}}$$

理想 CPI = 1，有冒险时 CPI > 1。

**典型计算模板**：

```
【题目】某流水线理想 CPI=1，
数据冒险导致 30% 指令停顿 1 周期，
分支占 20%，每次分支预测错误停顿 2 周期，错误率 25%。

数据冒险停顿 = 0.30 × 1 = 0.30
控制冒险停顿 = 0.20 × 0.25 × 2 = 0.10
CPI = 1 + 0.30 + 0.10 = 1.40
```

### 6.4 流水线加速比

$$\text{加速比} = \frac{\text{非流水线时间}}{\text{流水线时间}} = \frac{n \times k}{n + k - 1} \approx k \quad (n \gg k)$$

其中 $n$ 为指令数，$k$ 为流水线级数。

## 七、控制信号取值表

### 7.1 典型 MIPS 控制信号（五级流水线）

| 信号 | R型（add） | I型（addi） | lw | sw | beq |
|------|:--------:|:----------:|:--:|:--:|:---:|
| RegDst | 1（rd） | 0（rt） | 0（rt） | × | × |
| RegWrite | 1 | 1 | 1 | 0 | 0 |
| ALUSrc | 0（rt） | 1（imm） | 1（imm） | 1（imm） | 0（rt） |
| ALUOp | 10（运算） | 00（加） | 00（加） | 00（加） | 01（减） |
| MemRead | 0 | 0 | 1 | 0 | 0 |
| MemWrite | 0 | 0 | 0 | 1 | 0 |
| MemtoReg | 0（ALU） | 0（ALU） | 1（MEM） | × | × |
| PCSrc | 0 | 0 | 0 | 0 | 1（等） |
| MemtoReg | 0 | 0 | 1 | — | — |

**信号含义**：

| 信号 | 功能 | 取值说明 |
|------|------|---------|
| RegDst | 写寄存器选择 | 1→rd(R型), 0→rt(I型/lw) |
| RegWrite | 是否写寄存器 | 1→写, 0→不写 |
| ALUSrc | ALU 第二操作数来源 | 0→寄存器, 1→立即数 |
| ALUOp | ALU 操作类型 | 00→加, 01→减, 10→R型功能码 |
| MemRead | 读存储器 | 1→读, 0→不读 |
| MemWrite | 写存储器 | 1→写, 0→不写 |
| MemtoReg | 写回数据来源 | 0→ALU结果, 1→存储器数据 |
| PCSrc | PC 来源 | 0→PC+4, 1→分支目标 |

### 7.2 典型分析题

```
【题目】给定数据通路图和指令 add $t0, $s1, $s2，
描述数据流动路径并确定控制信号值。

数据流动：
1. IF: PC → IM → 指令取出 → IR
   PC = PC + 4

2. ID: IR[rs=$s1] → RF Read Port1 → $s1 值
   IR[rt=$s2] → RF Read Port2 → $s2 值
   IR[rd=$t0] → 留待写回用

3. EX: $s1 → ALU 输入A
   $s2 → ALU 输入B（ALUSrc=0）
   ALU 操作 = 加（ALUOp=10，由 funct 字段决定）
   结果 = $s1 + $s2

4. MEM: 无操作（MemRead=0, MemWrite=0）

5. WB: ALU 结果 → RF Write Port → $t0（RegWrite=1, MemtoReg=0）

控制信号：
  RegDst=1, RegWrite=1, ALUSrc=0, ALUOp=10
  MemRead=0, MemWrite=0, MemtoReg=0, PCSrc=0
```

## 八、典型分析题模板

### 给定指令，画数据通路 + 确定控制信号

```
第 1 步：识别指令类型
  - R型 / I型 / lw / sw / beq / j

第 2 步：确定数据流动路径
  IF → ID → EX → MEM → WB
  逐级描述数据从哪个元件流向哪个元件

第 3 步：确定控制信号
  对照控制信号取值表填写各信号值

第 4 步：判断是否有冒险
  - 数据冒险：是否使用了前一条指令的结果？→ 转发/停顿
  - 控制冒险：是否是分支指令？→ 预测/停顿

第 5 步：计算 CPI（如要求）
  CPI = 1 + 冒险停顿周期数
```

## 九、易错点清单

| # | 易错点 | 正确理解 |
|---|--------|---------|
| 1 | 单周期 CPU CPI < 1 | 错！单周期 CPI = 1，每个周期完成一条指令 |
| 2 | 多周期 CPU 时钟周期 = 最长指令时间 | 错！多周期时钟周期 = 最长**阶段**时间，每条指令用不同周期数 |
| 3 | 流水线理想 CPI = 0 | 错！理想 CPI = 1（每周期完成 1 条，但仍需 1 个周期） |
| 4 | 数据冒险都可转发解决 | 错！Load-Use 冒险**必须停顿 1 周期**，转发无法完全解决 |
| 5 | WAW 冒险最常见 | 错！RAW（写后读）最常见 |
| 6 | 转发从 WB 阶段到 EX | 转发可从 EX/MEM 或 MEM/WB 阶段直接到 EX 输入 |
| 7 | 微程序控制器比硬布线快 | 错！微程序需访控制存储器(CM)，比硬布线**慢** |
| 8 | 所有指令都经过 MEM 阶段 | 流水线中所有指令经过所有阶段（保持流水完整），但 MEM 阶段非访存指令不做操作 |
| 9 | PC 更新在取指阶段 | PC + 4 在 IF 阶段计算，但实际更新可能在不同位置 |
| 10 | 分支预测错误只需停 1 周期 | 取决于分支判断在哪个阶段。若在 EX 判断，错误需停 3 周期；若在 ID 判断，停 1 周期 |
| 11 | 结构冒险无法解决 | 可解决：分离 IM/DM、分离读写口 |
| 12 | 延迟转移 = 分支预测 | 不同！延迟转移是让分支后一条指令总是执行，分支预测是预测跳转方向 |
| 13 | ALUSrc=1 表示用寄存器 | 错！ALUSrc=1 表示用**立即数**，ALUSrc=0 表示用寄存器 |
| 14 | MemtoReg=1 写回 ALU 结果 | 错！MemtoReg=1 写回**存储器数据**，MemtoReg=0 写回 ALU 结果 |
| 15 | 微指令 = 机器指令 | 错！微指令是微程序的最小单位，一条机器指令由多条微指令组成 |

## 🧠 思考模式

**遇到这类题，第一反应应该是：**

1. 数据通路分析题（44 题）：先认指令类型（R 型 / I 型 / lw / sw / beq）→ 按 IF→ID→EX→MEM→WB 五阶段逐段描述数据流动（数据从哪个元件出发、经哪个元件、到哪个元件）→ 对照控制信号表逐个填值（RegDst / RegWrite / ALUSrc / ALUOp / MemRead / MemWrite / MemtoReg / PCSrc）→ 最后补一笔冒险分析
2. 流水线冒险题：先画五段时空图 → 判断冒险类型（结构 = 抢资源、数据 = RAW 相关、控制 = 分支）→ 数据冒险先试转发（EX/MEM、MEM/WB 直送 EX 输入），遇到 **Load-Use 必须停顿 1 周期** → 分支题先确认判断阶段：ID 阶段判断错则停 1 周期，EX 阶段判断错则停 3 周期
3. CPI 计算题：CPI = 1 + 各类冒险停顿之和，每项 = 发生概率 × 停顿周期数；算完 CPI 可回代概述章公式求执行时间——这类题往往是两章知识的接力

**知识串联提示：**
- 与其他板块的关联：IF 阶段取指与 MEM 阶段访存直接调用存储系统的 Cache 查找流程；指令的寻址方式（指令板块）决定 EX 阶段 ALUSrc 的取值与有效地址的计算方式；中断系统承接总线 IO 板块的 I/O 中断与存储板块的缺页中断（都打断指令流、走隐指令流程）；流水线 CPI 与概述章 CPU 执行时间公式首尾呼应
- 容易混淆的概念对比：单周期 vs 多周期 vs 流水线（时钟周期取最长指令 / 最长阶段 / 最长阶段，CPI 为 1 / 可变 / 理想 1）；转发 vs 停顿（多数数据冒险可转发，Load-Use 必须停顿）；微程序 vs 硬布线（存储逻辑、慢而规整 vs 组合逻辑、快而难改）；微命令→微指令→微程序→机器指令的四级嵌套关系（一条机器指令 = 一段微程序 = 若干微指令 = 一批微命令）
