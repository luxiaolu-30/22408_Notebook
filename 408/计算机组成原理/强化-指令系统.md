# 计算机组成原理 强化 · 指令系统

> **数据口径**：2016-2025 近 10 年大题统计。计组大题为 43-44 题（22 分）。
> **44 题大题约 8/10 年考**，常与数据通路/CPU 结合出题，考查汇编代码与寻址方式。

> **本板块串联**：指令系统（ISA）是软件与硬件的契约——上承编译器（高级语言翻译成指令），下启 CPU（指令如何在数据通路中执行）；44 题的汇编分析题正是本章与 CPU 板块的交叉点。

## 🧭 知识主线

本章的主线是：**指令是软件与硬件的契约**——软件看到的是"可用的指令集合"，硬件看到的是"必须实现的功能规范"，全章内容就是这份契约的三个部分。契约的**文本格式**是指令格式：操作码回答"干什么"，地址码回答"对谁干"，扩展操作码用可变长编码在固定字长内塞下更多指令（每级留"全 1"作扩展标志）。契约的**寻址条款**是寻址方式：立即/直接/间接/寄存器/基址/变址/相对，全部在回答同一个问题——"如何从形式地址 A 找到真正的操作数 EA"，10/10 必考的 EA 计算就是按契约查表。契约的**两种文风**是 CISC 与 RISC：变长 vs 定长、多种访存 vs 仅 Load/Store、微程序 vs 硬布线——RISC 的两条铁律（定长指令、仅 Load/Store 访存）正是为流水线而生。近年 44 题的汇编分析题（C 代码 ↔ MIPS 汇编互译）本质是让你**翻译这份契约**：看到 `sll $t2,$t1,2` 立刻反应"int 数组下标 ×4"，看到 `lw 0($t3)` 立刻反应"寄存器间接寻址"，而翻译用的字典只有一本——寻址方式表。

## 二、指令格式

### 2.1 指令的基本结构

```
┌──────────────────────────────────┐
│  操作码（Opcode）  │  地址码（Operand）  │
└──────────────────────────────────┘
```

- **操作码**：指出指令执行什么操作（加、减、访存、跳转等）
- **地址码**：给出操作数地址或操作数本身

### 2.2 按地址码个数分类

| 类型 | 格式 | 操作 | 访存次数 | 说明 |
|------|------|------|:--------:|------|
| 零地址 | OP | OP | 0 | 无操作数（停机、NOP、堆栈运算） |
| 一地址 | OP A1 | ACC ← (ACC) OP (A1) | 2 | 需 ACC 隐含参与 |
| 二地址 | OP A1 A2 | (A1) ← (A1) OP (A2) | 3~4 | 两个操作数 + 结果 |
| 三地址 | OP A1 A2 A3 | (A3) ← (A1) OP (A2) | 4 | 操作数 + 结果地址 |

**访存次数计算**（含取指令）：

| 类型 | 取指 | 取操作数 | 写回 | 总访存 |
|------|:----:|:--------:|:----:|:------:|
| 零地址 | 1 | 0 | 0 | 1 |
| 一地址 | 1 | 1（取A1） | 1（写回ACC） | 3 |
| 二地址 | 1 | 2（取A1、A2） | 1（写回A1） | 4 |
| 三地址 | 1 | 2（取A1、A2） | 1（写回A3） | 4 |

### 2.3 扩展操作码

**核心思想**：操作码不固定长度，通过地址码位数的变化来扩展操作码位数。

**设计规则**：
- 短地址码 → 长操作码（地址码少，操作码位数多）
- 长地址码 → 短操作码（地址码多，操作码位数少）
- 留一定编码模式作为扩展标志

**经典扩展设计模板**：

```
【题目】设指令字长 16 位，设计扩展操作码：
  - 三地址指令 15 条
  - 二地址指令 15 条  
  - 一地址指令 15 条
  - 零地址指令 16 条

三地址：操作码 4 位 + 三个地址各 4 位
  0000~1110 → 15 条三地址（1111 留作扩展）
  格式：OP(4) A1(4) A2(4) A3(4)

二地址：操作码 8 位 + 两个地址各 4 位
  1111 0000~1111 1110 → 15 条二地址（1111 1111 留作扩展）
  格式：OP(8) A1(4) A2(4)

一地址：操作码 12 位 + 一个地址 4 位
  1111 1111 0000~1111 1111 1110 → 15 条一地址
  格式：OP(12) A1(4)

零地址：操作码 16 位
  1111 1111 1111 0000~1111 1111 1111 1111 → 16 条零地址
  格式：OP(16)
```

**扩展操作码计算公式**：

若操作码长度可扩展 $k$ 次，每次扩展增加 $m$ 位，则可表示的操作码数量：

$$N = \sum_{i=0}^{k} n_i \quad \text{其中 } n_i \text{ 为第 } i \text{ 级的操作码数量}$$

> **易错**：扩展操作码中，**不能把操作码全 1 再扩展**（无法区分）。需要保留一种模式作为"扩展标志"。

## 三、寻址方式（核心考点！）

### 3.1 寻址方式总表

| 寻址方式 | 有效地址 EA | 访存次数 | 特点 |
|---------|------------|:--------:|------|
| 立即寻址 | 操作数在指令中 | 0 | 速度最快，但操作数长度受限 |
| 直接寻址 | EA = A | 1 | 简单，但地址范围受指令字长限制 |
| 间接寻址 | EA = (A) | 2 | 扩大寻址范围，但访存多 |
| 寄存器寻址 | EA = Ri（操作数在Ri中） | 0 | 快，但寄存器数量有限 |
| 寄存器间接 | EA = (Ri) | 1 | 兼顾速度和寻址范围 |
| 基址寻址 | EA = (BR) + A | 1 | 适合多道程序重定位 |
| 变址寻址 | EA = (IX) + A | 1 | 适合数组/循环访问 |
| 相对寻址 | EA = (PC) + A | 1 | 适合转移指令（位置无关） |

> **注意**：上表访存次数**不含取指令**，仅指取操作数时的访存。

### 3.2 各寻址方式详解

#### 立即寻址
- 操作数直接编码在指令中（A 即为操作数）
- 不需要访存取操作数，速度最快
- 限制：操作数大小受指令地址码位数限制

#### 直接寻址
- EA = A，指令中的 A 即为操作数地址
- 访存 1 次取操作数

#### 间接寻址
- EA = (A)，A 指向的存储单元中存放操作数地址
- 需访存 2 次：第一次取地址，第二次取操作数
- 优点：扩大寻址范围

#### 寄存器寻址
- 操作数在寄存器中，EA = Ri
- 不访存，速度快

#### 寄存器间接寻址
- EA = (Ri)，寄存器中存放操作数地址
- 访存 1 次取操作数

#### 基址寻址
$$\boxed{EA = (BR) + A}$$
- BR 为基址寄存器，A 为形式地址（偏移量）
- BR 内容可变，A 不变 → 适合程序重定位
- 常用于多道程序设计

#### 变址寻址
$$\boxed{EA = (IX) + A}$$
- IX 为变址寄存器，A 为形式地址（基地址）
- A 不变，IX 内容可变 → 适合数组访问、循环
- 与基址的区别：**变址中 A 是基准、IX 是变量；基址中 BR 是基准、A 是变量**

#### 相对寻址
$$\boxed{EA = (PC) + A}$$
- A 为偏移量（通常用补码表示，可正可负）
- 适合转移指令，实现位置无关代码
- **注意**：PC 在取指后已 +1（指向下条指令），EA = 当前 PC 值 + A

### 3.3 典型计算题

```
【题目】某机器主存按字节编址，指令采用一地址格式，
寄存器 R1 内容为 1000H，主存 1000H 单元内容为 2000H，
2000H 单元内容为 3000H，3000H 单元内容为 4000H，
PC 内容为 2000H。求以下寻址方式下的有效地址 EA：

(1) 直接寻址，指令地址码 A = 1000H
    EA = A = 1000H

(2) 间接寻址，指令地址码 A = 1000H
    EA = (A) = (1000H) = 2000H

(3) 寄存器间接寻址，R1 = 1000H
    EA = (R1) = (1000H) = 2000H

(4) 基址寻址，BR = 2000H，A = 1000H
    EA = (BR) + A = 2000H + 1000H = 3000H

(5) 变址寻址，IX = 2000H，A = 1000H
    EA = (IX) + A = 2000H + 1000H = 3000H

(6) 相对寻址，PC = 2000H，A = +1000H
    EA = (PC) + A = 2000H + 1000H = 3000H
    （注意：若 PC 已指向下条指令，需先确定下条指令地址）
```

### 3.4 指令寻址 vs 数据寻址

| 类型 | 说明 |
|------|------|
| 指令寻址 | 确定下一条指令的地址（顺序/跳跃） |
| 数据寻址 | 确定操作数的地址（本节所述各种方式） |

> **易错**：题目问"指令寻址方式"指下条指令的地址确定方式（PC+1 或跳转），问"寻址方式"通常指数据寻址。

## 四、CISC vs RISC

| 特性 | CISC（复杂指令集） | RISC（精简指令集） |
|------|-------------------|-------------------|
| 指令数量 | 多（100+） | 少（<100） |
| 指令长度 | 可变 | **固定** |
| 指令格式 | 多种 | 少而规整 |
| 寻址方式 | 多种 | 少（寄存器-寄存器为主） |
| 访存指令 | 多种 | 只有 Load/Store 访存 |
| 寄存器 | 较少 | 较多 |
| 执行时间 | 不固定 | 大多数 1 个周期 |
| 流水线 | 难以实现 | 容易实现 |
| 控制方式 | 微程序为主 | 硬布线为主 |
| 代表 | x86 | MIPS、ARM、RISC-V |

> **高频考点**：
> - RISC 只有 **Load/Store** 指令访问内存，其他指令在寄存器间操作
> - RISC 指令定长、格式规整，便于流水线实现
> - RISC 使用大量寄存器，减少访存

## 五、汇编代码分析（近年常考）

### 5.1 C 代码与汇编的对应关系

近年 44 题常给出一段 C 代码和对应的机器级汇编，要求分析寻址方式、寄存器使用等。

**常见模式**：

```c
// C 代码
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += a[i];
}
```

```asm
; 对应汇编（MIPS 风格）
    addi $t0, $zero, 0    ; sum = 0
    addi $t1, $zero, 0    ; i = 0
loop:
    sll  $t2, $t1, 2      ; i * 4（int 4字节）
    add  $t3, $a0, $t2    ; &a[i] = base + i*4
    lw   $t4, 0($t3)     ; 取 a[i]
    add  $t0, $t0, $t4    ; sum += a[i]
    addi $t1, $t1, 1     ; i++
    bne  $t1, $a1, loop  ; if i != n goto loop
```

**分析要点**：
- `sll` 左移 2 位 = 乘以 4（int 类型偏移）
- `add $t3, $a0, $t2` = 基址 + 变址（变址寻址）
- `lw 0($t3)` = 寄存器间接寻址
- `bne` = 相对寻址（PC 相对跳转）

### 5.2 常考分析角度

1. **寻址方式识别**：给定汇编指令，指出使用了什么寻址方式
2. **寄存器用途**：哪些是通用寄存器，哪些是指针/计数器
3. **偏移量计算**：数组元素访问的偏移 = 索引 × 元素大小
4. **字节编址 vs 字编址**：注意地址增量是否需要 ×4

## 六、典型计算题

### 6.1 扩展操作码设计

```
【题目】某机指令字长 16 位，每个地址码 4 位，
采用扩展操作码。设计：
(1) 15 条三地址指令
(2) 14 条二地址指令
(3) 31 条一地址指令
(4) 16 条零地址指令

解答：

三地址：OP(4位) + A1(4) + A2(4) + A3(4)
  操作码：0000~1110（15条）
  1111 留作扩展

二地址：OP(8位) + A1(4) + A2(4)
  操作码：1111 0000~1111 1101（14条）
  1111 1110 和 1111 1111 留作扩展

一地址：OP(12位) + A1(4)
  从 1111 1110 开始扩展：
  1111 1110 0000~1111 1110 1110（15条）
  从 1111 1111 开始扩展：
  1111 1111 0000~1111 1111 1110（15条）
  共 30 + 1 = 31 条
  1111 1111 1111 留作扩展

零地址：OP(16位)
  1111 1111 1111 0000~1111 1111 1111 1111（16条）
```

## 七、易错点清单

| # | 易错点 | 正确理解 |
|---|--------|---------|
| 1 | 基址寻址和变址寻址一样 | 不同！基址：BR 是基准、A 是变量；变址：A 是基准、IX 是变量 |
| 2 | 相对寻址 EA = PC + A（取指前PC） | PC 在取指后已更新（+1），EA = 更新后的 PC + A |
| 3 | 间接寻址访存 1 次 | 错！间接寻址访存 **2 次**：先取地址，再取操作数 |
| 4 | 立即寻址需要访存 | 错！立即数在指令中，**不访存**，速度最快 |
| 5 | 零地址指令一定不访存 | 大多数不访存，但堆栈指令需要访存（push/pop） |
| 6 | 扩展操作码可任意编码 | 需保留扩展标志，不能全 1 再扩展 |
| 7 | RISC 指令长度可变 | 错！RISC 指令**定长**，CISC 才可变长 |
| 8 | RISC 有访存运算指令 | 错！RISC 只有 **Load/Store** 访存，运算在寄存器间 |
| 9 | 访存次数 = 取操作数次数 | 需加上取指令 1 次（有些题目要求总访存次数含取指） |
| 10 | 变址寄存器内容不变 | 错！变址寄存器 IX 内容**可变**（循环中递增） |
| 11 | 基址寄存器由用户指定 | 基址寄存器通常由**操作系统**管理（重定位），用户不可改 |
| 12 | 寄存器寻址 = 寄存器间接寻址 | 错！寄存器寻址操作数在寄存器中；寄存器间接寻址操作数在内存中（地址在寄存器中） |
| 13 | 一地址指令只有 1 个操作数 | 一地址指令有 **2 个操作数**：一个在 A1，另一个隐含在 ACC 中 |
| 14 | 扩展操作码各级条数随意 | 各级可用操作码数受上一级扩展标志限制，需精确计算 |

## 🧠 思考模式

**遇到这类题，第一反应应该是：**

1. EA 计算题：先认出寻址方式 → 写出对应公式（EA = A / (A) / (Ri) / (BR)+A / (IX)+A / (PC)+A）→ 按题目给的主存内容链条逐层代入 → 最后核对访存次数是否含取指的 1 次
2. 扩展操作码题：从操作码最短的三地址指令开始逐级设计，**每级必须留一个编码（通常"全 1"）作为下一级的扩展标志**，中间各级可用条数 = 该级编码数 − 1，只有最后一级可以全部用满
3. 汇编分析题：先定位两个角色——数组基地址寄存器与循环变量寄存器 → 偏移 = 下标 × 元素字节数（`sll` 移 2 位 = ×4，说明是 int）→ 对照寻址方式表逐条标注指令 → 转移指令按相对寻址处理（EA = 已更新的 PC + 偏移量）

**知识串联提示：**
- 与其他板块的关联：每条指令都要走 CPU 板块"取指→译码→执行→访存→写回"的数据通路，44 题常把指令格式与控制信号取值联合考查；相对寻址的 EA = (PC)+A 与 CPU 板块的 PC 更新、转移目标地址计算是同一件事；RISC"仅 Load/Store 访存"的原则直接决定流水线 MEM 阶段的分析方式；Load/Store 指令触发存储系统的 Cache 查找路径
- 容易混淆的概念对比：基址 vs 变址（基址：BR 是基准、A 是变量，面向 OS 重定位；变址：A 是基准、IX 是变量，面向数组/循环）；立即 vs 直接（A 是操作数本身 vs A 是操作数地址）；指令寻址 vs 数据寻址（下一条指令在哪 vs 操作数在哪）；一地址指令的操作数个数（2 个：A1 + 隐含的 ACC）
