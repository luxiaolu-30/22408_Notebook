# 计算机组成原理 强化 · 存储系统

> **数据口径**：2016-2025 近 10 年大题统计。计组大题为 43-44 题（22 分）。
> **43 题大题 10/10 全勤**——Cache + 虚拟存储器综合题，是计组大题的绝对核心。

> **本板块串联**：本章是"程序访问数据的一条完整路径"，也是 43 题大题的唯一主场（10/10 全勤）——向上承接指令系统的访存指令与 CPU 的 MEM 阶段，向下与操作系统的内存管理（页表/虚存）是同一件事的两个视角。

## 🧭 知识主线

不要把存储器分类、扩展、Cache、虚存当成四个孤立话题，它们共同回答一个问题：**CPU 取一个数据要走哪条路**。寄存器装不下整个程序，于是有了"寄存器→Cache→主存→辅存"的金字塔——层次结构存在的唯一理由是用局部性原理做"速度换容量"的交易，而"上层是下层的缓存"这个思想在三级缓存中反复出现：**Cache 是主存的缓存，TLB 是页表的缓存，主存（虚存视角下）是磁盘的缓存**。当一条访存指令执行时，路径是固定的：CPU 给出虚拟地址 → 按页大小拆出虚页号|页内偏移 → 查 TLB（快），未命中再查主存中的页表（慢），页表也缺则缺页中断调页 → 实页号拼页内偏移得物理地址 → 再按 Cache 参数拆 Tag|组号|块内偏移查 Cache → 命中取数、未命中访主存调块。43 题大题考的就是这条路径上的地址拆分与各级命中组合，而映射方式（直接/组相联/全相联）只是决定"地址拆成几段、各段多宽"的参数。

## 二、存储器层次结构

```
┌──────────┐  速度↑  成本↑  容量↓
│ 寄存器    │  ← 最快，CPU 内部
├──────────┤
│ Cache    │  ← 缓存热点数据
├──────────┤
│ 主存(内存)│  ← 存放运行中的程序
├──────────┤
│ 辅存(硬盘)│  ← 持久化存储
└──────────┘  速度↓  成本↓  容量↑
```

**核心思想**：利用**局部性原理**（时间局部性 + 空间局部性），用少量快速存储器达到接近快速存储器的速度、接近慢速存储器的容量。

## 三、SRAM vs DRAM

| 特性 | SRAM（静态） | DRAM（动态） |
|------|-------------|-------------|
| 存储原理 | 触发器 | 电容充放电 |
| 是否需刷新 | 不需要 | **需要定期刷新** |
| 速度 | 快 | 慢 |
| 成本 | 高 | 低 |
| 集成度 | 低 | 高 |
| 功耗 | 较高 | 较低 |
| 用途 | **Cache** | **主存** |

**刷新方式**：
- 集中刷新：在一个刷新周期内集中刷新所有行，有"死区"
- 分散刷新：每次读/写后刷新一行，无死区但影响速度
- 异步刷新：每隔一段时间刷新一行，死区分散

> **易错**：刷新是**按行**进行的，不是按位。

## 四、存储器扩展

### 4.1 三种扩展方式

| 方式 | 方法 | 说明 |
|------|------|------|
| 位扩展 | 增加数据位数 | 多片存储器地址线并联，数据线拼接 |
| 字扩展 | 增加存储字数 | 增加地址线，用片选信号选择不同芯片 |
| 字位扩展 | 同时增加字数和位数 | 先位扩展组成存储模块，再字扩展 |

### 4.2 字扩展的片选

- 用高位地址线通过**译码器**选择不同芯片
- 片选信号 CE 选中芯片后才能读/写

**地址计算模板**：

```
已知：16K×8 位的存储器，用 2K×4 位芯片扩展

位扩展：2 片 2K×4 → 2K×8（数据位 4→8）
字扩展：8 组 2K×8 → 16K×8（字数 2K→16K）
总芯片数 = 2 × 8 = 16 片

地址线：
  芯片内地址：11 位（2K = 2^11）
  片选地址：3 位（8 组 = 2^3，用 3-8 译码器）
  总地址线：14 位（16K = 2^14）
```

## 五、Cache（绝对核心！）

### 5.1 三种映射方式

#### 直接映射

$$\text{Cache 行号} = \text{主存块号} \bmod \text{Cache 总行数}$$

- 每个主存块**只能映射到唯一**的 Cache 行
- 地址结构：**Tag | 行号 | 块内偏移**

#### 全相联映射

- 每个主存块**可以映射到任意** Cache 行
- 地址结构：**Tag | 块内偏移**（无行号字段）

#### 组相联映射

$$\text{Cache 组号} = \text{主存块号} \bmod \text{Cache 总组数}$$

- 每个主存块映射到唯一组，组内任意行
- 地址结构：**Tag | 组号 | 块内偏移**

### 5.2 地址拆分公式

**通用框架**：给定主存地址位数 $A$、Cache 总容量 $C$、主存块大小 $B$、映射方式。

```
步骤 1：计算块内偏移位数
  块内偏移 = log₂(B)   （B 为主存块大小）

步骤 2：计算 Cache 总行数
  Cache 行数 = C / B

步骤 3：根据映射方式计算地址各字段

  ┌────────── 直接映射 ──────────┐
  │ Tag | 行号(log₂C/B) | 块内偏移 |
  └──────────────────────────────┘

  ┌────────── 全相联映射 ─────────┐
  │ Tag | 块内偏移                  │
  │ Tag = A - 块内偏移              │
  └──────────────────────────────┘

  ┌────────── 组相联映射 ─────────┐
  │ Tag | 组号(log₂(C/(B×路数))) | 块内偏移 |
  │ 组数 = Cache总行数 / 路数         │
  └──────────────────────────────┘
```

**组相联关键公式**：

$$\text{组数} = \frac{\text{Cache 总行数}}{\text{路数（way）}}$$

$$\text{组号位数} = \log_2(\text{组数})$$

$$\text{Tag 位数} = \text{主存地址位数} - \text{组号位数} - \text{块内偏移位数}$$

### 5.3 完整计算示例

```
【题目】主存地址 32 位，按字节编址，Cache 数据区 32KB，
        8 路组相联，主存块 64B。求各字段位数。

步骤 1：块内偏移
  块大小 64B → 块内偏移 = log₂(64) = 6 位

步骤 2：Cache 总行数
  Cache 总行数 = 32KB / 64B = 32768 / 64 = 512 行

步骤 3：组数（8 路组相联）
  组数 = 512 / 8 = 64 组
  组号位数 = log₂(64) = 6 位

步骤 4：Tag 位数
  Tag = 32 - 6(组号) - 6(块内偏移) = 20 位

地址结构：Tag(20) | 组号(6) | 块内偏移(6) = 32 位
```

### 5.4 替换算法

| 算法 | 规则 | 优点 | 缺点 |
|------|------|------|------|
| **LRU**（最近最少使用） | 替换最久未访问的行 | 命中率高，利用时间局部性 | 需计数器/栈，硬件开销大 |
| **FIFO**（先进先出） | 替换最早调入的行 | 实现简单 | 效果差，可能替换即将使用的行 |
| **随机** | 随机替换 | 硬件简单 | 命中率不稳定 |

> **组相联映射下**，直接映射无需替换算法（只有一行可选），组相联和全相联需要。

### 5.5 写策略

| 策略 | 操作 | 说明 |
|------|------|------|
| **全写法**（Write-Through） | Cache 和主存**同时写入** | 数据一致性好，但写速度慢 |
| **写回法**（Write-Back） | 只写 Cache，设置**脏位**，替换时才写回主存 | 速度快，但需维护一致性 |

**写未命中时的策略**：

| 策略 | 操作 | 说明 |
|------|------|------|
| **写分配**（Write-Allocate） | 先将块调入 Cache，再写入 | 常与写回法配合 |
| **不按写分配**（Not-Write-Allocate） | 直接写主存，不调入 Cache | 常与全写法配合 |

**经典搭配**：
- 全写法 + 不按写分配
- 写回法 + 写分配

### 5.6 命中率与平均访问时间

$$\text{命中率} = \frac{\text{命中次数}}{\text{总访问次数}}$$

$$\text{平均访问时间} = h \times t_{\text{cache}} + (1-h) \times t_{\text{主存}}$$

> 其中 $h$ 为命中率，$t_{\text{cache}}$ 为 Cache 访问时间，$t_{\text{主存}}$ 为未命中时访问主存时间。

**含 Cache + 主存的改进公式**（考虑 Cache 命中时也可能需要访问主存）：

$$t_a = h \times t_c + (1-h) \times (t_c + t_m)$$

## 六、虚拟存储器

### 6.1 三种管理方式

| 方式 | 特点 | 优点 | 缺点 |
|------|------|------|------|
| 页式 | 固定大小页 | 管理简单，无外碎片 | 有内碎片 |
| 段式 | 按逻辑分段 | 共享保护方便 | 有外碎片 |
| 段页式 | 先分段再分页 | 结合两者优点 | 管理复杂 |

### 6.2 虚拟地址 → 物理地址转换

**页式虚拟存储器**：

```
虚拟地址 = 虚页号(VPN) | 页内偏移(VPO)
                ↓
          查页表（Page Table）
                ↓
          虚页号 → 实页号(PFN)
                ↓
物理地址 = 实页号(PFN) | 页内偏移(PPO)

注意：页内偏移(VPO) = 页内偏移(PPO)，位数相同
```

**关键公式**：

$$\text{页内偏移位数} = \log_2(\text{页大小})$$

$$\text{虚页号位数} = \text{虚拟地址位数} - \text{页内偏移位数}$$

### 6.3 TLB（快表）

页表存放在主存中，每次地址转换需访问主存两次，TLB 用于加速。

**TLB 的映射方式**（与 Cache 类似）：

| 映射方式 | 查找方式 |
|---------|---------|
| 全相联 | 虚页号与所有 TLB 表项并行比较 |
| 组相联 | 虚页号分组后查找对应组 |

**TLB 地址拆分**：

```
虚拟地址 = TLB Tag | TLB 组号 | 页内偏移

例：虚拟地址 48 位，页大小 4KB，TLB 有 256 组，4 路组相联

页内偏移 = log₂(4096) = 12 位
TLB 组号 = log₂(256) = 8 位
TLB Tag = 48 - 12 - 8 = 28 位
```

### 6.4 二级页表地址转换

当虚拟地址空间极大时，页表本身占用内存过大，使用多级页表。

**二级页表**：

```
虚拟地址 = 一级页号 | 二级页号 | 页内偏移

转换过程：
  1. 用一级页号查一级页表 → 得到二级页表基址
  2. 用二级页号查二级页表 → 得到实页号
  3. 物理地址 = 实页号 | 页内偏移
```

**访存次数**：
- 无 TLB：3 次访存（一级页表 + 二级页表 + 目标数据）
- 有 TLB 且命中：1 次访存（直接得到物理地址，访问目标数据）

## 七、Cache + TLB + 虚存三合一综合题（核心！）

### 7.1 完整流程图

```
              ┌─────────────┐
              │  虚拟地址 VA  │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │ ① 查 TLB    │ ← 用 VPN/TLB组号 查找
              └──────┬──────┘
                     │
            ┌────────┴────────┐
            │命中              │未命中
            ▼                  ▼
    ┌───────────────┐  ┌───────────────┐
    │ 直接得到物理   │  │ ② 查页表      │ ← 访问主存中的页表
    │ 页号(PFN)     │  └───────┬───────┘
    └───────┬───────┘          │
            │          ┌───────┴───────┐
            │          │命中            │未命中(缺页)
            │          ▼                ▼
            │  ┌───────────────┐ ┌───────────────┐
            │  │ 得到物理页号   │ │ ③ 缺页中断     │
            │  │ (PFN)         │ │ 调入页面       │
            │  └───────┬───────┘ └───────┬───────┘
            │          │                 │
            │          ▼                 │
            │  ┌───────────────┐         │
            └─→│ 组装物理地址   │←────────┘
               │ PA=PFN|PPO    │
               └───────┬───────┘
                       │
                       ▼
               ┌───────────────┐
               │ ④ 查 Cache    │ ← 用 物理地址 查 Cache
               └───────┬───────┘
                       │
             ┌─────────┴─────────┐
             │命中                 │未命中
             ▼                     ▼
     ┌───────────────┐    ┌───────────────┐
     │ 返回 Cache 数据 │    │ ⑤ 访问主存    │
     │ 命中！        │    │ 取数据写入     │
     └───────────────┘    │ Cache 后返回  │
                          └───────────────┘
```

### 7.2 各级命中/未命中组合分析

| TLB | 页表 | Cache | 访存次数 | 说明 |
|:---:|:----:|:-----:|:--------:|------|
| 命中 | — | 命中 | 0 次额外访存 | 最快：TLB 给物理地址，Cache 直接命中 |
| 命中 | — | 未命中 | 1 次访存 | TLB 给物理地址，Cache 未命中需访主存 |
| 未命中 | 命中 | 命中 | 1 次访存 | 查页表访存 1 次，Cache 命中 |
| 未命中 | 命中 | 未命中 | 2 次访存 | 查页表 1 次 + 访主存数据 1 次 |
| 未命中 | 未命中 | — | 缺页中断 | 需要从磁盘调入页面，开销巨大 |

> **核心理解**：TLB 是页表的缓存，Cache 是主存的缓存。两者是不同层级的缓存机制。

### 7.3 近年趋势（2023、2025）

近年 43 题趋向于给定一个 C 程序中的数组访问（如 `d[0]`、`d[100]`），要求：
1. 计算虚拟地址及各字段拆分
2. 判断虚拟地址中哪些位可直接作为 Cache 索引
3. 计算 Cache 缺失率和平均访问时间
4. 分析数组跨页情况及缺页次数

**关键技巧**：用**物理地址查 Cache**，但虚拟地址中的**组号 + 块内偏移**部分若与物理地址对应位相同（即"物理索引=虚拟索引"），则可以**并行查找 TLB 和 Cache**。

**判定条件**：Cache 索引位 + 块内偏移位 ≤ 页内偏移位时，虚拟地址可直接用于 Cache 索引。

## 八、标准答题步骤模板

### 模板：Cache + 虚存综合题

```
第 1 步：地址拆分

  虚拟地址拆分：
    页内偏移位数 = log₂(页大小)
    虚页号位数 = 虚拟地址位数 - 页内偏移位数
    （若有 TLB：TLB 组号 = log₂(TLB组数)，TLB Tag = 虚页号 - 组号）

  Cache 地址拆分（物理地址）：
    块内偏移 = log₂(主存块大小)
    Cache 组号 = log₂(Cache总行数 / 路数)
    Tag = 物理地址位数 - 组号位数 - 块内偏移位数

第 2 步：查 TLB

  用虚拟地址的 TLB 组号和 Tag 查 TLB
  - 命中 → 直接获得实页号(PFN)，跳到第 4 步
  - 未命中 → 进入第 3 步

第 3 步：查页表

  用虚页号查页表
  - 命中（有效位=1）→ 获得实页号(PFN)，更新 TLB
  - 未命中（有效位=0）→ 缺页中断，OS 从磁盘调入

第 4 步：组装物理地址

  物理地址 = 实页号(PFN) | 页内偏移(PPO)

第 5 步：查 Cache

  用物理地址的 Cache 组号和 Tag 查 Cache
  - 命中 → 返回数据
  - 未命中 → 访问主存取数据，写入 Cache，返回数据

第 6 步：计算命中率/平均访问时间（如题目要求）

  命中率 = 命中次数 / 总访问次数
  平均访问时间 = h × t_cache + (1-h) × t_miss
```

### 完整计算示例

```
【题目】某计算机按字节编址，虚拟地址 32 位，页大小 4KB，
TLB 为 4 路组相联共 64 组。Cache 数据区 32KB，8 路组相联，
主存块 64B，物理地址 30 位。数组 d 为 int 类型（4字节），
d 的起始虚拟地址为 0x1000 0000，依次访问 d[0], d[1], ... d[255]。

--- 地址拆分 ---

虚拟地址（32位）：
  页内偏移 = log₂(4096) = 12 位
  虚页号 = 32 - 12 = 20 位
  TLB 组号 = log₂(64) = 6 位
  TLB Tag = 20 - 6 = 14 位
  → 虚拟地址：TLB Tag(14) | TLB组号(6) | 页内偏移(12)

物理地址（30位）：
  块内偏移 = log₂(64) = 6 位
  Cache 总行数 = 32KB / 64B = 512 行
  Cache 组数 = 512 / 8 = 64 组
  Cache 组号 = log₂(64) = 6 位
  Tag = 30 - 6 - 6 = 18 位
  → 物理地址：Tag(18) | Cache组号(6) | 块内偏移(6)

--- 关键判定 ---

  Cache 组号 + 块内偏移 = 6 + 6 = 12 位
  页内偏移 = 12 位
  12 ≤ 12 → 虚拟地址可直接作为 Cache 索引（VIPT）

--- d[0] 地址计算 ---

  d[0] 虚拟地址 = 0x1000 0000
  二进制：0001 0000 0000 0000 0000 0000 0000 0000
  拆分：TLB Tag = 0001 0000 0000 00 = 0x0400
        TLB 组号 = 00 0000 = 0
        页内偏移 = 0000 0000 0000 = 0x000

  d[0] 在页内偏移 0，即该页的第一个位置。

--- d[100] 地址计算 ---

  d[100] 虚拟地址 = 0x1000 0000 + 100×4 = 0x1000 0190
  二进制：0001 0000 0000 0000 0001 1001 0000 0000
  拆分：页内偏移 = 0000 0001 1001 0000 0000 ... 不对
  
  实际计算：
  0x190 = 0001 1001 0000
  页内偏移(12位) = 0000 0001 1001 = 0x019 ... 

  正确计算：100×4 = 400 = 0x190
  虚拟地址 = 0x1000 0000 + 0x190 = 0x1000 0190
  
  页内偏移 = 0x190 = 400 字节 → 块内偏移 = 400 mod 64 = 16
  所在主存块（页内）= 400 / 64 = 6（第 6 块）

--- 缺页分析 ---

  数组 d 共 256 个 int = 256×4 = 1024 字节
  页大小 4KB = 4096 字节 → d 全在一页内
  所以 d[0]~d[255] 全在虚拟地址 0x1000 0000 所在页

--- Cache 命中率 ---

  主存块 64B，每个块存放 64/4 = 16 个 int
  d 共 256 个 int → 分布在 256/16 = 16 个主存块
  
  每个块第一次访问：Cache 未命中（从主存调入）
  同一块的后续 15 次访问：Cache 命中
  
  命中率 = (256 - 16) / 256 = 240/256 = 93.75%

--- 平均访问时间 ---

  假设 Cache 命中时间 = t_c，未命中时间 = t_m
  
  平均访问时间 = 93.75% × t_c + 6.25% × t_m
```

## 九、易错点清单

| # | 易错点 | 正确理解 |
|---|--------|---------|
| 1 | 组数 = 路数 | 错！组数 = Cache 总行数 / 路数。8 路组相联不等于 8 组 |
| 2 | Tag 位数 = 虚页号位数 | 错！Tag = 虚页号位数 - 组号位数（组相联）或 Tag = 虚页号（全相联） |
| 3 | Cache 用虚拟地址查找 | **VIPT** 特殊情况下可以，但标准情况用**物理地址**查 Cache |
| 4 | TLB 是 Cache 的缓存 | 错！TLB 是**页表**的缓存，Cache 是**主存**的缓存 |
| 5 | 直接映射需要替换算法 | 错！直接映射只有一行可选，无需替换算法 |
| 6 | 全写法用于 Cache→主存 | 对，但全写法 + 写分配是常见搭配？错！全写法常配**不按写分配** |
| 7 | 命中率 = 命中行数/总行数 | 错！命中率 = 命中**次数** / 总访问**次数** |
| 8 | 刷新是按列进行 | 错！刷新是**按行**进行的 |
| 9 | SRAM 用于主存 | 错！SRAM 用于 **Cache**，DRAM 用于**主存** |
| 10 | 虚拟地址所有位都参与查 Cache | 只有当 Cache 索引+偏移 ≤ 页内偏移时，虚拟地址可直接查 Cache（VIPT） |
| 11 | TLB 未命中 = 缺页 | 错！TLB 未命中只是要查页表，页表可能命中（不缺页） |
| 12 | 缺页后不需要查 Cache | 缺页中断后 OS 调入页面，之后需重新执行指令（重新查 TLB→Cache） |
| 13 | 块内偏移 = 块号偏移 | 块内偏移是块内的字节偏移（log₂(块大小)位），不是块号 |
| 14 | 二级页表查一次即可 | 二级页表需要查**两次**页表（一级+二级），TLB 命中则只需一次 |
| 15 | 平均访问时间公式分母 | $t = h \cdot t_c + (1-h) \cdot t_m$，注意 $t_m$ 是**未命中的总时间**（可能含 $t_c$） |

## 🧠 思考模式

**遇到 43 题（Cache + TLB + 虚存综合大题），第一反应应该是：不要急着算，先拆地址，按固定流程走——这是全卷最稳定的送分大题。**

1. **拿到虚拟地址 → 按位数拆字段**
   - 页内偏移 = log₂(页大小)——虚拟地址和物理地址共用，地址转换不改写这一段
   - 虚页号 = 虚拟地址位数 − 页内偏移位数
   - 若给 TLB 参数：TLB 组号 = log₂(TLB 组数)，TLB Tag = 虚页号位数 − TLB 组号位数
   - 物理地址侧：块内偏移 = log₂(主存块大小)；Cache 总行数 = Cache 容量 / 块大小；组号 = log₂(总行数 / 路数)；Tag = 物理地址位数 − 组号位数 − 块内偏移位数
2. **查 TLB**：用 TLB Tag + 组号查找。命中 → 直接得实页号，跳到第 4 步；未命中 → 转查页表。注意 **TLB 未命中 ≠ 缺页**，只是慢一步查页表
3. **查页表**：用虚页号查。有效位 = 1 → 得实页号并更新 TLB；有效位 = 0 → 缺页中断，OS 从磁盘调入页面，之后**重新执行该访存指令**（重新走 TLB→Cache 流程）
4. **拼物理地址**：物理地址 = 实页号 | 页内偏移——页内偏移原样照抄，只换高位
5. **拆 Cache 字段 → 查 Cache**：用物理地址的组号 + Tag 查。命中 → 返回数据；未命中 → 访问主存取整块写入 Cache 再返回
6. **题目追问访存次数 / 命中率 / 平均时间时**：
   - 各级命中组合查表：TLB 命中 + Cache 命中 = 0 次额外访存；TLB 未命中 + 页表命中 + Cache 命中 = 1 次；TLB 未命中 + 页表命中 + Cache 未命中 = 2 次；页表未命中 = 缺页（代价按磁盘访问算）
   - 数组顺序访问题：每个主存块首访缺失、同块后续访问命中（如每块 64B 存 16 个 int → 命中率 15/16），再套平均访问时间公式
   - VIPT 判定：Cache 组号位数 + 块内偏移位数 ≤ 页内偏移位数时，虚拟地址可直接索引 Cache（TLB 与 Cache 并行查找）

**知识串联提示：**
- 与其他板块的关联：虚存机制与操作系统内存管理的页表、缺页调度是**同一件事的两个视角**（计组看地址转换的硬件路径，OS 看页面替换策略）；CPU 板块的 MEM 阶段就是本章的 Cache 查找流程，lw/sw 的数据通路分析必然用到本章地址拆分；指令系统的 Load/Store 指令是这条路径的触发入口；缺页调入的磁盘传输与总线 IO 板块的 DMA 方式衔接
- 容易混淆的概念对比：TLB 是**页表**的缓存 vs Cache 是**主存**的缓存；TLB 未命中 vs 缺页（查页表即可 vs 要访磁盘）；组数 vs 路数（组数 = 总行数 / 路数，8 路组相联 ≠ 8 组）；物理地址查 Cache vs VIPT（标准情况用物理地址，满足位数条件时可用虚拟索引并行查找）；写策略搭配（全写法 + 不按写分配 vs 写回法 + 写分配）
