# 计算机组成原理 强化 · 总线与 I/O 系统

> **数据口径**：2016-2025 近 10 年大题统计。计组大题为 43-44 题（22 分）。
> 选择题常考，大题偶尔涉及。中断与 DMA 是选择题高频考点。

> **本板块串联**：总线与 I/O 是 CPU 与外部世界的接口——前面各章的数据都在机器内部流动，本章解决数据如何进出机器（外设、磁盘）；中断与 DMA 是选择题 10/10 的双考点，并与操作系统的 I/O 管理直接衔接。

## 🧭 知识主线

本章是一条**沟通方式的进化史**，主线是"CPU 参与度一步步降低"：**程序查询**阶段 CPU 全程陪跑——不断轮询外设状态寄存器，与 I/O 完全串行，效率最低；**程序中断**阶段外设学会打断 CPU——INTR → 指令周期末响应 → 中断隐指令（关中断、保护断点、取向量）→ 服务程序保护现场后才开中断允许嵌套 → 恢复现场返回，CPU 只在"有事时"参与；**DMA** 阶段数据搬运彻底绕过 CPU——DREQ → HRQ → CPU 交出总线 → 设备与主存直传整块数据 → 传输结束才发一次中断，CPU 仅在起点设置参数和终点响应中断时出场。三级演进的实质是**数据搬运工作不断从 CPU 卸载给专用硬件**，而 10/10 与 9/10 考频的"DMA vs 中断"对比正是相邻两个站点之争：传输单位（字 vs 块）、数据路径（经 CPU vs 直连主存）、响应时机（指令周期末 vs 总线周期末）。承载所有沟通的**物理基础是总线**：数据/地址/控制三类信号线、三种仲裁方式（链式/计数器/独立请求，解决谁先用总线）、带宽公式（工作频率 × 位宽 / 8，警惕 DDR/QDR 倍速陷阱）。

## 二、总线

### 2.1 总线分类

```
┌─────────────────────────────────────┐
│              总线分类                │
├─────────────┬───────────────────────┤
│ 按功能分    │ 按位置分              │
├─────────────┼───────────────────────┤
│ 数据总线    │ 片内总线（芯片内部）  │
│ 地址总线    │ 系统总线（板上）      │
│ 控制总线    │ 通信总线（机间）      │
└─────────────┴───────────────────────┘
```

| 总线类型 | 方向 | 功能 |
|---------|------|------|
| 数据总线 | 双向 | 传输数据，宽度决定一次传输的数据量 |
| 地址总线 | 单向 | 传输地址，宽度决定寻址空间 |
| 控制总线 | 双向 | 传输控制信号（读/写/中断/DMA 等） |

> **易错**：地址总线**单向**（CPU → 外设），数据总线**双向**。

### 2.2 总线带宽

$$\text{总线带宽} = \frac{\text{总线工作频率} \times \text{总线宽度}}{8} \quad (\text{MB/s})$$

**计算模板**：

```
【题目】总线工作频率 66MHz，总线宽度 32 位，求带宽。

带宽 = 66×10^6 × 32 / 8 = 264×10^6 B/s = 264 MB/s
```

> **注意**：有些总线（如前端总线 FSB）使用四倍数据速率（quad-pumped），
> 实际数据频率 = 基础频率 × 4。2025 年真题考过此点。

### 2.3 总线仲裁

| 方式 | 原理 | 优缺点 |
|------|------|--------|
| 链式查询 | 总线授权信号 BG 串联传递 | 简单，但优先级固定，离仲裁器近的优先级高 |
| 计数器定时查询 | 计数器值 = 设备地址 | 优先级可变（取决于计数器初值） |
| 独立请求 | 每个设备独立请求线和授权线 | 灵活，速度快，但线数多 |

```
链式查询：       BG 总线仲裁器 ← BG → 设备1 → BG → 设备2 → ...

计数器查询：     设备 → BR → 总线仲裁器 ← 计数器
                各设备比较计数器值与本设备地址

独立请求：       设备i ←→ BRi / BGi ←→ 总线仲裁器（每设备独立线）
```

### 2.4 总线周期

```
① 总线请求（BR）  → ② 总线仲裁  → ③ 数据传输  → ④ 总线释放
```

**总线事务**：CPU 发出地址 → 主存响应 → 数据传输（可能突发传送 Burst）

## 三、I/O 方式

### 3.1 三种 I/O 方式对比

| 方式 | CPU 参与度 | 数据传输单位 | 优点 | 缺点 |
|------|-----------|:-----------:|------|------|
| 程序查询 | 高（轮询） | 字/字节 | 简单 | CPU 利用率低 |
| 程序中断 | 中（响应中断） | 字/字节 | CPU 与 I/O 并行 | 中断处理有开销 |
| DMA | 低（仅起止） | 块 | 效率最高 | 需 DMA 控制器 |

### 3.2 程序查询方式

```
CPU 不断查询外设状态寄存器：
  while (设备不就绪) {
      读取状态寄存器
  }
  读取/写入数据
```

- CPU 与外设**完全串行**，效率极低
- 适合简单、低速设备

### 3.3 程序中断方式

#### 中断处理流程

```
① 外设发出中断请求（INTR）
② CPU 在当前指令执行完毕后响应中断
③ 中断隐指令：
   a. 关中断（防止中断嵌套破坏现场）
   b. 保存断点（PC 值入栈/存入特定单元）
   c. 取中断服务程序入口地址 → PC
④ 中断服务程序：
   a. 保护现场（保存通用寄存器等）
   b. 开中断（允许更高级中断嵌套）
   c. 执行中断服务（数据传输等）
   d. 关中断
   e. 恢复现场
   f. 中断返回（IRET，恢复 PC）
```

#### 中断隐指令

中断隐指令是**硬件自动完成**的，不是真正的指令（不在指令系统中）：

| 步骤 | 操作 | 执行者 |
|------|------|--------|
| 关中断 | 清除中断允许标志（IF=0） | 硬件 |
| 保存 PC | 将 PC 值存入栈或特定单元 | 硬件 |
| 取入口地址 | 中断向量 → PC | 硬件 |

#### 中断向量与中断向量表

- **中断向量**：中断服务程序的入口地址
- **中断向量表**：存放中断向量的内存区域
- **中断类型号** → 查中断向量表 → 中断向量（入口地址）

```
中断类型号 n → 中断向量表第 n 项 → 入口地址 → PC
```

#### 多重中断（嵌套）

```
允许中断嵌套条件：
  1. 中断服务程序中执行了"开中断"（IF=1）
  2. 新中断的优先级高于当前中断
```

> **易错**：中断隐指令中**关中断**，中断服务程序中**保护现场后才开中断**（允许嵌套）。恢复现场时又要**关中断**。

### 3.4 DMA 方式

#### DMA 工作流程

```
① I/O 设备向 DMA 控制器发出 DMA 请求（DREQ）
② DMA 控制器向 CPU 发出总线请求（HRQ/BUSREQ）
③ CPU 响应，放弃总线控制权（发出 HLDA）
④ DMA 控制器接管总线，直接控制 I/O 与主存之间的数据传输
⑤ 传输完毕，DMA 向 CPU 发中断信号（传输结束中断）
⑥ CPU 收回总线控制权
```

#### DMA 传输方式

| 方式 | 原理 | 特点 |
|------|------|------|
| 周期挪用（ stealing） | DMA 窃取 CPU 不使用总线的周期 | 不影响 CPU，适合 CPU 和 DMA 交替访存 |
| 停止 CPU 访存 | DMA 传输期间 CPU 停止 | 传输效率高，但 CPU 利用率低 |
| 交替访存 | CPU 和 DMA 分时使用总线 | 效率高，但需双口存储器或分时逻辑 |

#### DMA 与主存冲突

- DMA 和 CPU 可能同时请求访问主存
- 解决方法：DMA 优先级通常高于 CPU（I/O 不及时会丢数据）
- 但 CPU 有更高优先级的操作时（如刷新），可以暂停 DMA

### 3.5 DMA vs 中断对比

| 对比项 | 程序中断 | DMA |
|--------|---------|-----|
| CPU 参与度 | 每次数据传输都中断 CPU | 仅起止时参与 |
| 数据传输单位 | 字/字节 | 块 |
| CPU 利用率 | 较高（频繁中断） | 高（大量数据传输时不打扰 CPU） |
| 响应时间 | 较慢（需保护/恢复现场） | 快（直接控制总线） |
| 数据路径 | 设备 → CPU → 主存 | 设备 → 主存（不经 CPU） |
| 适用场景 | 中低速设备 | 高速设备（磁盘、网卡） |
| 优先级 | 一般 | 通常高于中断 |
| 异常处理 | 中断服务程序处理 | 传输结束才中断通知 CPU |

> **高频考点**：
> - DMA **传输结束**时发中断通知 CPU（不是 DMA 请求）
> - DMA 方式中 CPU 和 DMA **共享总线**，不是 CPU 完全不管
> - DMA 请求优先级**高于**中断请求

### 3.6 I/O 控制器结构

```
┌─────────────────────────────────┐
│         I/O 控制器              │
│  ┌──────────┐  ┌──────────┐    │
│  │ 数据寄存器│  │ 控制寄存器│    │
│  │（数据缓冲）│  │（控制/状态）│   │
│  └──────────┘  └──────────┘    │
│  ┌──────────────────────────┐   │
│  │ I/O 控制逻辑            │   │
│  └──────────────────────────┘   │
│  ┌──────────────────────────┐   │
│  │ 设备接口（与外设连接）   │   │
│  └──────────────────────────┘   │
└─────────────────────────────────┘
```

- CPU 通过端口地址访问 I/O 控制器中的寄存器
- I/O 端口编址方式：
  - **统一编址**（Memory-Mapped I/O）：I/O 端口与主存统一地址空间，用访存指令访问
  - **独立编址**（Isolated I/O）：I/O 端口独立地址空间，用专用 I/O 指令（IN/OUT）访问

## 四、中断响应优先级 vs 处理优先级

### 4.1 两种优先级

| 优先级 | 含义 | 决定者 |
|--------|------|--------|
| 响应优先级 | CPU 响应中断请求的顺序 | 硬件排队器（固定） |
| 处理优先级 | 中断服务程序执行中，是否能被其他中断打断 | 软件设置（中断屏蔽字） |

### 4.2 屏蔽字

- 每个中断源有一个屏蔽字
- 屏蔽字某位为 1 → 屏蔽对应中断（不允许嵌套）
- 屏蔽字某位为 0 → 允许对应中断嵌套

```
设中断优先级：A > B > C（A最高）

默认屏蔽字（不允许低级打断高级）：
  A 的屏蔽字：111（屏蔽所有，最高级不被打断）
  B 的屏蔽字：001（只允许 A 打断）
  C 的屏蔽字：011（允许 A 和 B 打断）

修改屏蔽字可改变处理优先级：
  若 B 的屏蔽字改为 101（屏蔽 A，允许 C）
  → C 可以打断 B（但 A 不能打断 B）
```

> **核心区分**：
> - **响应优先级**由硬件排队决定，不可改变
> - **处理优先级**由屏蔽字决定，可软件修改
> - 响应顺序 ≠ 执行顺序（通过屏蔽字可改变执行顺序）

## 五、典型计算题

### 5.1 总线带宽计算

```
【题目】某总线宽度 64 位，时钟频率 200MHz，每个时钟周期
传输 2 次数据（DDR），求总线带宽。

带宽 = 200×10^6 × 64/8 × 2 = 3200×10^6 B/s = 3.2 GB/s
```

### 5.2 中断处理时间计算

```
【题目】某外设以 1000 字/秒的速率产生中断请求，每次中断
处理需 100μs。CPU 是否能处理完？

中断间隔 = 1/1000 = 1ms = 1000μs
每次处理 = 100μs
CPU 利用率 = 100/1000 = 10%
→ 可以处理，CPU 还有 90% 时间执行主程序
```

### 5.3 DMA 传输时间计算

```
【题目】磁盘转速 7200 RPM，每磁道 1MB，DMA 传输 1 个磁道
的数据，求传输时间。

每转时间 = 60/7200 = 8.33ms
传输 1 磁道 = 8.33ms（需整转读完）
DMA 传输速率 = 1MB / 8.33ms ≈ 120 MB/s
```

## 六、易错点清单

| # | 易错点 | 正确理解 |
|---|--------|---------|
| 1 | 中断响应优先级 = 处理优先级 | 错！响应优先级由硬件排队器决定（固定），处理优先级由屏蔽字决定（可改） |
| 2 | 中断隐指令是机器指令 | 错！中断隐指令由**硬件自动完成**，不在指令系统中 |
| 3 | 中断服务程序第一步就开中断 | 错！先**保护现场**，再开中断（允许嵌套），恢复现场前又要关中断 |
| 4 | DMA 不需要 CPU 参与 | DMA 仅起止时需 CPU 参与设置参数和响应结束中断，传输过程 CPU 不参与 |
| 5 | DMA 传输完毕发 DMA 请求 | 错！DMA 传输完毕发**中断请求**通知 CPU |
| 6 | DMA 优先级低于中断 | 错！DMA 优先级通常**高于**中断（DMA 数据不即时处理会丢数据） |
| 7 | 地址总线是双向的 | 错！地址总线**单向**（CPU → 外设/主存） |
| 8 | 数据总线宽度 = 地址总线宽度 | 不一定！数据总线宽度决定数据量，地址总线宽度决定寻址空间 |
| 9 | 链式查询优先级可变 | 错！链式查询优先级**固定**，离仲裁器越近优先级越高 |
| 10 | 所有中断都可嵌套 | 只有更高级中断才能打断当前中断（通过屏蔽字控制） |
| 11 | 中断返回 = 恢复 PC | 不完全！中断返回恢复 PC（断点），还需恢复通用寄存器（现场） |
| 12 | 程序查询方式 CPU 效率高 | 错！程序查询 CPU **与 I/O 串行**，效率最低 |
| 13 | DMA 数据路径经过 CPU | 错！DMA 数据路径是 设备 → 主存（直接），不经 CPU |
| 14 | 统一编址需要 IN/OUT 指令 | 错！统一编址用**访存指令**（Load/Store）访问 I/O，独立编址才用 IN/OUT |
| 15 | 多重中断 = 多中断源同时响应 | 多重中断指中断服务程序执行中被更高级中断打断（嵌套），不是同时响应多个 |
| 16 | DMA 在传输过程中 CPU 完全空闲 | 取决于 DMA 传输方式。周期挪用方式下 CPU 可继续工作（窃取空闲周期） |

## 🧠 思考模式

**遇到这类题，第一反应应该是：**

1. 三种 I/O 方式对比题：先抓两个维度——CPU 参与度（全程轮询 / 响应中断 / 仅起止）与数据传输单位（字 / 字 / 块），再逐项套对比表；牢记高频陷阱：**DMA 传输结束发的是中断请求**（不是 DMA 请求）
2. 中断流程题：按"响应条件（当前指令执行完毕）→ 中断隐指令三件事（关中断、保护断点、取向量，硬件自动完成）→ 服务程序六步（保护现场→开中断→服务→关中断→恢复现场→中断返回）"的顺序逐步检查，重点核对开/关中断的时机
3. 中断嵌套/屏蔽字题：先分清**响应优先级**（硬件排队器决定，固定）与**处理优先级**（屏蔽字决定，可软件修改）→ 写屏蔽字（1 = 屏蔽不许打断，0 = 允许嵌套）→ 按屏蔽字画出实际的嵌套执行顺序
4. 带宽计算题：带宽 = 工作频率 × 位宽 / 8，先确认有无倍速（DDR ×2、四倍速 ×4）再代入

**知识串联提示：**
- 与其他板块的关联：DMA 控制器与 CPU 共享总线，谁先用由总线仲裁（本章）裁决；缺页中断（存储系统）与 I/O 中断（本章）共用 CPU 板块的中断系统，都走"隐指令 + 服务程序"流程；本章与操作系统 I/O 管理章节（驱动程序、缓冲区、SPOOLing）是同一件事的软硬件两个层面；I/O 效率分析可与概述章 CPU 利用率计算结合出题
- 容易混淆的概念对比：中断隐指令 vs 机器指令（硬件自动完成、不在指令系统中 vs 属于指令系统）；响应优先级 vs 处理优先级（固定 vs 可改）；关/开中断时机（隐指令先关、保护现场后才开、恢复现场前再关）；统一编址 vs 独立编址（访存指令访问 I/O vs 专用 IN/OUT 指令）；DMA 请求 vs DMA 结束中断（要总线控制权 vs 报告传输完成）
