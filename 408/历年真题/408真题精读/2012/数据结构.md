## 一、单项选择题

### 1. （2 分 · 绪论）

求整数 n(n≥0)  阶乘的算法如下，其时间复杂度是（ ）。

```C
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

- **A.** O(log₂n))
- **B.** O(n)
- **C.** O(nlog₂n))
- **D.** O(n²)

**答案**：B

**解析**：答案 B。递归调用链 fact(n)→fact(n−1)→…→fact(1) 共 n 次，每次调用只做常数次比较和乘法，工作量 O(1)。总时间 = n×O(1)，即 O(n)。

### 2. （2 分 · 栈、队列与数组）

已知操作符包括 `+`、`−`、`∗`、`/`、`(` 和 `)`。将中缀表达式 `a+b−a∗((c+d)/e−f)+g` 转换为等价的后缀表达式 `ab+acd+e/f−∗−g+` 时，用栈来存放暂时还不能确定运算次序的操作符，若栈初始为空，则转换过程中同时保存在栈中的操作符的最大个数是（ ）。

- **A.** 5
- **B.** 7
- **C.** 8
- **D.** 11

**答案**：A

**解析**：答案 A。中缀转后缀时，操作数直接输出，`(` 入栈，`)` 弹栈至 `(`，运算符弹出栈中优先级不低于自身的运算符后入栈。逐字符模拟该表达式，栈中同时保存的操作符最多为 5 个。

### 3. （2 分 · 树与二叉树）

若一棵二叉树的前序遍历序列为 a, e, b, d, c，后序遍历序列为 b, c, d, e, a，则根结点的孩子结点( )。

- **A.** 只有 e
- **B.** 有 e、b
- **C.** 有 e、c
- **D.** 无法确定

**答案**：A

**解析**：答案 A。由前序 a,e,b,d,c 与后序 b,c,d,e,a 知 a 为根。前序中 e 紧跟根 a，后序中 e 在 b、c、d 之后，说明 e 是 b、c、d 的祖先，故根的孩子只有 e。

### 4. （2 分 · 查找）

若平衡二叉树的高度为 6 ，且所有非叶结点的平衡因子均为 1 ，则该平衡二叉树的结点总数为( )。

- **A.** 10
- **B.** 20
- **C.** 32
- **D.** 33

**答案**：B

**解析**：答案 B。非叶结点平衡因子全为 1 时结点数最少，满足 Nₕ=Nₕ₋₁+Nₕ₋₂+1。N₁=1、N₂=2，递推得 N₃=4、N₄=7、N₅=12、N₆=20，即高度 6 的平衡二叉树至少有 20 个结点。

### 5. （2 分 · 图）

对有 n 个结点、e 条边且使用邻接表存储的有向图进行广度优先遍历，其算法时间复杂度是()。

- **A.** O(n)
- **B.** O(e)
- **C.** O(n+e)
- **D.** O(n×e)

**答案**：C

**解析**：答案 C。邻接表存储时，广度优先遍历每个顶点入队一次，需 O(n)；扫描各顶点的邻接表（出边）时每条边至多访问一次，需 O(e)。总时间 O(n+e)。

### 6. （2 分 · 图）

若用邻接矩阵存储有向图，矩阵中主对角线以下的元素均为零，则关于该图拓扑序列的结论是( )。

- **A.** 存在，且唯一
- **B.** 存在，且不唯一
- **C.** 存在，可能不唯一
- **D.** 无法确定是否存在

**答案**：C

**解析**：答案 C。主对角线以下全为零，说明只可能有小编号顶点指向大编号顶点的边，图无环，故一定存在拓扑序列；但边分布不同时拓扑序列可能不唯一。

### 8. （2 分 · 图）

下列关于最小生成树的叙述中，正确的是()。 

Ⅰ． 最小生成树的代价唯一 

Ⅱ． 所有权值最小的边一定会出现在所有的最小生成树中 

Ⅲ． 使用普里姆(Prim)算法从不同顶点开始得到的最小生成树一定相同 

Ⅳ． 使用普里姆算法和克鲁斯卡尔(Kruskal)算法得到的最小生成树总不相同

- **A.** 仅Ⅰ
- **B.** 仅Ⅱ
- **C.** 仅Ⅰ、Ⅲ

### 10. （2 分 · 排序）

在内部排序过程中，对尚未确定最终位置的所有元素进行一遍处理称为一趟排序。下列排序方法中，每一趟排序结束都至少能够确定一个元素最终位置的方法是( )。 

Ⅰ． 简单选择排序 

Ⅱ． 希尔排序 

Ⅲ． 快速排序 

Ⅳ． 堆排序

Ⅴ．二路归并排序

- **A.** 仅Ⅰ、Ⅲ、Ⅳ
- **B.** 仅Ⅰ、Ⅲ、Ⅴ
- **C.** 仅Ⅱ、Ⅲ、Ⅳ
- **D.** 仅Ⅲ、Ⅳ、Ⅴ

**答案**：A

**解析**：答案 A。简单选择排序每趟把最小元素放入最终位置；快速排序每趟把枢轴放到最终位置；堆排序每趟把堆顶与表尾交换确定一个位置。希尔排序、归并排序只得到局部有序，不能确定元素的最终位置，故选仅Ⅰ、Ⅲ、Ⅳ。

### 11. （2 分 · 排序）

对同一待排序序列分别进行折半插入排序和直接插入排序，两者之间可能的不同之处是（）。

- **A.** 排序的总趟数
- **B.** 元素的移动次数
- **C.** 使用辅助空间的数量
- **D.** 元素之间的比较次数

**答案**：D

**解析**：答案 D。两者总趟数相同、移动次数都取决于初始序列、辅助空间都是 O(1)，仅比较次数可能不同：直接插入排序用顺序查找，比较次数与初态有关；折半插入排序用折半查找，比较次数与初态无关。

## 二、综合应用题

### 41. （10 分 · 树与二叉树）

设有 6 个有序表 A、B、C、D、E、F，分别含有 10、35、40、50、60 和 200 个数据元素，各表中元素按升序排列。要求通过 5 次两两合并，将 6 个表最终合并成 1 个升序表，并在最坏情况下比较的总次数达到最小。请回答下列问题：

(1) 给出完整的合并过程，并求出最坏情况下比较的总次数。

(2) 根据你的合并过程，描述 N（N ≥ 2）个不等长升序表的合并策略，并说明理由。

**答案 / 解析**：

答案：1、合并过程（类似哈夫曼树，每次合并最短的两个表）：A(10)+B(35)→AB(45)；AB(45)+C(40)→ABC(85)；D(50)+E(60)→DE(110)；ABC(85)+DE(110)→ABCDE(195)；ABCDE(195)+F(200)→395。各次最坏比较次数分别为 10+35−1=44、45+40−1=84、50+60−1=109、85+110−1=194、195+200−1=394，总次数 44+84+109+194+394 = 825。2、策略：借鉴哈夫曼树（最优归并树）思想，每次选择长度最短的两个表合并。理由：两表合并最坏需比较 m+n−1 次，先合并短表可减少长表参与比较的次数，使总比较次数最小。

### 42. （12 分 · 线性表）

假定采用带头结点的单链表保存单词，当两个单词有相同的后缀时，则可共享相同的后缀存储空间。例如，“loading”和“being”的存储映像如下图所示。

![loading 与 being 共享后缀 ing 的链式存储映像](q42-shared-suffix.webp)

设 str1 和 str2 分别指向两个单词所在单链表的头结点，链表结点结构为 `data | next`。请设计一个时间上尽可能高效的算法，找出由 str1 和 str2 所指向两个链表共同后缀的起始位置（如图中字符 i 所在结点的位置 p）。


（1）给出算法的基本设计思想。


（2）根据设计思想，采用 C、C++ 或 Java 语言描述算法，关键之处给出注释。


（3）说明你所设计算法的时间复杂度。

**答案 / 解析**：

答案：1、基本思想：分别求出两链表长度 m、n，将较长链表的指针先走 |m−n| 步，使两指针距表尾等长；再同步后移并比较，第一个相同的结点即共同后缀的起始位置。2、核心代码（C 语言）：

```c
int getLength(Node *h) {            // h 为带头结点链表的头指针
    int len = 0;
    for (Node *p = h->next; p != NULL; p = p->next) len++;
    return len;
}
Node* findCommonSuffix(Node *str1, Node *str2) {
    int m = getLength(str1), n = getLength(str2);
    Node *p = str1->next, *q = str2->next;
    while (m > n) { p = p->next; m--; }   // 长表指针先走差值步
    while (n > m) { q = q->next; n--; }
    while (p != NULL && p != q) {         // 同步后移，找共同后缀起点
        p = p->next;
        q = q->next;
    }
    return p;                             // 共同后缀起始结点，无则返回 NULL
}
```

3、时间复杂度 O(m+n)（或 O(max(m,n))），空间复杂度 O(1)。
