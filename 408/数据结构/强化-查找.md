# 数据结构 强化-查找

> **本板块串联**：查找是"数据组织方式决定使用效率"的集中体现——上承树结构（BST/AVL/B树一脉相承），旁开散列（跳出比较的思路），ASL 则是横贯各结构的统一度量衡。

## 🧭 知识主线

本板块的主线是：**查找效率取决于组织方式**，沿"如何组织数据"能把所有考点串成一条演进链。最朴素：无序线性表只能顺序查找 O(n)；若数据**有序**，就把"有序"这个前置信息变成每次淘汰一半的资本——折半查找 O(log n)，其判定树恰是完全二叉树形态，树高 ⌈log₂(n+1)⌉ 就是最大比较次数，成功 ASL 按层加权；若嫌"每次只缩一半"不够，干脆用**散列**——H(key) 直接定位，理想 O(1)，代价是必须处理冲突（线性探测易堆积、平方探测要求 m 为 4k+3 型质数才能探遍全表、链地址法无堆积），且装填因子 α=n/m 越大冲突越多；若数据大到内存放不下（外存），就轮到 **B树/B+树**——把二叉查找树"变矮变胖"（多叉、每节点多关键字），一次磁盘 I/O 换回一大段有序区间：B树插入总在终端节点、溢出取第 ⌈m/2⌉ 个关键字分裂上移；B+树更彻底，数据全压到叶子并用链表串联，内部节点只做索引，分支因子更大、树更矮、I/O 更少，所以数据库索引都用它。所有方案用同一把尺子度量——**ASL**：折半查找按判定树逐层加权（分母 n）；散列表成功 ASL 分母是 n、失败 ASL 分母是 m——这个分母差异是十年真题最爱挖的坑。复习时对每个结构自问三句：怎么定位？最坏几次？ASL 怎么算？

## 考频统计

> 数据口径：2016-2025 近 10 年大题统计。DS 大题为 41-42 题（22-24分）。

- **选择题常考，大题偶尔出现（4/10 年）**
- 主要考查：折半查找判定树、B树性质、散列表构造与 ASL 计算
- 大题形式：散列表构造 + ASL 计算（手工模拟）

## 折半查找

### 基本算法

```c
// 前提：有序顺序表
int BinarySearch(int A[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;  // 向下取整
        if (A[mid] == key) return mid;
        else if (A[mid] > key) high = mid - 1;
        else low = mid + 1;
    }
    return -1;  // 查找失败
}
```

- 时间复杂度 O(log₂n)
- 判定树形态：**完全二叉树**的形态，但取决于 mid 取整方式

### 判定树分析

```
mid = (low + high) / 2 （向下取整）时：

示例：A = [7, 14, 18, 21, 23, 29, 32]
                21 (mid=3)
               /    \
           14(1)    29(5)
           / \       / \
        7(0) 18(2) 23(4) 32(6)

判定树结构 = 平衡二叉树
- 每个节点对应一次比较
- 查找路径 = 从根到某节点的路径
- 查找失败 = 落在叶子节点之间的空隙
```

- 判定树一定是**平衡二叉树**（任意两子树高度差 <= 1）
- 当 n = 2^h - 1 时判定树是**满二叉树**，高度为 h = ⌈log₂(n+1)⌉
- 查找失败时比较次数不超过 ⌊log₂n⌋ + 1

### ASL 计算

```
n = 7 的有序表，判定树如上：
第1层：1个节点，比较1次
第2层：2个节点，各比较2次
第3层：4个节点，各比较3次

成功 ASL = (1*1 + 2*2 + 4*3) / 7 = 17/7 ≈ 2.43
```

- 成功 ASL = Σ(各层节点数 × 该层深度) / n
- 失败 ASL：需考虑每个空隙的探测次数

> **分母是关键字个数 n**（成功 ASL）

## B树 / B+树

### B树性质

- m 阶 B树：每个节点最多 m 棵子树（m 个关键字+1 棵子树的变体，具体看定义）
- 根节点至少 2 棵子树（根非叶时）
- 非根非叶节点至少 ⌈m/2⌉ 棵子树
- 每个节点关键字数范围：⌈m/2⌉ - 1 到 m - 1
- 所有叶节点在同一层（等高）

| m阶B树 | 关键字数 | 子树数 |
|--------|----------|--------|
| 根节点（非叶） | 1 ~ m-1 | 2 ~ m |
| 非根非叶 | ⌈m/2⌉-1 ~ m-1 | ⌈m/2⌉ ~ m |
| 叶节点 | ⌈m/2⌉-1 ~ m-1 | — |

### B树插入

1. 插入一定在**最底层非叶节点**（终端节点）
2. 插入后若关键字数超过 m-1，则**分裂**：
   - 取中间关键字 ⌈m/2⌉↑到父节点
   - 左右两部分成为两个新节点
3. 若父节点也溢出，继续向上分裂，可能产生新根（B树高度+1）

### B树删除

1. 删除非终端节点关键字：用前驱/后继替代，转化为删除终端节点关键字
2. 删除终端节点关键字：
   - 删除后关键字数 >= ⌈m/2⌉-1：直接删
   - 删除后不足：先看兄弟能否借（借一个后仍满足），不能借则**合并**节点
   - 合并可能导致父节点下溢，继续向上调整

### B+树 vs B树

| 特性 | B树 | B+树 |
|------|-----|------|
| 关键字出现次数 | 1次 | 叶子层含全部，内部节点可重复 |
| 内部节点存什么 | 关键字+数据指针 | 只存关键字（索引）+子树指针 |
| 叶子节点 | 最底层非叶节点 | 真正的叶子，含全部关键字+记录指针 |
| 叶子链表 | 无 | 有（双向链表，支持顺序遍历） |
| 查找路径 | 任何层都可能命中 | 必须到叶子层才命中 |
| 非根节点关键字数 | ⌈m/2⌉-1 ~ m-1 | ⌈m/2⌉ ~ m |

> B+树更适合文件系统/数据库索引：内部节点不存数据指针 → 分支因子更大 → 树更矮 → 磁盘 I/O 更少。

## 散列表

### 散列函数设计

- 直接定址法：H(key) = a*key + b
- 除留余数法：H(key) = key % p（p 取不大于表长的最大质数）
- 数字分析法：取关键字中分布均匀的若干位
- 平方取中法：取关键字平方的中间几位

> **除留余数法最常考**。p 通常选 <= 表长 m 的最大质数。

### 冲突处理

#### 线性探测法

```
H_i = (H(key) + i) % m，i = 0, 1, 2, ..., m-1
```

- 冲突时向后逐个探测到第一个空位
- 容易产生**堆积**（聚集）现象
- 表长 m 必须能装下所有元素

#### 平方探测法（二次探测）

```
H_i = (H(key) + d_i) % m
d_i = 1², -1², 2², -2², ..., k², -k²（k <= m/2）
```

- 减少堆积，但探测序列不能遍历所有位置
- **要求 m 是 4k+3 形式的质数**时能探测到表中所有位置

#### 链地址法（拉链法）

```
相同哈希值的关键字用链表串联
```

- 无堆积，适合频繁增删
- 空间需额外存指针

### 散列表构造过程（手动模拟）

#### 完整示例

```
散列函数：H(key) = key % 7
冲突处理：线性探测法
表长 m = 7（哈希表长度与 p 相同）
关键字序列：{15, 36, 25, 48, 32, 18}

构造过程：
1. 15: H=15%7=1  → 位置1空 → 放位置1，探测1次
   表: [_, 15, _, _, _, _, _]
2. 36: H=36%7=1  → 位置1冲突 → 探测位置2空 → 放位置2，探测2次
   表: [_, 15, 36, _, _, _, _]
3. 25: H=25%7=4  → 位置4空 → 放位置4，探测1次
   表: [_, 15, 36, _, 25, _, _]
4. 48: H=48%7=6  → 位置6空 → 放位置6，探测1次
   表: [_, 15, 36, _, 25, _, 48]
5. 32: H=32%7=4  → 位置4冲突 → 位置5空 → 放位置5，探测2次
   表: [_, 15, 36, _, 25, 32, 48]
6. 18: H=18%7=4  → 位置4冲突 → 位置5冲突 → 位置6冲突
                 → 位置0空 → 放位置0，探测4次
   表: [18, 15, 36, _, 25, 32, 48]

最终哈希表：
位置:   0   1   2   3   4   5   6
关键字: 18  15  36  _   25  32  48
探测次数: 4   1   2   -   1   2   1
```

### ASL 计算（成功 vs 失败）

> **分母不同！这是考试最易错点！**

#### 成功 ASL

```
成功 ASL = Σ(各关键字查找时的探测次数) / 关键字个数 n

上面示例：
成功 ASL = (1+2+1+1+2+4) / 6 = 11/6 ≈ 1.83

分母 = n = 6（关键字个数）
```

#### 失败 ASL

```
失败 ASL = Σ(各初始散列位置探测到空位的次数) / 散列表长度 m

对每个可能的初始哈希地址（0 到 m-1），计算探测到空位的比较次数：

位置0 → 18在 → 位置1有 → 位置2有 → 位置3空 → 比较3次
位置1 → 15在 → 位置2有 → 位置3空 → 比较3次
位置2 → 36在 → 位置3空 → 比较2次
位置3 → 空 → 比较1次
位置4 → 25在 → 位置5有 → 位置6有 → 位置0有 → 回绕到位置1有 → 位置2有 → 位置3空 → 比较7次

⚠️ 线性探测法失败时探测到第一个空位为止
（若表满则需探测 m 次）

失败 ASL = (3+3+2+1+7+5+4) / 7
（这里需要按实际逐位置重新模拟，分母是 m=7）

分母 = m = 7（散列表长度）
```

> **核心区别**：
> - 成功 ASL 分母 = **关键字个数 n**
> - 失败 ASL 分母 = **散列表长度 m**（或哈希地址个数 p）

## 散列表完整构造示例（链地址法）

```
散列函数：H(key) = key % 7
冲突处理：链地址法
关键字序列：{15, 36, 25, 48, 32, 18}

构造：
H(15)=1 → 链1: 15
H(36)=1 → 链1: 15 → 36
H(25)=4 → 链4: 25
H(48)=6 → 链6: 48
H(32)=4 → 链4: 25 → 32
H(18)=4 → 链4: 25 → 32 → 18

散列表：
0: NULL
1: 15 → 36 → NULL
2: NULL
3: NULL
4: 25 → 32 → 18 → NULL
5: NULL
6: 48 → NULL

成功 ASL：
链1: 15(1次) + 36(2次) = 3
链4: 25(1次) + 32(2次) + 18(3次) = 6
链6: 48(1次) = 1
成功 ASL = (3+6+1) / 6 = 10/6 ≈ 1.67

失败 ASL：
位置0: 空 → 1次比较(NULL)
位置1: 比较到NULL → 3次（15, 36, NULL）
位置2: 空 → 1次
位置3: 空 → 1次
位置4: 25, 32, 18, NULL → 4次
位置5: 空 → 1次
位置6: 48, NULL → 2次
失败 ASL = (1+3+1+1+4+1+2) / 7 = 13/7 ≈ 1.86

分母 = m = 7（哈希地址范围个数）
```

## 易错点清单

1. **ASL 分母不同**：成功 ASL 分母是 n（关键字个数），失败 ASL 分母是 m（表长/地址个数）。这是考查频率最高的易错点。
2. **线性探测法失败 ASL 的计算**：需对每个可能的初始哈希地址（0 ~ m-1）分别模拟到遇到空位为止。不能只算有元素的位置。
3. **平方探测法能否遍历全表**：只有当 m 是形如 4k+3 的质数时，平方探测才能探测到表中所有位置。否则可能探不到某些位置导致"假满"。
4. **散列表装填因子 α**：α = n/m（已存元素数/表长）。α 越大冲突越多。不要求 α < 1（链地址法可以 > 1）。
5. **B树节点关键字范围**：m 阶 B树非根非叶节点关键字数范围是 **⌈m/2⌉-1 ~ m-1**，子树数是 ⌈m/2⌉ ~ m。注意 ⌈m/2⌉ 是向上取整。
6. **B树插入位置**：插入一定发生在**最底层非叶节点（终端节点）**，不是任何叶子位置。
7. **B树删除导致合并**：删除后若节点关键字数不足下限，先看能否从兄弟节点借一个，不能借才合并。合并后可能引起连锁反应向上。
8. **B+树叶子含全部关键字**：B+树内部节点只是索引，真正的关键字和记录都在叶子节点，叶子用链表相连。
9. **折半查找判定树**：判定树形态取决于 mid 取整方式。`mid = (low+high)/2`（向下取整）和 `mid = (low+high+1)/2`（向上取整）判定树不同。考试默认向下取整。
10. **散列函数 p 的选取**：除留余数法中 p 取不大于表长 m 的最大质数。若 m=10 则 p=7，不是 p=10。
11. **链地址法失败 ASL**：需逐个位置算到链表末尾 NULL 的比较次数，包括比较 NULL 这一步。

## 🧠 思考模式

**遇到这类题，第一反应应该是：**

1. 先看数据的组织前提：无序 → 顺序查找；有序顺序表 → 折半（画判定树）；要求 O(1) 定位 → 散列；外存/大规模动态索引 → B树/B+树
2. 折半查找题画判定树：mid 向下取整，树形态平衡，成功 ASL = Σ(层号 × 该层节点数) / n，失败查到"空隙"为止且不超过 ⌊log₂n⌋+1 次
3. 散列表题严格三步走：定 H(key)（除留余数法 p 取 ≤ 表长的最大质数）→ 按冲突规则逐个模拟放表并记录每个关键字的探测次数 → 分清算成功 ASL（分母 n）还是失败 ASL（分母 m，逐初始地址模拟到空位）
4. B树题先默写数量约束表（根非叶 2~m 棵子树、其余 ⌈m/2⌉~m），插入在终端节点、溢出从第 ⌈m/2⌉ 个分裂上移；删除后不足先向兄弟借、借不到再合并，合并可能连锁向上
5. 手动模拟务必画表记录每步探测/比较次数，ASL 从表里加权平均出来，不凭印象写答案

**知识串联提示：**
- 与其他板块的关联：折半查找判定树 = 栈队列树板块的完全二叉树/平衡二叉树形态，且"中序有序"正是 BST 的定义——BST/AVL 上的查找就是"树上的折半"；散列表线性探测的取模运算与循环队列 (rear+1)%MaxSize 同构；链地址法的链就是线性表板块的单链表；B树/B+树的"多路平衡"是 AVL 平衡思想向宽度方向的推广；排序板块的折半插入排序直接复用折半查找定位插入点
- 容易混淆的概念对比：成功 ASL 分母 n vs 失败 ASL 分母 m；B树非根节点关键字下限 ⌈m/2⌉-1 vs B+树的 ⌈m/2⌉；B树任何层都可能命中 vs B+树必须到叶子才命中；平方探测探遍全表需 m 为 4k+3 型质数；装填因子 α = n/m 只有链地址法才可 > 1；判定树形态取决于 mid 取整方式（默认向下取整）
