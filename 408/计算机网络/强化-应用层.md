# 计算机网络 强化-应用层

> **本板块串联**：DNS → ARP → TCP → HTTP。应用层位于网络体系最顶层，直接为用户应用进程服务——下层构建的一切能力（传输层的端口与连接、网络层的编址与路由、链路层的成帧与传输），最终都在应用层一次完整的"网页访问"中协同显现。

## 🧭 知识主线

应用层的主线是"**从输入 URL 到页面显示**"：拿到 URL 后先 **DNS 解析**（各级缓存 → 递归/迭代查询）获得服务器 IP，再 **ARP** 解析下一跳 MAC（跨网段时是网关），然后 **TCP 三次握手**建立连接，接着 **HTTP** 请求与响应传送页面内容，最后**四次挥手**释放连接。每个应用协议都是这条链上的环节：DHCP 是链条之前的准备（新主机先拿地址），FTP/电子邮件是替换 HTTP 环节的其他应用，而"哪个协议用 TCP、哪个用 UDP、各自用什么端口"是贯穿所有环节的暗线。

## 一、网络应用架构

### 1.1 C/S 架构（客户端/服务器）

| 特性 | 说明 |
|------|------|
| 服务器 | 总是开机，固定IP，集中式 |
| 客户端 | 间歇性连接，动态IP |
| 特点 | 服务器压力大，但管理简单 |
| 应用 | HTTP, FTP, SMTP, POP3 |

### 1.2 P2P 架构（对等）

| 特性 | 说明 |
|------|------|
| 节点 | 既是客户端又是服务器 |
| 特点 | 可扩展性好，资源利用率高 |
| 管理 | 分散，复杂 |
| 应用 | BitTorrent, Skype（早期） |

### 1.3 对比

| 特性 | C/S | P2P |
|------|-----|-----|
| 服务器压力 | 大 | 分散 |
| 可扩展性 | 差 | 好 |
| 管理 | 集中 | 分散 |
| 资源利用 | 低 | 高 |
| 数据一致性 | 好 | 难保证 |

## 二、DNS系统

### 2.1 层次结构

```
          根DNS服务器
          /     |     \
     顶级域(.com .org .cn ...)
      /    |    \
  权威DNS   权威DNS  权威DNS
  (example.com) (test.org) ...
      |
   主机记录 www.example.com → IP
```

| 层级 | 说明 |
|------|------|
| 根域名服务器 | 13组（逻辑），全球分布，知道所有顶级域 |
| 顶级域名服务器(TLD) | .com, .org, .cn, .edu 等 |
| 权威域名服务器 | 存储具体域名的IP映射 |
| 本地域名服务器 | ISP或机构提供，也称默认域名服务器 |

### 2.2 递归查询 vs 迭代查询

| 查询方式 | 说明 | 适用 |
|---------|------|------|
| 递归查询 | 被查询者负责继续向下一级查询，返回最终结果 | 主机→本地DNS |
| 迭代查询 | 被查询者返回下一步该问谁，查询者自己继续问 | 本地DNS→根/TLD/权威 |

> **标准模式**：主机→本地DNS（递归）；本地DNS→根→TLD→权威（迭代）

### 2.3 完整域名解析流程

```
1. 浏览器DNS缓存 → 命中则返回
2. 操作系统DNS缓存（hosts文件）→ 命中则返回
3. 本地域名服务器缓存 → 命中则返回
4. 本地域名服务器查询（以下为迭代查询）：
   a. 向根DNS查询 → 根返回TLD地址
   b. 向TLD查询 → TLD返回权威DNS地址
   c. 向权威DNS查询 → 返回最终IP
5. 本地DNS缓存结果，返回给主机
```

### 2.4 DNS要点

- DNS 使用 **UDP**，端口 **53**
- DNS 资源记录格式：(域名, 类型, 值, TTL)
- 记录类型：
  - A：域名→IPv4
  - AAAA：域名→IPv6
  - CNAME：域名→域名（别名）
  - MX：邮件交换
  - NS：域名服务器

## 三、HTTP协议

### 3.1 HTTP请求报文格式

```
GET /index.html HTTP/1.1        ← 请求行（方法 URL 版本）
Host: www.example.com            ← 首部行
User-Agent: Mozilla/5.0
Accept: text/html
Connection: keep-alive
                                ← 空行（CRLF）
[请求体]                        ← POST才有
```

### 3.2 HTTP响应报文格式

```
HTTP/1.1 200 OK                  ← 状态行（版本 状态码 短语）
Content-Type: text/html          ← 首部行
Content-Length: 1234
Connection: keep-alive
                                ← 空行
<html>...</html>                 ← 响应体
```

### 3.3 HTTP方法

| 方法 | 说明 | 安全 | 幂等 |
|------|------|------|------|
| GET | 获取资源 | ✅ | ✅ |
| POST | 提交数据 | ❌ | ❌ |
| PUT | 更新/创建 | ❌ | ✅ |
| DELETE | 删除资源 | ❌ | ✅ |
| HEAD | 只取首部 | ✅ | ✅ |

> **GET vs POST**：GET参数在URL中，有长度限制，幂等；POST参数在请求体中，无长度限制，非幂等。

### 3.4 HTTP状态码

| 状态码 | 含义 | 示例 |
|--------|------|------|
| 1xx | 信息性 | 100 Continue |
| 2xx | 成功 | 200 OK |
| 3xx | 重定向 | 301 永久重定向, 302 临时重定向 |
| 4xx | 客户端错误 | 404 Not Found, 403 Forbidden, 400 Bad Request |
| 5xx | 服务器错误 | 500 Internal Server Error, 503 Service Unavailable |

### 3.5 非持久连接 vs 持久连接

| 特性 | 非持久连接(HTTP/1.0) | 持久连接(HTTP/1.1) |
|------|---------------------|-------------------|
| 连接 | 每个请求新建TCP连接 | 多个请求复用TCP连接 |
| 模式 | — | 流水线/非流水线 |
| 延迟 | 高（每次TCP握手） | 低 |

**非持久连接获取一个页面的时间**：
```
一个HTML文件+引用m个图片：
- 每个对象需 2RTT（TCP握手1RTT + HTTP请求1RTT）
- 总时间 ≈ 2×RTT × (m+1) + 传输时间
- 若串行：2RTT × (m+1)
- 若并行（6个连接）：可减少等待
```

### 3.6 Cookie机制

```
1. 客户端首次请求（无Cookie）
2. 服务器响应，Set-Cookie: sessionid=xxx
3. 客户端保存Cookie
4. 后续请求自动带上Cookie: sessionid=xxx
5. 服务器识别用户
```

Cookie 组成：
- Cookie首部行（客户端→服务器）
- Set-Cookie首部行（服务器→客户端）

## 四、FTP协议

### 4.1 双连接机制

| 连接 | 端口 | 说明 |
|------|------|------|
| 控制连接 | 21 | 传输FTP命令，全程保持 |
| 数据连接 | 20 | 传输文件数据，每次传输新建 |

### 4.2 主动模式 vs 被动模式

| 模式 | 控制连接 | 数据连接 |
|------|---------|---------|
| 主动(PORT) | 客户端→服务器:21 | 服务器:20→客户端 |
| 被动(PASV) | 客户端→服务器:21 | 客户端→服务器随机端口 |

### 4.3 要点

- FTP使用 **TCP**
- 控制连接保持，数据连接按需建立
- 控制连接传命令（ASCII），数据连接传文件（二进制或ASCII）

## 五、DHCP协议

### 5.1 四步流程

```
客户端                          DHCP服务器
  |                               |
  |  ① DISCOVER (广播)            |
  |  src=0.0.0.0:68               |
  |  dst=255.255.255.255:67       |
  |  ---------------------------->|
  |                               |
  |  ② OFFER (单播/广播)          |
  |  包含提议的IP地址              |
  |  <----------------------------|
  |                               |
  |  ③ REQUEST (广播)             |
  |  确认使用某服务器提供的IP      |
  |  ---------------------------->|
  |                               |
  |  ④ ACK                        |
  |  确认分配，附租约信息          |
  |  <----------------------------|
```

### 5.2 DHCP要点

- 传输层：**UDP**，服务器端口 **67**，客户端端口 **68**
- DISCOVER 和 REQUEST 是广播（客户端还没有/未确认IP）
- OFFER 可以是单播或广播
- REQUEST广播的原因：通知未被选中的服务器收回地址
- DHCP还分配：子网掩码、默认网关、DNS服务器

### 5.3 DHCP租约

- 租约到期前需续约（DHCP REQUEST）
- 租约过半时发送单播REQUEST续约
- 租约过 7/8 时发送广播REQUEST

## 六、电子邮件

### 6.1 电子邮件系统组成

```
发件人 → 用户代理 → 邮件服务器(SMTP) → ↓
                                          邮件服务器(POP3/IMAP) → 用户代理 → 收件人
```

### 6.2 协议与端口

| 协议 | 端口 | 传输层 | 方向 |
|------|------|--------|------|
| SMTP | 25 | TCP | 发送邮件 |
| POP3 | 110 | TCP | 接收邮件 |
| IMAP | 143 | TCP | 接收邮件（更高级） |
| SMTP(SSL) | 465 | TCP | 发送邮件（加密） |
| IMAP(SSL) | 993 | TCP | 接收邮件（加密） |

### 6.3 SMTP vs POP3

| 特性 | SMTP | POP3 |
|------|------|------|
| 功能 | 推送邮件 | 拉取邮件 |
| 方向 | 发送端→服务器, 服务器→服务器 | 服务器→接收端 |
| 模式 | — | 下载即删除 / 下载保留 |

### 6.4 IMAP vs POP3

| 特性 | POP3 | IMAP |
|------|------|------|
| 模式 | 下载到本地 | 在线管理 |
| 服务器 | 删除/保留 | 保留 |
| 多设备 | 差 | 好 |

## 七、综合应用：从输入URL到页面显示的完整流程

### 7.1 完整流程

```
1. DNS解析
   a. 查浏览器DNS缓存
   b. 查操作系统DNS缓存（hosts）
   c. 查本地DNS服务器缓存
   d. 本地DNS迭代查询：根→TLD→权威
   e. 获得目标服务器IP

2. ARP解析
   a. 若目标在本网段：ARP请求获取目标MAC
   b. 若目标不在本网段：ARP请求获取网关MAC
   c. ARP广播请求，单播响应

3. 建立TCP连接
   a. 三次握手：SYN → SYN+ACK → ACK
   b. 协商序列号

4. 发送HTTP请求
   a. 客户端发送HTTP GET请求
   b. 包含Host首部等

5. 服务器处理并响应
   a. 服务器返回HTTP响应（状态码200）
   b. 返回HTML内容

6. 浏览器渲染
   a. 解析HTML
   b. 遇到CSS/JS/图片等资源，重复2-5步获取
   c. 构建DOM树，渲染页面

7. 断开连接
   a. 四次挥手：FIN → ACK → FIN → ACK
   b. TIME_WAIT 2MSL
```

### 7.2 涉及的协议层次

| 步骤 | 协议 | 层次 |
|------|------|------|
| DNS解析 | DNS over UDP | 应用层/传输层 |
| ARP解析 | ARP | 网络层 |
| TCP连接 | TCP | 传输层 |
| HTTP请求 | HTTP over TCP | 应用层 |
| 数据传输 | IP, Ethernet | 网络层/链路层 |

### 7.3 涉及的端口

| 协议 | 端口 |
|------|------|
| DNS | 53 (UDP) |
| HTTP | 80 (TCP) |
| HTTPS | 443 (TCP) |
| DHCP | 67/68 (UDP) |
| FTP | 20/21 (TCP) |
| SMTP | 25 (TCP) |
| POP3 | 110 (TCP) |
| IMAP | 143 (TCP) |

## 八、典型综合题答题模板

### 8.1 DNS解析流程分析题

```
题目：主机A要访问 www.example.com，分析DNS解析过程。

答题框架：
1. 说明查询类型（递归/迭代）
2. 逐步分析查询路径：
   A→本地DNS（递归）
   本地DNS→根DNS（迭代）→返回TLD地址
   本地DNS→TLD（迭代）→返回权威DNS地址
   本地DNS→权威DNS（迭代）→返回IP
3. 每步使用的协议（DNS/UDP/53端口）
4. 缓存机制（每级都可缓存）
```

### 8.2 DHCP+DNS综合题

```
题目：新主机获取IP并访问网站的完整流程。

答题框架：
1. DHCP获取IP（四步流程，UDP，67/68端口）
2. DNS解析获取目标IP（迭代查询，UDP，53端口）
3. ARP获取网关MAC（广播请求，单播响应）
4. TCP三次握手建立连接
5. HTTP请求/响应（TCP，80端口）
6. TCP四次挥手断开连接
```

### 8.3 HTTP请求过程分析题

```
题目：分析浏览器访问网页的过程，计算延迟。

答题框架：
1. DNS查询时间（若有缓存则跳过）
2. TCP建立时间 = 1.5 RTT（或2 RTT取决于是否算最后一个ACK）
3. HTTP请求时间 = 1 RTT（请求+响应）
4. 总时间 = DNS时间 + TCP时间 + HTTP时间 + 传输时间
5. 若页面引用多个对象：
   - 非持久连接：每个对象2 RTT
   - 持久连接(非流水线)：首对象2 RTT，后续每个1 RTT
   - 持久连接(流水线)：首对象2 RTT，后续可并行
```

## 🧠 思考模式

**遇到这类题，第一反应应该是：**

1. **综合大题（URL 到页面）**：按主线逐环节作答——DNS（缓存 → 递归/迭代、UDP 53）→ ARP（广播请求、单播响应、跨网段问网关）→ TCP（三次握手、seq/ack 变化）→ HTTP（请求/响应、80 端口）→ 四次挥手，每步标注协议、所在层次、端口，这就是满分框架。
2. **延迟计算题**：先分清连接模式——非持久每对象 2RTT（TCP 握手 1 + 请求响应 1）；持久非流水线首对象 2RTT、后续每对象 1RTT；流水线后续对象可并行；再叠加 DNS 时延与传输时延。
3. **DNS 流程题**：先判断递归/迭代发生在哪一段（主机 → 本地 DNS 是递归，本地 → 根/TLD/权威是迭代），再按"各级缓存 → 根 → TLD → 权威"顺序展开；记住本地 DNS 服务器不属于"根/TLD/权威"层次结构。
4. **协议细节选择题**：抓"连接数"和"端口"——FTP 双连接（控制 21 全程保持、数据 20 按需建立）；DHCP 四步中 DISCOVER 和 REQUEST 是广播；DNS 用 UDP 53（大响应/区域传送可 TCP）。

**知识串联提示：**
- 本层知识点与网络层/传输层的关联：DNS、DHCP 虽是应用层协议，却都建立在 UDP 之上（53 / 67、68 端口）；DHCP 的 0.0.0.0 → 255.255.255.255 广播牵出网络层特殊地址；HTTP 页面加载性能直接受 TCP 连接管理支配——"非持久每对象 2RTT"中的 1 个 RTT 就来自传输层握手。
- 容易混淆的概念对比：递归查询（被查者负责到底）vs 迭代查询（被查者只指下一步问谁）；FTP 主动模式（服务器发起数据连接）vs 被动模式（客户端发起）；SMTP（推、发送方→服务器）vs POP3/IMAP（拉、服务器→接收方）；301 永久重定向 vs 302 临时重定向。

## 九、易错点清单

1. **DNS使用UDP**，端口53，不是TCP（大查询时可TCP）。
2. **DNS递归和迭代的区分**：主机→本地DNS是递归，本地DNS→根/TLD/权威是迭代。
3. **HTTP是无状态协议**，Cookie用于维持状态，不是HTTP本身的机制。
4. **FTP有两个连接**：控制连接（21端口）和数据连接（20端口），不要混淆。
5. **DHCP四步流程中DISCOVER和REQUEST都是广播**。
6. **DHCP使用UDP**，不是TCP。
7. **SMTP推协议，POP3拉协议**：SMTP发送端→服务器→服务器，POP3服务器→接收端。
8. **非持久连接每个对象2 RTT**（TCP握手1 RTT + HTTP请求1 RTT）。
9. **持久连接复用TCP连接**，不需要每个对象重新握手。
10. **HTTP/1.1默认持久连接**，HTTP/1.0默认非持久。
11. **301永久重定向**，302临时重定向，不要混淆。
12. **GET参数在URL**，POST参数在请求体。
13. **DNS层次结构**：根→顶级(TLD)→权威，本地DNS不属于此层次结构。
14. **ARP在跨网段时请求的是网关MAC**，不是目标主机MAC。
15. **从输入URL到显示页面**涉及DNS→ARP→TCP→HTTP多个协议，注意每步的层次和端口。
