# 计算机网络 强化-传输层

> **本板块串联**：TCP 连接建立 → 可靠传输 / 流量控制 / 拥塞控制三大机制协同 → 连接释放。传输层在网络层"主机到主机"通信之上实现"进程到进程"通信（端口复用与分用），并为应用层在 UDP（简单快速）和 TCP（可靠有序）之间提供选择——应用层每个协议的体验都由本层的机制决定。

## 🧭 知识主线

传输层的主线是"**一条 TCP 连接的生命周期**"：**建立**（三次握手同步双方初始序号）→ **传输数据**（三大机制协同：可靠传输保证数据不丢不乱不重、流量控制防止淹没接收方、拥塞控制防止压垮网络，发送窗口 = min(rwnd, cwnd) 是三者协同的落点）→ **释放**（四次挥手 + TIME_WAIT 2MSL）。数据传输阶段中的拥塞控制四算法（慢启动/拥塞避免/快重传/快恢复）是必考大题的核心；UDP 则是"跳过整个生命周期"的轻量替代方案。

## 一、TCP三次握手详解

### 1.1 三次握手过程

```
客户端                         服务器
  |                               |
  |  ① SYN=1, seq=x               |
  |  ----------------------------> |  (SYN_SENT)
  |                               |  (SYN_RCVD)
  |  ② SYN=1, ACK=1,              |
  |     seq=y, ack=x+1           |
  |  <---------------------------- |
  |                               |
  |  ③ ACK=1, seq=x+1, ack=y+1   |
  |  ----------------------------> |  (ESTABLISHED)
  |                               |
```

### 1.2 序列号变化详解

| 步骤 | 标志 | seq | ack | 说明 |
|------|------|-----|-----|------|
| ① | SYN=1 | x | — | 客户端发SYN，序号x |
| ② | SYN=1,ACK=1 | y | x+1 | 服务器回SYN+ACK，确认x+1 |
| ③ | ACK=1 | x+1 | y+1 | 客户端ACK，确认y+1 |

### 1.3 为什么三次握手？

- **防止旧连接请求延迟到达**：若两次握手，延迟的SYN会建立无效连接
- **同步双方序列号**：确保双方都知道对方的初始seq
- **确认双方收发能力正常**

### 1.4 SYN攻击

- 攻击者大量发送SYN但不回ACK
- 服务器半连接队列满，拒绝正常连接
- 防御：SYN Cookie等

## 二、TCP四次挥手详解

### 2.1 四次挥手过程

```
客户端                         服务器
  |                               |
  |  ① FIN=1, seq=u              |
  |  ----------------------------> |  (FIN_WAIT_1)
  |                               |
  |  ② ACK=1, ack=u+1            |
  |  <---------------------------- |  (FIN_WAIT_2 ← CLOSE_WAIT)
  |                               |
  |  ③ FIN=1, seq=v              |
  |  <---------------------------- |  (LAST_ACK ← 服务端)
  |                               |
  |  ④ ACK=1, ack=v+1            |
  |  ----------------------------> |  (TIME_WAIT ← CLOSED)
  |                               |
```

### 2.2 TIME_WAIT状态与2MSL

> **为什么TIME_WAIT等待2MSL？**

1. **保证最后一个ACK到达**：若ACK丢失，服务器会重发FIN，客户端在2MSL内可收到并重发ACK
2. **防止旧连接数据干扰**：2MSL后本次连接的所有报文都会从网络中消失

- MSL = Maximum Segment Lifetime（最长报文段寿命）
- TIME_WAIT 持续 2×MSL

### 2.3 序列号变化

| 步骤 | 标志 | seq | ack | 说明 |
|------|------|-----|-----|------|
| ① | FIN=1 | u | — | 客户端FIN |
| ② | ACK=1 | — | u+1 | 服务器ACK |
| ③ | FIN=1 | v | — | 服务器FIN |
| ④ | ACK=1 | — | v+1 | 客户端ACK |

## 三、TCP可靠传输机制

### 3.1 可靠传输保障

| 机制 | 说明 |
|------|------|
| 序号 | 每字节编号，确认收到的连续数据 |
| 确认 | 累计确认（ACK = 期望收到的下一个字节号） |
| 重传 | 超时重传 + 快重传 |
| 流量控制 | 滑动窗口 |
| 拥塞控制 | 慢启动/拥塞避免/快重传/快恢复 |

### 3.2 累计确认

- ACK号 = 期望收到的下一字节序号
- 确认了该号之前的所有数据
- 例如：收到的数据到序号1000，ACK=1001

### 3.3 超时重传时间（RTO）

$$\text{RTO} = \text{RTT}_S + 4 \times \text{RTT}_D$$

- RTT_S = 加权平均往返时延
- RTT_D = RTT偏差的加权平均值

## 四、TCP流量控制

### 4.1 滑动窗口

- 接收方通过ACK报文中的窗口字段（rwnd）通告可用缓冲区
- 发送窗口 = min(rwnd, cwnd)
  - rwnd = 接收窗口（流量控制）
  - cwnd = 拥塞窗口（拥塞控制）

### 4.2 零窗口探测

- 接收方通告 rwnd=0（缓冲区满）时，发送方停止发送
- 发送方定期发送**零窗口探测报文**（1字节数据），防止死锁
- 接收方返回更新的窗口值

### 4.3 糊涂窗口综合症

- 发送小数据包效率低
- 解决：Nagle算法（积累足够数据再发）、延迟确认

## 五、TCP拥塞控制四算法（最核心内容）

### 5.1 慢启动（Slow Start）

- 初始 cwnd = 1（通常 1 MSS）
- 每收到一个ACK，cwnd +1
- 实际效果：**每经过一个RTT，cwnd翻倍**（指数增长）

```
RTT 1: cwnd=1 → 2
RTT 2: cwnd=2 → 4
RTT 3: cwnd=4 → 8
RTT 4: cwnd=8 → 16
...
```

### 5.2 拥塞避免（Congestion Avoidance）

- 当 cwnd ≥ ssthresh 时，进入拥塞避免阶段
- 每经过一个RTT，**cwnd + 1**（线性增长）

```
RTT n:   cwnd=16
RTT n+1: cwnd=17
RTT n+2: cwnd=18
...
```

### 5.3 快重传（Fast Retransmit）

- 不等超时，收到 **3个重复ACK** 即重传丢失报文
- 触发条件：3个重复ACK（共收到4个相同ACK）

### 5.4 快恢复（Fast Recovery）

- 与快重传配合使用
- **不回到慢启动**，而是降低后继续拥塞避免

**快恢复算法**：
```
1. ssthresh_new = cwnd / 2
2. cwnd_new = ssthresh + 3（+3是因为已收到3个重复ACK，表示3个包已离开网络）
3. 继续拥塞避免（线性增长）
```

### 5.5 状态转换图

```
                    ┌─────────────┐
            ┌──────→│  慢启动      │
            │       │ cwnd翻倍    │
            │       └──────┬──────┘
            │              │ cwnd ≥ ssthresh
            │              ↓
            │       ┌─────────────┐
            │       │ 拥塞避免    │
            │       │ cwnd+1/RTT  │
            │       └──┬───────┬─┘
            │   超时   │       │ 3重复ACK
            │  (超时)  │       ↓
            │  ssthresh┌─────────────┐
            │  =cwnd/2 │ 快恢复      │
            │  cwnd=1  │ ssthresh=cwnd/2│
            └──────────┤ cwnd=ssthresh+3│
                       └─────────────┘
```

### 5.6 超时 vs 3重复ACK的不同处理

| 事件 | ssthresh | cwnd | 状态 |
|------|----------|------|------|
| 超时 | cwnd/2 | 1 | 慢启动 |
| 3重复ACK | cwnd/2 | ssthresh+3 | 快恢复→拥塞避免 |

> **关键区别**：超时更严重（可能网络严重拥塞），回到慢启动；3重复ACK较轻（个别包丢失），快恢复。

## 六、TCP与UDP对比

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠传输 | 不可靠 |

| 应用 | HTTP, FTP, SMTP | DNS, DHCP, TFTP |

> 给定初始 cwnd=1, ssthresh=8，分析以下事件序列中的 cwnd 和 ssthresh 变化。

### 7.2 标准表格格式

| RTT | 事件 | cwnd | ssthresh | 状态 |
|-----|------|------|----------|------|
| 初始 | — | 1 | 8 | 慢启动 |
| 1 | 收到ACK | 2 | 8 | 慢启动 |
| 2 | 收到ACK | 4 | 8 | 慢启动 |
| 3 | 收到ACK | 8 | 8 | 慢启动→拥塞避免（cwnd=ssthresh） |
| 4 | 收到ACK | 9 | 8 | 拥塞避免 |
| 5 | 收到ACK | 10 | 8 | 拥塞避免 |
| 6 | 3重复ACK | — | 5（10/2） | 快恢复 |

> **注意**：超时时 ssthresh = cwnd/2，cwnd=1，回到慢启动。快恢复时 ssthresh=cwnd/2，cwnd=ssthresh+3。

### 7.4 答题模板

```
步骤1：判断初始状态（cwnd < ssthresh → 慢启动）
步骤2：每个RTT更新cwnd
  - 慢启动：cwnd翻倍
  - 拥塞避免：cwnd+1
步骤3：遇到事件时处理
  - 超时：ssthresh=cwnd/2, cwnd=1, 进入慢启动
  - 3重复ACK：ssthresh=cwnd/2, cwnd=ssthresh+3, 进入拥塞避免
步骤4：cwnd达到ssthresh时切换状态
  - 慢启动 → 拥塞避免
```

## 🧠 思考模式

**遇到这类题，第一反应应该是：**

1. **拥塞控制模拟题**：画表格逐 RTT 更新——每行先判状态（cwnd < ssthresh → 慢启动翻倍；≥ ssthresh → 拥塞避免 +1），遇事件套固定动作：**超时** = ssthresh 减半、cwnd 归 1、回慢启动；**3 个重复 ACK** = ssthresh 减半、cwnd = ssthresh + 3、直接进拥塞避免（快恢复）。
2. **握手挥手题**：盯住 seq/ack 的规律——SYN 和 FIN 各消耗一个序号，ack = 对方 seq + 1；主动关闭方才进入 TIME_WAIT 并等待 2MSL；不确定就画时序图。
3. **综合计算题**：发送窗口 = min(rwnd, cwnd)，两个约束都要检查；首部开销 TCP 20B、UDP 8B；累计确认的 ACK 号 = 期望收到的下一个字节序号。
4. **选 TCP 还是 UDP**：看应用特性——要求可靠有序、面向连接 → TCP（HTTP/FTP/SMTP）；要求低延迟、支持广播、报文小 → UDP（DNS/DHCP/TFTP）。

**知识串联提示：**
- 本层知识点与数据链路层的关联：GBN/SR 滑动窗口（以帧为单位、无拥塞控制、窗口上限 2ⁿ−1 / 2ⁿ⁻¹）与 TCP 滑动窗口（以字节为单位、累计确认、窗口 = min(rwnd, cwnd)）的区别是经典对比题。
- 本层知识点与应用层的关联：端口号是应用层寻址的入口，每个应用协议的"性格"由其传输层选择决定——DNS 小查询用 UDP、区域传送用 TCP；HTTP 非持久连接的性能问题（每对象 2RTT）本质是 TCP 连接管理（三次握手）的开销。
- 容易混淆的概念对比：慢启动（指数翻倍）vs 拥塞避免（线性 +1）；超时（严重拥塞，回慢启动）vs 3 重复 ACK（轻度丢包，快恢复）；rwnd（接收方能力限制）vs cwnd（网络拥塞程度限制）。

## 八、易错点清单

1. **三次握手序列号变化**：SYN消耗一个序号，ACK确认的是SYN的seq+1。
2. **四次挥手FIN也消耗一个序号**：ack=FIN的seq+1。
3. **TIME_WAIT等待2MSL**，不是1MSL或1RTT。
4. **TIME_WAIT在主动关闭方**，不在被动关闭方。
5. **慢启动是指数增长（翻倍）**，不是线性；拥塞避免是线性增长（+1）。
6. **快恢复时cwnd = ssthresh + 3**，不是cwnd = ssthresh + 1。
7. **快恢复后进入拥塞避免**，不回慢启动。
8. **超时回到慢启动cwnd=1**，不是ssthresh。
9. **3个重复ACK = 共4个相同ACK**（1个初始+3个重复）。
10. **发送窗口 = min(rwnd, cwnd)**，同时受流量控制和拥塞控制约束。
11. **TCP首部20字节**，UDP首部8字节。
12. **累计确认**：ACK号 = 期望收到的下一个字节序号。
13. **慢启动cwnd达到ssthresh时**，转为拥塞避免，不是停在ssthresh。
14. **ssthresh初始值**通常为接收窗口大小或一个较大值（如16或64）。
15. **快重传的3重复ACK不等于超时**，处理方式完全不同。
