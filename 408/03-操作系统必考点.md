## 一、PV 操作 进程同步（选择 + 应用 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

**信号量（Semaphore）**是解决进程同步与互斥的核心工具，本质是一个整型变量加上一个等待队列，只能通过两个**原子操作** P 和 V 来访问（原子操作意味着执行过程不可被中断）。

- **记录型信号量**（408 考查的标准形式）：包含 `value`（资源剩余数量）和 `wait_queue`（阻塞进程队列）。
- **P 原语（wait）**：申请资源。先将 `value` 减 1；若减完后 `value < 0`，说明资源已用完，当前进程**阻塞**并进入等待队列。
- **V 原语（signal）**：释放资源。先将 `value` 加 1；若加完后 `value <= 0`，说明仍有进程在等待，**唤醒**等待队列中的一个进程。

> **核心理解**：`value` 的正值表示可用资源数；`value` 的负值其绝对值表示等待队列中的进程数。例如 `value = -3` 表示有 3 个进程在排队等待。

**同步与互斥的区别**：
- **互斥**：多个进程不能同时访问临界资源（如打印机），信号量初值通常为 1（二元信号量）。
- **同步**：进程之间存在先后执行顺序的约束（如生产者必须等缓冲区有空位才能放），信号量初值通常为 0 或缓冲区大小。

#### 2. 关键公式与信号量初值确定

| 场景 | 信号量初值 | 含义 |
|------|-----------|------|
| 互斥（mutex） | `mutex = 1` | 只允许 1 个进程进入临界区 |
| 同步-资源数为 0（如空缓冲区） | `full = 0` | 初始时没有可用资源 |
| 同步-资源数为 n（如空缓冲区） | `empty = n` | 初始时有 n 个空位 |

**P/V 操作对信号量的影响**：

$$P(S): S.value = S.value - 1;\quad \text{if } S.value < 0 \text{ then block}$$

$$V(S): S.value = S.value + 1;\quad \text{if } S.value \leq 0 \text{ then wakeup}$$

#### 3. 三大经典模型详解

**（1）生产者-消费者问题（Producer-Consumer）**

问题描述：一组生产者向缓冲区放数据，一组消费者从缓冲区取数据，缓冲区大小为 n。需要保证：缓冲区满时生产者等待，缓冲区空时消费者等待，任何时候只有一个进程访问缓冲区。

```c
semaphore empty = n;   // 空缓冲区数
semaphore full  = 0;   // 满缓冲区数
semaphore mutex = 1;   // 缓冲区互斥访问

// 生产者
producer() {
    while(1) {
        P(empty);      // ★ 同步在前：申请空位
        P(mutex);      // ★ 互斥在后：申请缓冲区锁
        放产品;
        V(mutex);      // 释放缓冲区锁
        V(full);       // 满缓冲区数 +1
    }
}

// 消费者
consumer() {
    while(1) {
        P(full);       // ★ 同步在前：申请产品
        P(mutex);      // ★ 互斥在后
        取产品;
        V(mutex);
        V(empty);      // 空位 +1
    }
}
```

> **⚠️ 关键**：`P(empty)` 必须在 `P(mutex)` 之前！如果先 `P(mutex)` 再 `P(empty)`，当缓冲区满时，生产者持有 mutex 并阻塞在 empty 上，消费者因无法获取 mutex 也无法消费 → **死锁**。

**（2）读者-写者问题（Reader-Writer）**

问题描述：多个读者可以同时读，但写者必须独占访问。读者优先策略下，新读者可以插队到等待的写者之前。

```c
semaphore rwmutex = 1;  // 读写互斥（写者专用，或第一个/最后一个读者用）
semaphore rmutex  = 1;  // 保护 readcount 的互斥
int readcount = 0;      // 当前读者数

// 读者
reader() {
    P(rmutex);
    if (readcount == 0)    // 第一个读者负责锁住写者
        P(rwmutex);
    readcount++;
    V(rmutex);
    
    读操作;
    
    P(rmutex);
    readcount--;
    if (readcount == 0)    // 最后一个读者释放写者
        V(rwmutex);
    V(rmutex);
}

// 写者
writer() {
    P(rwmutex);
    写操作;
    V(rwmutex);
}
```

**（3）哲学家就餐问题（Dining Philosophers）**

问题描述：5 个哲学家围坐圆桌，每人需要左右两支筷子才能吃饭。每支筷子是临界资源。

**防死锁策略**（任选其一）：
- 最多允许 4 人同时拿筷子
- 奇数号先拿左筷子、偶数号先拿右筷子
- 同时拿起左右两支（用 mutex 保护"同时拿"的动作）

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};
semaphore mutex = 1;  // 限制同时拿筷子的人数

philosopher_i() {
    while(1) {
        P(mutex);                    // 限制最多 4 人同时拿
        P(chopstick[i]);             // 拿左筷子
        P(chopstick[(i+1) % 5]);     // 拿右筷子
        吃饭;
        V(chopstick[i]);
        V(chopstick[(i+1) % 5]);
        V(mutex);
    }
}
```

#### 4. 解题步骤（408 应用题 45 标准流程）

**Step 1**：分析题目，找出所有进程以及它们之间的**同步关系**（先后顺序约束）和**互斥关系**（共享资源访问约束）。

**Step 2**：为每种关系定义信号量，确定初值：
- 互斥信号量 → 初值 = 1
- 同步信号量 → 初值 = 初始可用资源数（通常为 0 或 n）

**Step 3**：在每个进程的代码中插入 P/V 操作：
- 同步约束：在"等待条件"之前放 P，在"产生条件"之后放 V
- 互斥约束：在临界区之前放 P，在临界区之后放 V

**Step 4**：检查 P 操作的顺序——**同步 P 必须在互斥 P 之前**，否则可能死锁。

**Step 5**：验证逻辑正确性，确保不会死锁、不会饥饿。

#### 5. 典型例题

> **【例题】** 有三个进程 PA、PB、PC 合作解决文件打印问题：PA 从磁盘读数据到缓冲区 B1（大小为 1），PB 从 B1 复制数据到缓冲区 B2（大小为 1），PC 从 B2 打印输出。请用 P、V 操作实现三进程的同步。
>
> **【解答】**
>
> 分析同步关系：
> - PA 和 PB 之间：B1 为空时 PA 才能写，B1 满时 PB 才能读 → 需要 `empty1 = 1`、`full1 = 0`
> - PB 和 PC 之间：B2 为空时 PB 才能写，B2 满时 PC 才能读 → 需要 `empty2 = 1`、`full2 = 0`
>
> ```c
> semaphore empty1 = 1, full1 = 0;  // B1 的状态
> semaphore empty2 = 1, full2 = 0;  // B2 的状态
>
> PA() { while(1) { 读磁盘; P(empty1); 写入B1; V(full1); } }
> PB() { while(1) { P(full1); 从B1读; V(empty1); P(empty2); 写入B2; V(full2); } }
> PC() { while(1) { P(full2); 从B2读; V(empty2); 打印; } }
> ```
>
> **【答案要点】** 4 个信号量，初值分别为 `empty1=1, full1=0, empty2=1, full2=0`。

#### 6. 易错点/坑点

| 常见错误 | 正确做法 |
|---------|---------|
| 互斥 P 放在同步 P 之前 | **同步在前，互斥在后** |
| 信号量初值写反（如 `full=n`） | 仔细分析初始状态，"满"的初始值通常为 0 |
| 忘记成对出现 P 和 V | 每个 P 必须有对应的 V，且在不同进程中 |
| 多个信号量只用一个 mutex | 互斥和同步要分开，不能用互斥信号量代替同步 |
| V 操作顺序无所谓但 P 顺序致命 | P 的顺序决定死锁风险，V 的顺序不影响正确性 |

#### 7. 记忆口诀/技巧

> **口诀**：**"同步前互斥后，P 成对不遗漏；初值看初始状态，empty 空 full 满"**

**对比表格**：

| 模型 | 信号量数量 | 核心难点 |
|------|-----------|---------|
| 生产者-消费者 | 3 个（empty, full, mutex） | P 顺序不能反 |
| 读者-写者 | 2 个（rwmutex, rmutex）+ readcount | 第一个/最后一个读者负责加解锁 |
| 哲学家就餐 | 5 个筷子 + 1 个 mutex | 防死锁策略 |

## 二、页面置换算法（选择 + 应用 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

**页面置换算法**是指在请求分页系统中，当发生缺页中断且内存中没有空闲物理块时，选择哪一个内存页面调出到磁盘（对换区）的策略。选择的好坏直接影响系统性能（缺页率）。

**请求分页的基本流程**：
1. 访问逻辑地址，查快表（TLB）→ 命中则直接访问
2. 未命中则查页表 → 若页在内存（有效位=1）则访问
3. 若页不在内存（有效位=0）→ **缺页中断** → 调页 → 若内存满则执行页面置换

**关键性能指标**：

$$\text{缺页率} \; f = \frac{\text{缺页次数}}{\text{页面访问总次数}}$$

$$\text{有效访问时间} \; EAT = (1 - f) \times t_{memory} + f \times t_{page\_fault}$$

其中 $t_{memory}$ 为内存访问时间（通常 100ns），$t_{page\_fault}$ 为缺页处理时间（通常包含磁盘 I/O，约 8-25ms）。

#### 2. 四种核心算法详解

**（1）FIFO（First In First Out，先进先出）**

- 思想：淘汰最先进入内存的页面（驻留时间最长）
- 实现：维护一个页面队列，新页加入队尾，淘汰队首
- **Belady 异常**：增加物理块数，缺页次数反而增加（**仅 FIFO 有**，LRU 和 OPT 没有）

**（2）LRU（Least Recently Used，最近最久未使用）**

- 思想：淘汰最长时间没有被访问过的页面
- 依据：局部性原理——最近被访问的页面短期内还会被访问
- 实现：需要硬件支持（计数器或栈），开销较大
- 性能：接近 OPT，是实际应用中最常用的算法

**（3）OPT（Optimal Page Replacement，最佳置换算法）**

- 思想：淘汰未来最长时间内不会被访问的页面（或永不使用）
- 特点：**理论上缺页率最低**，但无法实现（无法预知未来访问序列）
- 用途：作为评价其他算法的**上界参照**

**（4）Clock（时钟算法 / 二次机会法）**

- 思想：LRU 的近似。每个页面有一个访问位（reference bit），页面被访问时硬件自动置 1。
- 实现：用指针循环扫描页面链表，遇到访问位=1 的置 0 并跳过（给第二次机会），遇到访问位=0 的淘汰。
- 改进型 Clock：增加修改位（dirty bit），优先淘汰未修改的页（减少写磁盘开销）。

#### 3. 关键公式总结

| 公式 | 含义 |
|------|------|
| $\text{缺页率} = \frac{F}{N}$ | $F$ = 缺页次数，$N$ = 访问序列长度 |
| $\text{有效访问时间} = (1-f) \cdot t_m + f \cdot t_f$ | $t_m$ = 内存访问时间，$t_f$ = 缺页处理时间 |
| $\text{缺页次数} = N - \text{命中次数}$ | 命中 = 访问的页面已在内存中 |

#### 4. 解题步骤（408 应用题 46 标准流程）

**Step 1**：明确已知条件——页面访问序列、物理块数（内存中可容纳的页面数）、初始内存状态（通常为空）。

**Step 2**：按算法规则逐行处理访问序列，画表格记录每一步内存中的页面状态：

| 访问序列 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | ... |
|---------|---|---|---|---|---|---|---|---|---|---|-----|
| 物理块1 |   |   |   |   |   |   |   |   |   |   |     |
| 物理块2 |   |   |   |   |   |   |   |   |   |   |     |
| 物理块3 |   |   |   |   |   |   |   |   |   |   |     |
| 缺页(√) |   |   |   |   |   |   |   |   |   |   |     |

**Step 3**：统计缺页次数，计算缺页率。

**Step 4**：若题目要求计算有效访问时间，代入公式。

#### 5. 典型例题

> **【例题】** 设某程序页面访问序列为 `7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1`，物理块数为 3，初始内存为空。分别用 FIFO 和 LRU 算法计算缺页次数和缺页率。

> **【FIFO 解答】**
>
> | 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 | 1 | 2 | 0 | 1 | 7 | 0 | 1 |
> |------|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
> | 块1  | 7 | 7 | 7 | 2 | 2 | 2 | 2 | 4 | 4 | 4 | 0 | 0 | 0 | 1 | 1 | 1 | 1 | 7 | 7 | 7 |
> | 块2  |   | 0 | 0 | 0 | 0 | 3 | 3 | 3 | 2 | 2 | 2 | 2 | 2 | 2 | 2 | 0 | 0 | 0 | 0 | 0 |
> | 块3  |   |   | 1 | 1 | 1 | 1 | 0 | 0 | 0 | 3 | 3 | 3 | 3 | 3 | 3 | 3 | 1 | 1 | 1 | 1 |
> | 缺页 | √ | √ | √ | √ |   | √ | √ | √ | √ | √ | √ |   |   | √ |   | √ | √ | √ |   |   |
>
> 缺页次数 = 15，命中次数 = 5，缺页率 = 15/20 = 75%
>
> **【LRU 解答】**
>
> | 访问 | 7 | 0 | 1 | 2 | 0 | 3 | 0 | 4 | 2 | 3 | 0 | 3 | 2 | 1 | 2 | 0 | 1 | 7 | 0 | 1 |
> |------|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
> | 块1  | 7 | 7 | 7 | 2 | 2 | 2 | 2 | 4 | 4 | 4 | 0 | 0 | 0 | 1 | 1 | 1 | 1 | 7 | 7 | 7 |
> | 块2  |   | 0 | 0 | 0 | 0 | 3 | 3 | 3 | 2 | 2 | 2 | 2 | 2 | 2 | 2 | 0 | 0 | 0 | 0 | 0 |
> | 块3  |   |   | 1 | 1 | 1 | 1 | 0 | 0 | 0 | 3 | 3 | 3 | 3 | 3 | 3 | 3 | 1 | 1 | 1 | 1 |
> | 缺页 | √ | √ | √ | √ |   | √ | √ | √ | √ | √ |   |   |   | √ |   | √ | √ | √ |   |   |
>
> 缺页次数 = 12，命中次数 = 8，缺页率 = 12/20 = 60%
>
> **【结论】** LRU 缺页率（60%）< FIFO 缺页率（75%），LRU 性能更优。

#### 6. 易错点/坑点

| 常见错误 | 正确做法 |
|---------|---------|
| 初始状态忘记设为空 | 题目说"初始为空"则前 k 个不同页面一定缺页 |
| FIFO 和 LRU 淘汰页选错 | FIFO 看"谁最早进"，LRU 看"谁最久没被访问" |
| Belady 异常记错算法 | **只有 FIFO 有** Belady 异常 |
| Clock 算法访问位处理错 | 扫描时遇到 1 置 0 跳过，遇到 0 淘汰 |
| 缺页率公式分子分母搞反 | 缺页率 = 缺页次数 / 访问总次数 |

#### 7. 记忆口诀/技巧

> **口诀**：**"FIFO 看进门早晚，LRU 看最近用过没；OPT 是理想，Clock 给二次机会"**

**算法对比表格**：

| 算法 | 淘汰依据 | 实现方式 | Belady 异常 | 408 考查频率 |
|------|---------|---------|-------------|-------------|
| FIFO | 进入内存时间最早 | 队列 | **有** | ★★★★★ |
| LRU | 最近最久未使用 | 计数器/栈 | 无 | ★★★★★ |
| OPT | 未来最晚使用 | 理论算法 | 无 | ★★★ |
| Clock | 访问位是否为 0 | 循环链表 | 无 | ★★★★ |

## 三、死锁 银行家算法（选择 ≈14/15 年）

### 📐 核心考点

#### 1. 概念详解

**死锁**：两个或两个以上的进程在执行过程中，因争夺资源而陷入互相等待的状态，若无外力干涉它们都无法推进。

**死锁产生的四个必要条件**（必须同时满足才会死锁）：

| 条件 | 含义 | 破坏方式 |
|------|------|---------|
| **互斥** | 资源不能共享，一次只能一个进程用 | 使用可共享资源（如只读文件） |
| **不可剥夺** | 进程获得的资源不能被强制抢占 | 允许系统强制回收资源 |
| **请求保持** | 进程持有资源的同时请求新资源 | 一次性申请所有资源 |
| **循环等待** | 存在进程集合 {P1,P2,...,Pn}，P1 等 P2 的资源，P2 等 P3...Pn 等 P1 | 资源按序申请（有序分配） |

**死锁处理策略**：
- **预防**：破坏四个条件之一
- **避免**：银行家算法（在分配前预判是否安全）
- **检测+解除**：允许死锁发生，定期检测并解除
- **忽略**：如鸵鸟算法（UNIX 采用）

#### 2. 银行家算法详解

银行家算法是**死锁避免**的核心算法，由 Dijkstra 提出。核心思想：在分配资源前，先预判分配后系统是否仍处于安全状态，只有安全才分配。

**关键数据结构**（设 n 个进程，m 种资源）：

| 符号 | 含义 |
|------|------|
| $Available$ | 可用资源向量，长度为 m |
| $Max[i]$ | 进程 i 对各类资源的最大需求矩阵 |
| $Allocation[i]$ | 进程 i 已分配的资源量 |
| $Need[i]$ | 进程 i 还需要的资源量，$Need = Max - Allocation$ |
| $Request_i$ | 进程 i 当前请求的资源向量 |

**核心关系式**：

$$Need[i][j] = Max[i][j] - Allocation[i][j]$$

#### 3. 银行家算法四步流程

**Step 1**：检查请求合法性

$$Request_i \leq Need_i$$

若不满足，请求超过最大需求，拒绝。

**Step 2**：检查资源是否足够

$$Request_i \leq Available$$

若不满足，资源不够，进程等待。

**Step 3**：试分配（假设同意请求）

$$Available = Available - Request_i$$
$$Allocation_i = Allocation_i + Request_i$$
$$Need_i = Need_i - Request_i$$

**Step 4**：安全性算法——检查试分配后系统是否安全

安全性算法步骤：
1. 设 $Work = Available$，$Finish[i] = false$
2. 找进程 $i$ 满足 $Finish[i] = false$ 且 $Need_i \leq Work$
3. 若找到，则 $Work = Work + Allocation_i$，$Finish[i] = true$，回到第 2 步
4. 若所有进程 $Finish[i] = true$，则系统**安全**，正式分配；否则**不安全**，撤销试分配，进程等待

#### 4. 解题步骤（408 选择题标准流程）

**题型一：判断系统当前是否安全**

**Step 1**：根据已知 $Max$ 和 $Allocation$ 计算 $Need = Max - Allocation$。

**Step 2**：计算 $Available = 总资源 - \sum Allocation$。

**Step 3**：执行安全性算法，寻找安全序列。

**Step 4**：若能找到安全序列则系统安全，否则不安全。

**题型二：进程请求能否立即满足**

**Step 1**：判断 $Request \leq Need$（请求是否合法）。

**Step 2**：判断 $Request \leq Available$（资源是否足够）。

**Step 3**：试分配，执行安全性算法。

**Step 4**：安全则分配，不安全则等待。

#### 5. 典型例题

> **【例题】** 系统中有 5 个进程 P0-P4，3 种资源 A/B/C（总数分别为 10、5、7）。当前时刻资源分配情况如下表：
>
> | 进程 | Allocation (A,B,C) | Max (A,B,C) |
> |------|--------------------|-------------|
> | P0   | (0,1,0)            | (7,5,3)     |
> | P1   | (2,0,0)            | (3,2,2)     |
> | P2   | (3,0,2)            | (9,0,2)     |
> | P3   | (2,1,1)            | (2,2,2)     |
> | P4   | (0,0,2)            | (4,3,3)     |
>
> (1) 当前 $Available$ 是多少？系统是否安全？请找出安全序列。
> (2) P1 请求 $Request_1 = (1,0,2)$，能否立即分配？
>
> **【解答】**
>
> **(1)** 计算 $Need = Max - Allocation$：
>
> | 进程 | Need (A,B,C) |
> |------|--------------|
> | P0   | (7,4,3)      |
> | P1   | (1,2,2)      |
> | P2   | (6,0,0)      |
> | P3   | (0,1,1)      |
> | P4   | (4,3,1)      |
>
> $Available = (10,5,7) - (7,2,5) = (3,3,2)$
>
> 安全性算法执行过程：
>
> | 步骤 | 选中进程 | Need ≤ Work? | Work (分配前) | Work (分配后) |
> |------|---------|-------------|---------------|---------------|
> | 1    | P3      | (0,1,1)≤(3,3,2) ✓ | (3,3,2) | (5,4,3) |
> | 2    | P1      | (1,2,2)≤(5,4,3) ✓ | (5,4,3) | (7,4,3) |
> | 3    | P4      | (4,3,1)≤(7,4,3) ✓ | (7,4,3) | (7,4,5) |
> | 4    | P0      | (7,4,3)≤(7,4,5) ✓ | (7,4,5) | (7,5,5) |
> | 5    | P2      | (6,0,0)≤(7,5,5) ✓ | (7,5,5) | (10,5,7) |
>
> **系统安全**，安全序列为 **P3 → P1 → P4 → P0 → P2**（答案不唯一）。
>
> **(2)** P1 请求 $Request_1 = (1,0,2)$：
> - $Request_1 \leq Need_1$？$(1,0,2) \leq (1,2,2)$ ✓
> - $Request_1 \leq Available$？$(1,0,2) \leq (3,3,2)$ ✓
> - 试分配：$Available = (2,3,0)$，$Allocation_1 = (3,0,2)$，$Need_1 = (0,2,0)$
> - 安全性算法：此时只有 P3 的 Need(0,1,1) ≤ (2,3,0)，执行后 Work=(4,4,1)；然后 P4 的 Need(4,3,1) ≤ (4,4,1)，执行后 Work=(4,4,3)；然后 P0 的 Need(7,4,3) > (4,4,3)，P1 的 Need(0,2,0) ≤ (4,4,3) ✓，执行后 Work=(4,4,3)+(3,0,2)=(7,4,5)；然后 P0 的 Need(7,4,3) ≤ (7,4,5) ✓，执行后 Work=(7,5,5)；然后 P2 的 Need(6,0,0) ≤ (7,5,5) ✓。
> - **能找到安全序列 P3→P4→P1→P0→P2，可以分配。**

#### 6. 易错点/坑点

| 常见错误 | 正确做法 |
|---------|---------|
| 忘记计算 Need，直接用 Max | $Need = Max - Allocation$，必须算 |
| Available 计算错误 | $Available = 总资源 - \sum Allocation$ |
| 安全性算法中 Work 更新错 | $Work = Work + Allocation_i$（不是加 Need） |
| 安全序列只找到一个就停 | 必须验证所有进程都能 Finish |
| 请求分配后忘记还原 | 不安全时要撤销试分配 |
| 安全序列唯一 | 安全序列**不唯一**，找到一个即可 |

#### 7. 记忆口诀/技巧

> **口诀**：**"Need 等于 Max 减 Allocation，Available 等于总数减已分；安全算法找 Need 小于等于 Work 的，回收 Allocation 再继续"**

**死锁四条件与破坏策略对比**：

| 条件 | 预防策略 | 缺点 |
|------|---------|------|
| 互斥 | 难以破坏（某些资源本质互斥） | — |
| 不可剥夺 | 允许抢占 | 适用于 CPU/内存，不适用打印机 |
| 请求保持 | 一次性分配所有资源 | 资源利用率低，可能饥饿 |
| 循环等待 | 资源有序分配 | 资源编号固定，不灵活 |

**银行家算法 vs 安全性算法**：

| 对比项 | 银行家算法 | 安全性算法 |
|--------|-----------|-----------|
| 用途 | 判断请求能否分配 | 判断系统是否处于安全状态 |
| 步骤 | 4 步（含试分配） | 4 步（找安全序列） |
| 关系 | 银行家算法**调用**安全性算法 | 是银行家算法的第 4 步 |

## 四、磁盘调度算法（选择 ≈15/15 年）

### 📐 核心考点

#### 1. 概念详解

**磁盘调度**：当有多个进程请求磁盘 I/O 时，系统决定响应请求的顺序，以最小化寻道时间（Seek Time，磁头移动到目标磁道的时间）。

**磁盘访问时间组成**：

$$T_{access} = T_{seek} + T_{rotation} + T_{transfer} + T_{controller}$$

其中：
- $T_{seek}$：**寻道时间**（磁头移动），是磁盘调度算法优化的主要目标
- $T_{rotation}$：旋转延迟（盘片旋转到目标扇区），平均为旋转半圈的时间
- $T_{transfer}$：数据传输时间
- $T_{controller}$：控制器开销

> **408 考查重点**：磁盘调度算法主要优化**寻道时间**，通常给定磁头当前位置、移动方向、请求序列，要求画出服务顺序并计算总移动磁道数。

#### 2. 四种核心算法详解

**（1）FCFS（先来先服务）**

- 思想：按请求到达的先后顺序服务
- 优点：公平、简单
- 缺点：寻道时间长，磁头可能来回大幅摆动
- 408 中通常作为对照基准

**（2）SSTF（最短寻道时间优先）**

- 思想：优先服务离当前磁头位置最近的请求
- 优点：平均寻道时间较短
- 缺点：可能导致**饥饿**（远端请求长期得不到服务）

**（3）SCAN（电梯算法）**

- 思想：磁头沿一个方向移动，沿途服务请求，到达磁盘**最端面**（最内或最外）后反向移动。
- 优点：寻道时间较短，不会饥饿
- 缺点：对刚越过区域的请求响应较慢（到达端面后才返回）

**（4）C-SCAN（循环扫描）**

- 思想：磁头沿一个方向移动，沿途服务请求，到达端面后**立即快速返回起点**（返回途中不服务），然后再次同向扫描。
- 优点：比 SCAN **更公平**，各位置请求等待时间均匀
- 缺点：返回时空跑，浪费了一些时间

**（5）LOOK（LOOK 算法）**

- 思想：SCAN 的改进版。磁头不用到达磁盘最端面，只需移动到**该方向上最后一个请求**就反向。
- 优点：比 SCAN 减少了不必要的端面移动

**（6）C-LOOK（C-LOOK 算法）**

- 思想：C-SCAN 的改进版。磁头移动到该方向最后一个请求后，快速回到**反方向上的第一个请求**（不是回到磁盘端点）。
- 优点：比 C-SCAN 更节省时间

#### 3. 关键公式

$$\text{总移动磁道数} = \sum_{i=1}^{n-1} |track_{i+1} - track_i|$$

$$\text{平均寻道长度} = \frac{\text{总移动磁道数}}{\text{请求总数}}$$

其中 $track_i$ 表示第 $i$ 个被服务的磁道号。

#### 4. 解题步骤（408 选择题标准流程）

**Step 1**：明确已知条件——磁头当前位置、磁头移动方向（向磁道号增大/减小方向）、请求序列。

**Step 2**：按算法规则确定服务顺序：

- **FCFS**：按请求序列原顺序
- **SSTF**：每次选距离当前位置最近的请求
- **SCAN**：沿当前方向，服务所有经过的请求，到最端面后反向
- **C-SCAN**：沿当前方向，服务所有经过的请求，到最端面后快速返回起点（不服务）
- **LOOK**：沿当前方向，服务到该方向最后一个请求即反向
- **C-LOOK**：沿当前方向，服务到该方向最后一个请求，快速回到反方向第一个请求

**Step 3**：计算总移动磁道数——将相邻服务磁道之差的绝对值相加。

**Step 4**：若题目要求，计算平均寻道长度。

#### 5. 典型例题

> **【例题】** 设磁盘有 200 个磁道（0-199），磁头当前位于 53 号磁道，并向磁道号增大的方向移动。请求序列为：`98, 183, 37, 122, 14, 124, 65, 67`。请分别用 SCAN 和 C-SCAN 算法写出磁头服务顺序，并计算总移动磁道数。
>
> **【SCAN 解答】**
>
> 磁头从 53 开始，向磁道号增大方向移动，到最端面（199）后反向。
>
> - 增大方向（53 → 199）：依次服务 65, 67, 98, 122, 124, 183
> - 到达 199（最端面）后反向
> - 减小方向（199 → 0）：依次服务 37, 14
>
> 服务顺序：**53 → 65 → 67 → 98 → 122 → 124 → 183 → 37 → 14**
>
> 总移动磁道数 = $|65-53| + |67-65| + |98-67| + |122-98| + |124-122| + |183-124| + |37-183| + |14-37|$
> $= 12 + 2 + 31 + 24 + 2 + 59 + 146 + 23 = \mathbf{299}$
>
> **【C-SCAN 解答】**
>
> 磁头从 53 开始，向磁道号增大方向移动，到最端面（199）后快速返回起点（0），再同向扫描。
>
> - 增大方向（53 → 199）：依次服务 65, 67, 98, 122, 124, 183
> - 到达 199 后快速返回 0（途中不服务）
> - 再次从 0 向增大方向：依次服务 14, 37
>
> 服务顺序：**53 → 65 → 67 → 98 → 122 → 124 → 183 → 14 → 37**
>
> 总移动磁道数 = $12 + 2 + 31 + 24 + 2 + 59 + |14-183| + |37-14|$
> $= 12 + 2 + 31 + 24 + 2 + 59 + 169 + 23 = \mathbf{322}$
>
> **【结论】** 本例中 SCAN 总移动 299 道，C-SCAN 总移动 322 道。SCAN 寻道更短，但 C-SCAN 更公平。

#### 6. 易错点/坑点

| 常见错误 | 正确做法 |
|---------|---------|
| 忘记磁头初始移动方向 | 题目明确给出方向，必须注意 |
| SCAN 不到最端面就反向 | SCAN 必须到**磁盘最端面**（0 或最大值），LOOK 才到最后一个请求 |
| C-SCAN 返回途中服务了请求 | C-SCAN 返回时**不服务任何请求** |
| 总移动磁道数计算时漏掉某段 | 逐段计算，用绝对值相加 |
| 磁道号范围搞错 | 注意题目给的磁道范围（如 0-199 还是 1-200） |
| LOOK 和 SCAN 混淆 | SCAN 到端面，LOOK 到最后一个请求即回头 |

#### 7. 记忆口诀/技巧

> **口诀**：**"SCAN 撞墙才回头，LOOK 没人就回头；C-SCAN 撞墙跑回起点，C-LOOK 撞墙跑到头"**

**六种算法对比表格**：

| 算法 | 磁头移动方式 | 是否到端面 | 返回时服务 | 饥饿 | 408 频率 |
|------|-------------|-----------|-----------|------|---------|
| FCFS | 按请求顺序 | — | — | 无 | ★★ |
| SSTF | 每次选最近 | — | — | **有** | ★★★ |
| SCAN | 单向到端面再反向 | **是** | 服务 | 无 | ★★★★★ |
| C-SCAN | 单向到端面快速返回 | **是** | **不服务** | 无 | ★★★★★ |
| LOOK | 单向到末请求即反向 | 否 | 服务 | 无 | ★★★★ |
| C-LOOK | 单向到末请求快速返回 | 否 | **不服务** | 无 | ★★★★ |

**SCAN 家族对比**：

| 对比项 | SCAN | C-SCAN | LOOK | C-LOOK |
|--------|------|--------|------|--------|
| 移动到端面？ | ✓ | ✓ | ✗ | ✗ |
| 返回时服务？ | ✓ | ✗ | ✓ | ✗ |
| 公平性 | 一般 | **最好** | 一般 | **最好** |
| 寻道效率 | 较高 | 一般 | **最高** | 较高 |
