## Git 仓库损坏事故处理（严重）

### 现象
- 用户执行 `git pull --rebase` 时报 `could not mark as interactive: No such file or directory`
- 仓库状态错乱：`main` 变为 unborn（"No commits yet"），`origin/main` 指向缺失对象 `c3f30fa`，无任何 rebase 进行中

### 修复步骤（已执行，数据零丢失）
1. 定位完好游离提交 `ffb696d`（实为本地+远程的合并提交，父为 57f67901 与 84d8993d）——即"解决冲突+拉取"已完成的状态
